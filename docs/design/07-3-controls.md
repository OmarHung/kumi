# 設計規範 — 7.3：下拉選單、勾選、日期

> `docs/DESIGN.md`（設計規範）的一部分；索引、通則與其他各節在那裡。節號是整份規範共用的：別的地方寫「7.3」指的就是這一份。

## 7.3 下拉選單、勾選與其他原生控制項〔已有：`Select`、勾選框、篩選框，全站換掉（自訂控制項 P0～P3）〕

瀏覽器原生的下拉選單，按鈕的外觀可以用 CSS 改，但打開之後的選項清單是作業系統畫的：字體、間距、深色模式、選取的樣子都不受設計變數控制，每個系統長得不一樣，和旁邊的 `Menu` 也不一樣。Windows 上方向鍵在關著的下拉上會直接換值，原本得靠 `lib/usePointerPick.ts` 分辨滑鼠與鍵盤（換掉之後拿掉了）。原則 7「同一件事只有一種長相」在原生的下拉上做不到，所以換成了自己的。

| 控制項 | 現在 | 規範 |
|---|---|---|
| 下拉選單與它的選項清單 | 已有：全站都是 `Select`，沒有原生的 `<select>` | 一律 `Select`（或包了標籤的 `SelectField`）。〔已有〕功能裡**一定**不直接寫 `<select>`、`<option>`：樣式檢查會擋（第 13 節） |
| 勾選框 | 已有：自己畫的方框與勾（`global.css`） | 元素不變，方框與打勾自己畫 |
| 多選的欄位 | 一組勾選框 | 不變（不做多選的下拉） |
| 單選鈕 | 沒有用到 | 需要時照勾選框的做法：16px 的圓、選取是中間一個強調色的點，加進 `components/` |
| 顏色 | 已有（2026-11-24 分頁的未讀提示）：自己畫的取色器（`CustomColorPicker`，見第 7 節） | 不用 `<input type="color">`（打開的取色器是作業系統畫的，長相、字與深色模式都管不到；和原生的下拉同一個理由）。要讓人選顏色時先給幾個預設的色票（`BadgeColorPicker`），任意的顏色放在「自訂」後面的 `CustomColorPicker` |
| 日期 | 已有（視覺翻新）：表單與格子都是自己畫的日曆（`DatePicker`／`DateField`；格子是 `DatePicker` 的 `bare`） | 一律 `DatePicker`（或包了標籤的 `DateField`），見本節最後的「日期」。時間目前沒有欄位：之後需要時照同一套長相做 `TimeField`，先改這一節 |

**`Select` 的結構**

```
┌──────────────────────────┐
│ ◐ 進行中               ⌄ │   按鈕：目前的值（前面可以有小圖）、向下的箭頭
└──────────────────────────┘
┌──────────────────────────┐
│ ○ 待辦                   │   清單：浮在按鈕下方，寬度至少和按鈕一樣
│ ◐ 進行中               ✓ │   目前的值：打勾，字重 medium
│ ● 完成                   │   反白（滑鼠滑過或方向鍵所在）：實心的強調色底、反白的字，同時只有一個
│ ─────────────────────── │   分組的細線（可以沒有）
│ ⊘ 已取消                 │
│   這個流程沒有這條路      │   不能選的：灰字，原因寫在第二行
└──────────────────────────┘
```

**按鈕的長相**

- 和輸入框同一套：高度 `--control-height`（`size="sm"` 是 `--control-height-sm`，工具列、表格列、格子裡用），1px `--color-control-border`、`--radius-md`、`--color-surface` 底，字是 `--text-control`。左右內距 `--space-3`（`sm` 是 `--space-2`）。
- 值是一行，放不下用省略號；箭頭是 `Icon` 的 `chevronDown`、`--color-text-muted`，貼在右邊，不旋轉。原本用漸層拼出來的 CSS 箭頭已經拿掉〔已有〕。
- 寬度：表單裡撐滿欄位（`width="fill"`，預設）；工具列、表格上方那一列與設定頁的列上照目前的值，最窄 8rem、最寬 16rem（`width="content"`，標在按鈕的 `data-width`，`Select.module.css` 一份；`SelectField` 的 `size="sm"` 加 `isLabelHidden` 自動是這一種）。理由：原本工具列（`Field.module.css`）與設定頁（`SettingsControls.module.css`）各寫一份上下限。
- 沒有值時（必選、還沒選）顯示 `placeholder`，灰字，例如「選擇人員」「選擇狀態」。「所有類型」這種本身就是一個選擇的，是真的選項，不是 placeholder。「還沒選」一律是 placeholder，不做成清單裡的「請選擇…」選項（設定頁刪除狀態的搬移原本是選項、類型換流程的搬移是 placeholder，兩種做法統一成 placeholder；選了之後要改就重選，不提供改回沒選）。選項還在讀：停用加 placeholder「載入中…」（模板、加入成員的人員）。

| 狀態 | 長相 |
|---|---|
| 滑過 | 外框 `--color-text-muted`；打開與鍵盤焦點時不換（外框維持焦點色） |
| 鍵盤焦點 | 2px 的 `--color-focus` 外框（外框加 1px 同色的內環線）加 3px 的 `--color-focus-ring` 光暈，`outline` 是透明的（和輸入框一樣，第 9 節）：只有一圈，不再加全域的 2px 焦點外框 |
| 打開 | 和鍵盤焦點一樣（外框 `--color-focus` 加光暈）：清單開著時焦點可能在篩選框裡，按鈕照樣看得出是它打開的 |
| 有錯 | 外框 `--color-danger`、`aria-invalid`；取得焦點、打開時外框維持危險色，裡面多一圈 1px `--color-focus` 的內環線，外面照樣是光暈（第 9 節） |
| 停用 | 原生的 `disabled`，整顆變淡（和 `Button` 一樣），打不開；要讓人知道原因的用 `aria-disabled` 加 `aria-describedby`，停得到、打不開 |
| 送出中 | `aria-busy`，打得開但不收新的值（點了選項清單照樣關上，值不變） |

**清單與選項**

- 清單經過 `components/Floating`（第 13 節），外殼和 `Menu` 一樣：`--color-surface`、細線、`--radius-md`、`--shadow-popover`、內距 `--space-1`。預設在按鈕下方、靠左對齊，下方放不下就翻到上方。寬度至少和按鈕一樣，最寬到視窗左右各留 8px。高度最多 18rem，超過在清單裡捲動；反白的選項一定捲到看得到。
- 選項的列和 `Menu` 的項目同一種：至少 `--target-min` 高（觸控 44px）、內距 `--space-1 --space-2`、`--radius-sm`、`--text-sm`。文字太長就換行，不截斷。和 `Menu` 不同的是內容垂直置中（實作時改；理由：觸控時一列 44px，一行字靠上會在下面空一大塊）。
- 同一個清單裡每個選項給同樣大小的小圖，字才對齊〔已有〕：人員的清單是 20px（`Avatar` 的 `sm`），狀態的清單是 16px（狀態類別的形狀）。「我」是自己的頭像；不是某一個人、某一個狀態的選項用同樣大小的佔位小圖：「所有人」是頭像大小的圓裡一個人員的圖示（12px：和頭像裡的字一樣大，16px 的圖示放進 20px 的圓會比旁邊的頭像重；`Icon` 16px 的例外）、「沒有負責人」「沒有人」是字色（`currentColor`）的虛線空圓（看板卡片上的「沒有負責人」是同一個，那一列是次要的字色；反白的選項上跟著變成 `--color-accent-contrast`，寫死灰色的話在強調色上只有 1.02:1）、名字查不到（已經不是成員）的人是沒有字的頭像，「所有狀態」是「沒有值」的短線（7.1）。這些都在 `features/work-items/selectOptionMarks.tsx`，表格、看板、項目頁、設定頁共用；大小是那裡的 CSS 區域變數。`Select` 本身不替沒有小圖的選項讓出位置，所以不放小圖的清單（類型、角色、優先度）每個選項都不放。
- 目前的值：右邊一個 `check` 圖示（`--color-accent`）加字重 medium。反白〔已有：視覺翻新〕：實心的 `--color-accent-solid` 底、白字（`--color-accent-contrast`，對比 5.96／5.30），前面的小圖、第二行的原因、目前的值的打勾都跟著字色（`Menu` 的反白、快速跳轉選起來的那一個同一種）。理由：淡底和紙的對比不到 1.2:1，鍵盤走到哪一個看不出來；原本靠左邊 3px 的色條補，現在實心的底本身就看得出來，不需要色條（第 9 節）。實心的底一定用 `-solid`，不用 `--color-accent`：深色的 `--color-accent` 是淡紫，當實心的底像糖果、只能配深色字。不能選的選項反白時**不是**實心的：`--color-hover` 的底加灰字（`text-muted` 對它 5.5／6.4），看得出選不了；淡底對紙只有 1.1:1，所以再加一圈 2px `--color-focus` 的環線（`inset 0 0 0 2px`），鍵盤走到這裡看得出來（最後一位管理員的角色、看板「移到…」被擋下的目標）。目前的值與反白可以同時出現在同一列。不只靠顏色（打勾、字重）。
- 前面的小圖（可以沒有）：狀態的選項放狀態類別的形狀（和 `StateBadge` 同一組圖示），人員的選項放 `Avatar`；裝飾、`aria-hidden`。按鈕上目前的值帶同一個小圖。類型、角色、流程這些不放。
- 不能選的選項留在清單裡、灰字、方向鍵停得到，原因寫在第二行（`--text-xs`）：寫短語，完整的說明放在清單外面（按鈕用 `aria-describedby` 連過去）。例：最後一位管理員的角色選單裡，其他角色都不能選，選項寫「最後一位管理員不能換角色」，完整的句子在表格下面那一段（理由：同一句長的說明在清單裡重複好幾次）。
- 分組：只畫一條細線，不加標題。例：負責人的篩選是「所有人、我、沒有負責人」一組，成員一組。
- 一個選項都沒有時清單裡寫「沒有可以選的」，不是空白的框。這一列是清單裡一個不能選的選項（`role="option"`、`aria-disabled`），反白指著它：報讀軟體打開時聽得到，不是一個空的清單。篩選之後沒有符合的是「沒有符合的選項」，同一種長相。

**鍵盤**（焦點在按鈕上，清單裡的反白用 `aria-activedescendant` 表示；選項多、有篩選框時見下面的「選項很多的時候」）

| 按鍵 | 關著的時候 | 開著的時候 |
|---|---|---|
| Enter、空白鍵 | 打開，反白在目前的值 | 選反白的那個，關上 |
| ↓、↑、Alt+↓ | 打開，反白在目前的值；**不換值** | 移動反白，到頭尾就停，不繞回去 |
| Home、End | 打開，反白在第一個、最後一個 | 到第一個、最後一個 |
| PageUp、PageDown | 不處理 | 一次移動 10 個 |
| 打字 | 打開，反白跳到開頭符合的選項 | 跳到開頭符合的選項；500ms 內連續打的字算同一串（這時的空白鍵是字的一部分），同一個字重複打是在符合的選項之間輪流 |
| Esc | 不處理（外層照常收到：格子取消編輯、對話框關閉；面板的 Esc 和原生的下拉一樣不作用，`lib/shortcuts.ts` 把 `role="combobox"` 當成下拉） | 關上，值不變，不往外傳 |
| Tab | 照常往下走 | 關上，值不變，照常往下走 |
| 其他（⌘K、←、→） | 不處理，交給呼叫端的 `onKeyDown` 與外層 | 同左 |

輸入法選字中的按鍵都不算（`lib/keyboard.ts`）。

**滑鼠與觸控**：點按鈕開關（用滑鼠左鍵按下時就把焦點放到按鈕上：Safari 點 `<button>` 不給焦點）；點欄位的標籤和點按鈕一樣（開著時是關上，指到按鈕的標籤不算「外面」；打開時焦點不在按鈕上就補一次：Safari 點標籤不給按鈕焦點）；點選項就選、關上；點在外面關上、值不變；按鈕被捲出畫面時關上。滑過選項只移動反白。在清單上（包括外框與內距）按下滑鼠不會把焦點從按鈕帶走（`Floating` 的 `keepsAnchorFocus`；篩選框除外，要點得進去）。清單捲到頭不連帶捲動後面的頁面（`overscroll-behavior: contain`）。觸控和滑鼠同一份清單（不換成系統的選擇器，也不換成底部抽屜），選項 44px 高。

**值什麼時候變**：只有明確選了（點選、Enter、空白鍵）才變，並且通知一次；方向鍵與打字只移動反白。選了目前的值等於沒改。這和原生的不一樣（原生在某些系統按方向鍵就換值），所以「滑鼠選了就存、鍵盤要按 Enter」的區分不需要了：**選了就是選了**。

**在格子與對話框裡**

- 就地編輯的格子用 `variant="bare"`〔已有：視覺翻新，`data-variant="bare"`〕：按鈕沒有外框、底色、焦點光暈，撐滿格子（`height: 100%`，至少 `--control-height-sm`），左右內距和平常的格子一樣（`--space-3`）、字和格子一樣大，進入編輯時文字不跳動；外框由格子畫（一圈 2px 的 `--color-focus`，8.3「就地編輯」）。理由：原本格子畫一圈、裡面的下拉又一圈圓角外框加焦點外框，兩層框（使用者回報的問題）。清單照常浮出來。對話框裡（`placement="dialog"`）照舊是一般的長相（`default`）。
- 就地編輯的格子：進入編輯時清單直接打開。選了就儲存並結束編輯（選了目前的值也結束，不送出）；Esc 一次就關上清單並取消編輯；Tab 或點在外面是關上、不改、結束編輯；按鈕被捲出畫面是關上並取消編輯、焦點回到格子（不捲動；項目頁與面板沒有表格幫忙找回停駐點，用「離開」結束的話焦點會掉到頁面本體）；再按一次下拉是關上並取消編輯、焦點回到格子（實作時定；理由：選了就已經存了，這時一定沒改，用「離開」結束的話按鈕跟著不見、焦點會掉到頁面本體）。
- 表單與對話框：選了只是填好，和其他欄位一起送出。在關著的下拉上按 Enter 是打開清單，不是送出表單。
- 馬上生效的下拉（成員的角色、篩選、看板的流程）：選了就生效。

**無障礙的合約**

- 按鈕：`role="combobox"`、`aria-haspopup="listbox"`、`aria-expanded`，打開時有 `aria-controls` 與 `aria-activedescendant`。名稱來自 `<label>`、`aria-label` 或 `aria-labelledby`，**一定**要有，而且和換掉之前一樣（測試用 `getByRole('combobox', { name })` 找它）。目前的值是按鈕裡的文字。
- 清單：`role="listbox"`，名稱和按鈕一樣。選項：`role="option"`、`aria-selected`；不能選的 `aria-disabled` 加 `aria-describedby` 連到原因。每個選項帶 `data-value`。
- 選項可以帶 `groupLabel`（組的名字）〔已有：PM-4a，批次改狀態時選取的項目分屬不同流程，依流程分組；2026-11-20 起篩選的狀態也依流程分組，見 8.3「篩選與搜尋」〕：這一項前面多一行組的名字（`--text-xs`、semibold、`--color-text-muted`；不是選項、不能選、`role="presentation"`，報讀軟體跳過，清單照樣是 `role="listbox"` 底下只有選項）；第一組的名字在最上面，後面的組前面一條細線。每一組的第一項帶、其他不帶；和 `startsGroup` 擇一。組的名字不進篩選；打字篩選時一組的第一項可能被篩掉，組名改畫在那一組**第一個看得到的**選項前面（`selectGroups.ts`），留下來的選項才看得出是哪一組的（兩個流程都有「內部驗收」）。
- 清單只有打開時才在畫面與無障礙樹裡：要看有哪些選項，先打開。
- 強制色彩（Windows 的高對比）：外框與打勾跟著系統色；反白是系統的 `Highlight` 底加 `HighlightText` 字（系統色不會被換掉），外面再畫一圈 `Highlight` 的外框，底色真的被拿掉時仍然看得出來；不能選的選項反白時是 `Canvas` 底、`GrayText` 字加外框；危險的選單項目反白時也是 `Highlight` 底（不是被系統換掉的危險色）；不能選的選項與 placeholder 是系統的 `GrayText`；分組的細線用外框畫（`Menu` 的分隔線也是），不用會被拿掉的底色。按鈕取得焦點時的光暈會被拿掉，透明的 `outline` 由系統畫出來。
- 放大到 200%、寬度 320px 時清單不超出畫面。

**選項很多的時候**〔已有：自訂控制項 P3，`components/Select/selectFilter.ts`〕：10 個以上的（人員、負責人、上層項目，以及任何 10 個以上的）清單最上面多一個篩選框，自動出現、不用逐處開關。中文沒辦法靠「打字跳到開頭符合的選項」找人，所以人多的清單一定要有它。

- 打開時焦點在篩選框裡（格子進入編輯時也是）；關著時在按鈕上打字是打開並把那個字放進篩選框（游標在字的後面，接著打的字接在後面）。每次打開都從空的篩選開始。清單開著、焦點卻在按鈕上時（在按鈕上按下滑鼠、拖出去才放開），打的字與方向鍵轉給篩選框，照篩選後的清單算。
- 打字就篩選：比對選項的文字與 `keywords`（人員另外比對 Email），用「包含」不是「開頭」，英文不分大小寫，兩邊先做 NFKC（全形與半形一樣：「ＡＧＹ－１２」找得到 AGY-12）；只畫符合的選項，反白到第一個符合的（清空時回到目前的值）。輸入法選字中不篩，選好字才篩；選字中的按鍵都是輸入法的（Esc 也不往外傳）。
- 篩選框的做法照快速跳轉的 combobox：輸入框是 `role="combobox"`、`aria-controls` 指到清單、`aria-autocomplete="list"`，反白用它的 `aria-activedescendant`（按鈕這時不帶）；選項的 id 照它在完整清單裡的位置編，篩選時同一個選項 id 不變、反白換了 `aria-activedescendant` 的值就換（理由：照篩選後的第幾個編的話，反白常常一直是第 0 個，值沒變報讀軟體不唸）；名稱是「篩選」加清單的名稱（「篩選 負責人」）；按鈕的說明與錯誤（`aria-describedby`、`aria-invalid`）也帶到篩選框；長相是 `TextField` 的 `size="sm"` 加放大鏡。
- 按鍵：↑／↓ 與 PageUp／PageDown 移動反白（和上面的表一樣）；Home、End 留給輸入框（游標到頭尾）；Enter 選反白的那個；Esc 關上、值不變、焦點回到按鈕、不往外傳；Tab 關上、值不變、照常往下走（焦點先回到按鈕，瀏覽器再從按鈕往下走）。選了、Esc、再按一次按鈕之後焦點都在按鈕上。
- 沒有符合的：清單裡寫「沒有符合的選項」，Enter 不選、清單留著。結果數用 `aria-live="polite"` 的區域（只給報讀軟體；不用 `role="status"`：頁面上全域的 status 只有一個）唸「5 個符合」「沒有符合的選項」，打字停下來 300ms 才換（和快速跳轉送出搜尋同一個 300ms；理由：每打一個字就唸，會和字元的回音搶著唸）。區域打開時是空的，關著時打字打開的那一次也唸得到。篩選字換了，反白的選項照樣捲到看得到。
- 焦點在按鈕與篩選框之間移動不算離開：呼叫端的 `onBlur`（格子的「離開就儲存」）只在焦點離開整個下拉時叫。對話框的焦點陷阱算頭尾時不算篩選框（`lib/focusable.ts` 的 `TRANSIENT_FOCUS_ATTRIBUTE`）：下拉是對話框最後一個可停的元素時，Tab 從篩選框繞回對話框的第一個。
- 不做虛擬化：最多的是上層項目（200 個），篩選時只畫符合的、還符合的選項是同一個元素（`key` 是 value），按鍵時不重建整個清單。

**勾選框**

- 元素仍然是原生的 `<input type="checkbox">`：鍵盤、表單、名稱、測試都不變，只換畫法（`appearance: none`），寫在 `global.css`，全站一次換掉。
- 方框 16px、`--radius-sm`、1px `--color-control-border`、`--color-surface` 底，外距是 0（瀏覽器各家給的外距拿掉，對齊由呼叫端的 gap 決定）。大小、勾的長寬與 2px 的線寬是 `global.css` 的區域變數，功能的 CSS 不再各寫一份 16px。勾選：底與外框變成 `--color-accent-solid`，中間一個 `--color-accent-contrast` 的勾，用 CSS 畫（不用圖片、不用文字符號），出現時 `--duration-fast`。
- 滑過外框 `--color-text-muted`；鍵盤焦點是全域的焦點外框；停用是 `--color-surface-sunken` 的底、`--color-border-strong` 的外框，勾變灰；有錯是 `--color-danger` 的外框。
- 點擊範圍是整個 `<label>`，至少 `--target-min`（已有）。
- 部分選取（`indeterminate`，表格表頭的「選取全部」，7.1「多選」）：和勾選一樣是 `--color-accent-solid` 的底與外框，中間不是勾而是一條橫線（`--color-accent-contrast`，線寬同勾）〔已有：PM-4a〕。
- 強制色彩時退回系統的樣子（`appearance: auto`）：自己畫的勾會被系統拿掉。

**日期**〔已有：視覺翻新，`components/DatePicker`〕：自己畫的日曆，取代原生的 `<input type="date">`。理由：瀏覽器的日曆是系統畫的（系統字、「2026年11月 ▾」、系統的藍），字體、顏色、深色模式都管不到，每個系統長得不一樣（使用者回報「好醜」）；原則 7「同一件事只有一種長相」在原生的日曆上做不到。原本「自己做日曆要處理鍵盤、手動輸入、各地的日期寫法」的顧慮：鍵盤照 APG 做、手動輸入照下面的格式、日期寫法只有一種（`2026/12/15`），範圍可以控制。

```
┌──────────────────────────┐
│ 2026/12/15            ▦ │   輸入框（role="combobox"）：可以直接打字；右邊的日曆圖示是裝飾
└──────────────────────────┘
┌────────────────────────────────┐
│  ‹      2026 年 12 月 ⌄      ›  │   上一個月｜標題（按鈕：換到月份畫面）｜下一個月
│  一  二  三  四  五  六  日      │   一週從哪天開始照個人偏好（預設週一）
│  30   1   2   3   4   5   6    │   前後月份補滿六列：灰字、可以選
│   …  ■15■ …                    │   選的那一天：實心的強調色；今天：強調色的字加 1px 環線
│ ─────────────────────────────── │
│  今天                    清除    │
└────────────────────────────────┘
```

- **結構**（照 WAI-ARIA APG 的 Date Picker Combobox：焦點留在輸入框）：輸入框是 `role="combobox"`、`aria-haspopup="dialog"`、`aria-expanded`，打開時 `aria-controls` 指到日曆。日曆是 `role="dialog"`（名稱「選擇日期」）裡的 `role="grid"`：名稱是月份「2026 年 11 月」；換頁、換畫面時另外有一個只給報讀軟體的 `aria-live="polite"` 區域唸出新的標題（標題現在是按鈕，按鈕的名稱換了不會自己唸）——打字讓日曆跟著換月時不唸（區域清空），只有按鈕、方向鍵、換畫面造成的才唸，理由：和打字的回音搶著唸；表頭「一 二 三 四 五 六 日」的名稱是「星期一」…；每一格的名稱是完整的日期加星期（「2026 年 11 月 17 日 星期二」），選的那一天 `aria-selected="true"`、今天 `aria-current="date"`。日期格用 roving tabindex：只有焦點那一格（選的那一天，沒有值時是今天）的 `tabIndex` 是 0。月曆**一定**是 `div` 加角色（`grid`、`row`、`columnheader`、`gridcell`），排版用 CSS grid（一列七欄），**不用** `<table>`：浮層不是 portal（第 13 節），日曆留在打開它的元素旁邊的 DOM 裡，放在表格的格子裡時會吃到外層表格的樣式（`.table td` 的內距與每一列的細線、黏住的表頭、滑過的底色），外層用 `querySelectorAll('tr')` 數列的程式也會數到日曆的列（8080 實測時格子裡的日曆每一列下面多一條線）。月份按鈕是 `IconButton`（「上一個月」「下一個月」，`chevronLeft`／`chevronRight`），中間的標題是換到月份畫面的按鈕（見下面的「年份與月份」），下面一列「今天」「清除」（`ghost`、`sm`）。
- **一週從哪天開始**〔已有：2026-11-18〕：照個人偏好 `WeekStart`（`lib/weekStart.ts`，`'monday' | 'sunday'`，預設週一；`useWeekStart()`，切換的地方見 8.3「網址就是狀態」與帳號選單、行事曆）。表頭的順序（週一到週日，或週日到週六）、頭尾補的上下個月的日子（六列 42 天從 1 日所在那一週的第一天起排）、Home／End 都照它走；每一格的名稱仍是完整的日期加星期（「2026 年 11 月 17 日 星期二」），不受偏好影響。算法在 `domain/dates.ts`（`startOfWeek`、`endOfWeek`、`dayOfWeekIndex`），和我的工作「這一週」、「本週到期」、行事曆、時間軸是同一套。理由：一週從哪天開始因人而異（台灣的月曆常見週日開頭，工作週常從週一算），各處的「一週」必須一致，所以做成一個偏好、不各自設定；預設週一，不讓原本的畫面突然改變。
- **打字**：顯示與打字的格式是 `2026/12/15`（`formatDate`）；也接受 `2026-12-15`、`2026.12.15`、`2026/1/5`（月、日一位數）、`20261215`，全形的數字與「／」也認得（先做 NFKC，和下拉的篩選一樣）；空白是沒有值。年份要四位數、1000 以上：`0999/1/1` 當成解析不了（原始文字照傳），不會變成不是 ISO 的「999-01-01」。打成解析得了的日期：`onChange` 收到 ISO，日曆跟著跳到那個月、標出那一天；解析不了的傳原始文字，呼叫端自己判斷不合法（格子顯示錯誤），不默默吃掉。打到一半不重新排版（`2026/1/1` 不會跳成 `2026/01/01`，游標不跳），離開欄位或從日曆選了才排成 `2026/12/15`。打字不算「選了」（不叫 `onPick`）。
- **打開與關上**：用滑鼠點輸入框的任何地方（包括圖示）就打開，焦點留在輸入框、照樣可以打字；用 Tab 走進來不打開。↓ 或 Alt+↓ 打開並把焦點移進日曆（開著時也是）。關上：選了（日期、「今天」、「清除」）之後關上、焦點回到輸入框；Esc（輸入框或日曆裡；在月份、年份畫面是先回到上一層畫面）關上、值不變、焦點回到輸入框、不往外傳（關著時的 Esc 照常往外傳：格子取消編輯、對話框關上）；點在外面、輸入框被捲出畫面關上（焦點在日曆裡時，點在外面的當下先把焦點放回輸入框：點的是另一個停得到的元素，焦點照樣移過去、呼叫端的 `onBlur` 照樣叫；點的是停不到的地方——對話框的背景——就留在輸入框，不掉到頁面本體，對話框的焦點陷阱照樣有效）；開著時在輸入框按 Tab 是關上並照常往下走（只想填表單的人不必走過整個日曆）。`onDismiss` 的原因和 `Select` 一樣（`escape`、`outside`、`tab`、`scrolled`；沒有切換開關的按鈕，`toggle` 目前不會出現）。停用與唯讀的打不開；送出中（`aria-busy`）打得開，但選了不收新的值。
- **日曆裡的按鍵**：←→ 一天、↑↓ 一週、Home／End 這一週的第一天與最後一天（照上面的偏好：週一與週日，或週日與週六）、PageUp／PageDown 一個月、Shift+PageUp／PageDown 一年（日子超出就停在月底：1 月 31 日的下一個月是 2 月 28 日）；走到別的月份時日曆跟著換。Enter、空白鍵選焦點那一天（選了目前的值不叫 `onChange`，`onPick` 照樣叫）。Tab 在日曆裡依序走過上一個月、標題、下一個月、日期格、「今天」「清除」；從「清除」再 Tab 是關上並往下走（焦點先回到輸入框，瀏覽器再從輸入框往下走）。輸入法選字中的按鍵都不算。
- **年份與月份**〔已有：視覺翻新〕：日曆有三層畫面——日期 → 月份 → 年份。理由：到期日、開始日常要跳到明年或幾個月後，原本只有一個月一個月按（鍵盤的 Shift+PageUp／PageDown 一年，滑鼠沒有辦法）；使用者問「沒辦法直接切年份嗎」。
  - 日期畫面的標題「2026 年 12 月」是按鈕（`ghost`，後面一個小的 `chevronDown`；名稱「2026 年 12 月，選擇年份與月份」，看得到的字在名稱開頭，WCAG 2.5.3），按了換到**月份畫面**：標題是「2026 年」按鈕（名稱「2026 年，選擇年份」），左右是「上一年」「下一年」，下面 3×4 的「1 月」…「12 月」（每一格的名稱是「2026 年 12 月」）。月份畫面的標題按了換到**年份畫面**：一頁 12 年，從顯示的年份往前兩年開始（2026 → 2024～2035：看得到去年、前年，也看得到明年之後的幾年），標題是範圍「2024～2035」（不是按鈕，沒有再下一層），左右是「前 12 年」「後 12 年」，格子的名稱是「2026 年」。三種畫面的格子都是 `role="grid"`（`div` 加角色）。
  - 選了月份：回到日期畫面、顯示那個月，焦點那一格是**同一天**（那個月沒有這一天就夾到月底）；選了年份：回到月份畫面、顯示那一年。在月份、年份畫面裡移動時記著進月份畫面時的那一天：1 月 31 日經過 2 月走到 3 月還是 31 日（只看 2 月的話會變成 28 日）。
  - 選的日期所在的月、年是實心的 `--color-accent-solid`（`aria-selected="true"`），今天所在的月、年是強調色的字加 1px 環線（`aria-current="date"`：`date` 是「一組日期裡目前的那一個」，月、年也是日期的單位，和日期格同一套，不用 `true`）。
  - 按鍵（月份、年份畫面）：←→ 一格、↑↓ 一列（3 格）、Home／End 這一列的頭尾、PageUp／PageDown 月份畫面一年、年份畫面 12 年（年份走出這一頁時，頁面一次換 12 年，不跟著每一步滑動）；Enter、空白鍵選；**Esc 是回到上一層畫面**（年份 → 月份 → 日期），日期畫面的 Esc 照舊關上日曆、焦點回到輸入框。
  - 焦點：換畫面時，焦點本來就在日曆裡（用鍵盤、或按了日曆裡的按鈕）才放到新畫面對應的那一格；焦點在輸入框（用滑鼠點開、照樣可以打字）時不搶。
  - 只有選了日期（日期畫面裡選、「今天」、「清除」）才算選了：換月、換年、換畫面都不叫 `onChange`／`onPick`，格子不會因此存檔。打開日曆一律從日期畫面開始。
  - 三種畫面的外框一樣大：月份、年份的格子撐滿日期畫面的寬（七格加六個間隙）與高（表頭加六列），換畫面時日曆不跳；觸控 44px 與 320 寬的例外照舊（格子的大小在日曆那一層定一次）。
- **滑鼠與焦點**：在日曆上按下滑鼠不帶走焦點（`Floating` 的 `keepsAnchorFocus`）：用滑鼠換月份、換畫面時焦點留在輸入框；焦點在格子上時（用鍵盤走進日曆之後再用滑鼠按左右兩顆按鈕），焦點跟著移到新的一頁對應的那一格（原本那一格跟著不見，不移的話焦點掉到頁面本體，之後的 Esc 交給了面板）；焦點在按鈕上就留在按鈕上。
- **觸控**：用手指點開日曆時，輸入框暫時是 `inputMode="none"`（不叫出螢幕鍵盤：鍵盤會蓋住日曆，iOS 尤其如此）；日曆開著時再點一次輸入框、或日曆關上，就恢復成一般的輸入框、可以打字。用滑鼠點開的不設（照樣可以直接打字）。日曆的焦點只是暫時在那裡（`TRANSIENT_FOCUS_ATTRIBUTE`）：對話框的焦點陷阱算頭尾時不算它。呼叫端的 `onBlur` 只在焦點離開整個元件（輸入框與日曆）時叫。
- **長相**：輸入框和 `TextField` 同一套（`fieldControlClassName`，焦點照第 9 節），右邊一個 16px 的日曆圖示（`--color-text-muted`）；格子裡用 `variant="bare"`（和 `Select` 的 `bare` 一樣：沒有外框、底色、焦點光暈，撐滿格子，左右內距 `--space-3`）。日曆經過 `Floating`（第 13 節），外殼和 `Select` 的清單同一族（紙、細線、`--shadow-popover`），裡面有格子所以圓角是 `--radius-lg`（例外：浮層的外框一般是 `--radius-md`，日曆裡是一整片 32px 的格子、比選單寬也高，外框比格子的 `--radius-md` 大一號才貼合，第 5 節）、內距 `--space-3`；寬度固定（七格加間隙），放不下就翻到上面。標題 `--text-base` semibold；表頭 `--text-xs`、`--color-text-muted`。日期格 32px 見方（觸控 44px，`max(2rem, var(--target-min))`）、格子之間 `--space-1`、`--radius-md`、`--text-sm`、`tabular-nums`：滑過 `--color-hover`；選的那一天實心的 `--color-accent-solid` 底、白字、semibold（日曆的慣例）；今天是 `--color-accent` 的字加 1px 的環線（`inset 0 0 0 1px`，不是色條、不是小圓點）；別的月份 `--color-text-muted`；鍵盤焦點是全域的焦點外框、畫在格子外面 1px（選的那一天是實心的強調色，畫在裡面看不出來）。**日曆裡實心的是選的那一天，鍵盤所在的那一格是焦點外框**：和 `Select`、`Menu` 不同（它們的反白是實心的），日曆同時要表示「選的是哪一天」與「鍵盤在哪一格」，兩件事要分得開。**例外**：320px 寬的手機放不下七格 44px（加上浮層兩邊的留白、內距與間隙要 360px 以上），日期格照畫面的寬度縮到約 36px，日曆不超出畫面——仍然高於 24px 的最低要求（WCAG 2.5.8）；390px 以上是 44px。第 14 節的 `targetsUnder44High` 在 320 寬打開日曆時不算這些格子。矮的畫面（320 寬、高度不到約 700px）日曆比上下可用的空間高，浮層照規則限高、在裡面捲動：「今天」「清除」要捲一下才看得到（目前接受）。強制色彩：選的那一天 `Highlight`／`HighlightText`、今天用系統色的外框、別的月份 `GrayText`。
- **格子裡的日期**〔已有：視覺翻新，`features/item-table/cells/DateEditor.tsx`〕：用 `variant="bare"`、`size="sm"`；只有**用滑鼠**進入編輯（`click` 的 `detail > 0`）時 `isOpenInitially`，用鍵盤進入編輯（Enter、F2）不打開（照樣可以打字，↓ 再打開）；從日曆選了（`onPick`）就存並結束編輯，打字的照舊 Enter 或離開才存；打了解析不了的字在格子裡說明（8.3「就地編輯」）。補填對話框裡是一般的長相、不自己打開，選了只是填好。原生的 `<input type="date">` 與 `showPicker()` 已經不用（`components/Field/datePicker.ts` 拿掉了）。
- **時間**：目前沒有時間的欄位。之後需要時照同一套長相做 `TimeField`（輸入框加自己畫的浮層、同樣的鍵盤與無障礙的合約），先改這一節；不用原生的 `<input type="time">`。
