## 1. 方向與原則

**方向：明亮的工作室。** 這是每天要用、資訊很密的工作工具，核心仍然是「藍圖」：每個專案的流程、類型、欄位都照藍圖來。畫面要像一間採光好的工作室——帶一點紫的紙（內容）放在藤灰的桌面（側欄）上，靠細線、留白與對齊分出結構；深色模式是鐵紺，明暗都不用純白與近黑（2026-11-23，2.2）；語氣年輕但不失專業：紫藍的強調色（`#5a4ae3`）、圓一點的角、柔和而帶色相的陰影、友善的拉丁字型（Plus Jakarta Sans），編號與代號用等寬字（Geist Mono）。紫藍是唯一的互動色，狀態類別、危險、警告、成功各有自己的顏色；顏色只拿來表達意義，**沒有裝飾用的色條**（第 9 節）。不做裝飾：沒有漸層、插畫、玻璃效果，也不用 emoji。理由（2026-11-17 視覺翻新，`internal/HANDOFF-visual-refresh.md`）：原本的「製圖桌」（藍圖藍、純灰、系統字）精確但冷，使用者要「年輕但不失專業」；下面七條原則不變，變的是語氣。

七條原則，後面每一節都是它們的展開：

1. **內容先於外框。** 導覽、頁首、工具列加起來有高度預算（第 14 節）。第一筆資料要在第一個畫面的上半部。
2. **一層就好。** 一個畫面最多兩層底色（紙與凹下去的軌道）；不做卡片裡的卡片。分隔靠細線與留白，陰影只給「浮起來的東西」（選單、對話框、拖曳中的卡片、黏住的列）。
3. **顏色只表達意義。** 強調色＝可以互動、目前所在、已選取；狀態類別各有自己的顏色（進行中是自己的藍，不借強調色：紫藍是「可以按」，藍是「正在做」，綠是「做完了」）；危險、警告、成功各有固定的顏色。同一件事不能只靠顏色區分，一定同時有文字、圖示或形狀。顏色不拿來裝飾：選取、反白、提示、狀態都不畫色條。
4. **密而不擠。** 滑鼠操作時用 14px 的字與 36px 的列高；觸控時同一份畫面自動換成 36px 的控制項（按鈕、下拉、輸入框）、44px 的整列目標（清單的一筆、選單項目）與 16px 的輸入框（靠設計變數，不是另一套畫面；控制項原本也是 44px，使用者 2026-11-27 嫌太高）。
5. **鍵盤與報讀是一等公民。** 每件事都能用鍵盤完成；拖曳一定有替代操作；按鈕不見之後焦點有去處；無障礙名稱是對外合約（測試靠它找元素）。
6. **就地、可回復、說人話。** 能在原地改就不換頁；不可回復的操作先說清楚後果再確認；錯誤訊息說發生了什麼、接下來可以做什麼。
7. **同一件事只有一種長相。** 一種選單、一種提示、一種狀態標籤。需要新的長相時，先看第 7 節有沒有，沒有就加進共用元件與本文件。

## 3. 文字

**字型**〔已有：2026-11-17 視覺翻新〕：拉丁字母與數字用自帶的 **Plus Jakarta Sans**（`--font-sans`，可變字重；圓潤、友善，數字好認），編號、代號、key 用自帶的 **Geist Mono**（`--font-mono`）；中文不自帶，落到系統的台灣字體（PingFang TC、微軟正黑體、Noto Sans TC）。兩套都是 OFL-1.1（可以隨另外賣商業授權的產品散布），從 npm 的 `@fontsource-variable/plus-jakarta-sans`、`@fontsource-variable/geist-mono` 安裝、在 `src/main.tsx` 匯入，由 Vite 打包成和網站同網域的檔案（內容安全政策與第 13 節）。理由：系統字在每個平台長得不一樣、語氣偏冷；中文字型一套好幾 MB，自帶不划算，系統的台灣字體也夠好。拉丁字型的字身比中文小一點，混排時**不要**為了對齊而調整字級（變數一份，兩種文字一起用）。

| 用途 | 大小 | 字重 | 備註 |
|---|---|---|---|
| 內容區的頁面標題（項目的標題、變更集編號） | `--text-xl` | bold（`--weight-bold`） | `--leading-tight`；`--weight-bold` 只給這一種標題 |
| 頁列上的標題（清單頁、專案頁、設定頁的 h1） | `--text-md` | semibold | 一行，超過用省略號 |
| 區塊標題 h2 | `--text-md` | semibold | |
| 子區塊標題 h3、對話框裡的分組 | `--text-base` | semibold | |
| 內文、表格、表單 | `--text-base` | regular；主要的那一欄 medium | |
| 欄位標籤、表頭、提示、時間 | `--text-sm` 或 `--text-xs` | regular／medium | `--color-text-muted` |
| 編號、代號、key（`AGY-12`、`code_review`） | `--font-mono`、`--text-sm` | regular | 不換行 |

- 最小 12px。層次靠字重與灰階，不靠更多種大小；一個畫面**建議**不超過四種字級。
- 每一頁剛好一個 h1，文字和瀏覽器分頁標題一樣（`PageBar`／`DocumentTitle`〔已有〕；項目頁的分頁標題是「編號 標題」；設定頁的分頁標題帶上區塊，見 8.3：分頁標題和 h1 不同時用 `PageBar` 的 `documentTitle`，一頁只有一個 `<title>`；登入後有未讀通知時前面多未讀數「(3) 我的工作 · Kumi」，見 8.3「收件匣」）；標題層級不跳號。載入中、讀不到的畫面可以沒有 h1（頁列只設分頁的標題）。
- 數字欄用 `font-variant-numeric: tabular-nums`，靠右對齊。
- 中文**不要**加字距、不用斜體、不用 `text-transform`；強調用字重或顏色。中文與英數之間留一個半形空白（「第 4 版」「已載入 6 個項目」）。
- 長段文字（說明、留言、說明性的段落）一行最寬 `--reading-max`。項目的說明超過 12 行先收起來（`line-clamp`，最後一行是省略號），下面「顯示全部」展開、「收起」收回（按鈕的文字就是狀態，不另外標 `aria-expanded`：兩個都有會唸成「收起，已展開」）；全文一直在 DOM 裡，報讀軟體唸得到全部，`pre-wrap` 的換行與縮排照舊；編輯時一律是全文。理由：說明很長時下層項目與活動被推到好幾個畫面之後（W5 量到 `AGY-3`）。
  - 例外：AI 助理的對話（整頁與右下角的浮動面板：訊息、輸入框、空白對話的說明）不限在 `--reading-max`〔2026-11-23〕。理由：2026-11-23 使用者要求：AI 助理的對話用滿畫面，和浮動視窗一樣，寬度由使用者自己的視窗與列表寬度決定（整頁的對話列表可以拖、浮動面板可以拖大，限寬了就白拖）。
- 截斷：表格與卡片裡的名稱可以單行省略，但完整文字**一定**有地方看得到（連到詳細頁，或 `title`）。說明、錯誤訊息、提示不截斷。

## 4. 色彩的意義

| 意義 | 變數 | 用在 |
|---|---|---|
| 可以互動、目前所在、已選取 | `accent`、`accent-soft`、`selected`、`focus`、`focus-ring`；實心的底是 `accent-solid`、`accent-solid-hover` | `accent`（線與字）：連結、目前的導覽項目的字、選取的列的連結、焦點外框、今天的環線；`accent-solid`（實心的底）：主要按鈕、反白的選項、勾選的方框、日曆選的那一天；`selected`：選取的列、目前的導覽項目的底 |
| 狀態類別 | `state-idle`、`state-active`、`state-done` 與各自的 `-soft` | 狀態標籤（`StateBadge`）；看板的欄靠標題列的標籤表達，不畫色條 |
| 不可回復、失敗、過期 | `danger`、`danger-soft` | 刪除、錯誤、「已過期」、擋住套用 |
| 要注意、畫面可能是舊的 | `warning`、`warning-soft` | 背景重抓失敗、已修改、高優先度 |
| 做完了、可以套用 | `success`、`success-soft` | 成功提示、完成類 |
| 中性 | `neutral-soft`、`text-muted` | 其他標籤、次要資訊、資訊類的提示（`Notice` 的 `info`：提示不能按，不用互動色） |
| 藍圖選項的藍與紫 | `option-blue`、`option-purple` 與各自的 `-soft` | 單選、多選欄位的標籤（`Badge` 的 `blue`、`purple`）；其他顏色（紅、橙、黃、綠、灰）對到語意色的標籤 |
| 認人（不是意義） | `avatar-1`～`avatar-6` 與各自的 `-soft` | 只有 `Avatar` |

- 五個狀態類別的長相〔已有，`StateBadge`〕：顏色之外**一定**有形狀——待規劃是虛線圓、未開始是空心圓、進行中是半滿的圓、完成是打勾的圓、已取消是劃掉的圓。標籤的文字是藍圖裡的狀態名稱。顏色〔已有：視覺翻新〕：待規劃、未開始、已取消是 `state-idle`（灰字）加 `state-idle-soft`；進行中是 `state-active`（自己的藍 `#1a5fd0`，深色 `#6fa8ff`）加 `state-active-soft`；完成是 `state-done` 加 `state-done-soft`。進行中**一定**不借強調色：紫藍是「可以按」，藍是「正在做」，綠是「做完了」，一眼分得出互動與狀態。
- 頭像的色調〔已有：視覺翻新，`components/Avatar`〕：照名稱算出 1～6 其中一種（`avatarToneOf`：FNV-1a 雜湊取餘數，名稱前後的空白不算），標在元素的 `data-tone`；底是 `--color-avatar-N-soft`、字是 `--color-avatar-N`。同一個名稱在表格、看板、活動、成員裡永遠是同一個顏色，掃過去就認得出是誰。色調只是幫忙認人，**不是**唯一的線索：頭像旁邊或名稱裡一定有名字的文字（第 7 節 `Avatar`）。名稱是空白的頭像（只畫「?」）、名字查不到的人（沒有字的頭像）、「所有人」「沒有負責人」的佔位小圖維持中性（`neutral-soft`、`text-muted`）：它們不是某一個人。理由：不用字元碼加總取餘數——中文姓名用加總時六種分得不平均（實測 3200 個姓名，最多與最少的色調差兩成），字換了位置也會同色。
- 優先度：緊急＝`danger`、高＝`warning`、中＝`text`、低＝`text-muted`，一定有文字（「緊急」「高」…）。
- 還沒送出的修改（設定頁）：新增＝`accent`、已修改＝`warning`、已移動＝中性、要刪除＝`danger`，一定有文字標籤〔已有〕。已修改、已移動、要刪除的整列（轉換表格是那一格）再加該語意的淡底（`warning-soft`、`neutral-soft`、`danger-soft`）；**新增的不加底色**，只靠強調色的「新增」標籤（轉換表格是強調色的「新增」兩個字）——理由：強調色的淡底就是「已選取」的 `--color-selected`，新增的列看起來會像被選取了。都不畫色條〔已有：視覺翻新〕。
- 變更集的狀態「等待核准」是中性的標籤（`neutral`），不用強調色：強調色只表達「可以互動、目前所在、已選取」，等待核准是狀態〔已有：視覺翻新〕。
- 變更集的狀態「已過期」用 `warning`（標籤與過期的提示），不是上表「過期」的 `danger`：那一列指的是到期日過了；變更集過期只是別的版本先套用了，可以到設定頁重新編輯再送，不是失敗。
- 一個畫面上的強調色面積要小：一顆主要按鈕、目前所在的標示、連結。大片的底色只用 `surface`、`surface-sunken`、`sidebar`。

## 5. 尺寸、間距、圓角、陰影

- 間距用 4px 的倍數（`--space-*`）。同一組裡的元素間隔 `space-2`，相關的群組之間 `space-4`，區塊之間 `space-8`。**建議**用 `gap` 排版，不要每個元素各自設 margin。
- 控制項（按鈕、輸入框、下拉）一律 `--control-height`；工具列與表格列上用 `--control-height-sm`。不要自己寫高度。
- 可以點的東西最小 `--target-min` 見方（滑鼠 24px、觸控 44px）；**例外**是觸控時的控制項（按鈕、下拉、輸入框、圖示按鈕，`--control-height`）是 36px，仍高於 WCAG 2.5.8 的 24px（2026-11-27 使用者看了手機版說「按鈕跟下拉選單、輸入框不用這麼高吧」），驗收時 `ui-audit` 的 `targetsUnder44High` 會數到它們，只看 24px 那一條。圖示本身 16px，不夠的部分用內距補；勾選框把整個 `<label>` 當成點擊範圍。內文裡的連結不在此限。
- 圓角照用途選，不要全部用同一個〔已有：視覺翻新，6／8／12／16〕：`--radius-sm`（6px）給外框裡面的內層項目（選單與下拉的選項、分段切換的一格、編輯中的格子）與小方塊；`--radius-md`（8px）給按鈕、輸入框、下拉的按鈕、選單與浮層的外框、提示；`--radius-lg`（12px）給看板的卡片、區塊的卡片、面板，以及日期欄位的日曆（浮層的例外：裡面是一整片格子，外框比格子的 `--radius-md` 大一號才貼合，7.3「日期」）；`--radius-xl`（16px）給對話框與看板的欄；`--radius-pill` 給標籤（`Badge`、`StateBadge`）、計數、頭像。外層比內層大一號，內層才貼合。例外：勾選框是 `--radius-sm` 小 2px（4px，`global.css` 的區域變數）——16px 的方框用 6px 看起來像圓點。
- 陰影〔已有：視覺翻新，柔和、帶一點強調色的色相〕：`raised` 給看板的卡片與分段切換裡目前的那一格；`raised-hover` 給滑鼠滑過的看板卡片（浮起來一點，看得出拿得起來；觸控不需要）；`popover` 給選單、浮層與拖曳中跟著指標走的卡片（`dialog` 是給擋住畫面、要先處理完的對話框；拖曳中的卡片只是暫時浮起來，和選單同一層）；`dialog` 給對話框與手機的抽屜。表格、區塊、面板**不用**陰影，用細線。
- 層級：全域的只用 `--z-*`；元件內部自己疊可以寫 `1`、`2`、`3`。表格裡的順序（由低到高）：固定欄 `1`（蓋過捲到它底下的格子）、編輯中浮起來的格子 `2`（蓋過下面幾列與固定欄，8.3「就地編輯」）、黏住的表頭 `3`（蓋過全部，包含編輯中的格子：編輯標題時捲動，表頭照樣在上面）。理由：原本只准 `1`、`2`，編輯中的固定欄升到 `2` 就和表頭打平，表身在後面，捲動時標題格會蓋在黏住的表頭上。黏住的表頭自成一層，裡面再疊〔已有：欄寬〕：調欄寬的把手 `1`（蓋過右邊那一格的表頭）、固定欄的標題 `2`、編號 `3`——橫向捲過去的欄的把手在固定欄底下，編號右緣的把手疊在標題的表頭上、不被它蓋住。樣式檢查（`scripts/check-styles.mjs`）照這個允許清單。
- 會橫向捲動的容器**一定**設 `position: relative`：裡面給報讀軟體的隱藏文字是絕對定位的，容器不當基準的話，捲出去的那些會把整頁撐寬（表格與設定頁的轉換表格都這樣做；轉換表格原本漏了，曾經讓設定頁在手機寬度橫向溢出）。

- **帳號選單的項目**〔已有：帳號安全那一輪，`features/shell/AccountMenu.tsx`〕：由上而下是「我的帳號」（到 `/account`，第 8.3 節「我的帳號」）、主題那一組、「登出」，組與組之間一條分隔線。「我的帳號」放第一個：打開選單時焦點就在它上面，改密碼、登出其他裝置是這個選單裡最常找的事。
- **主題的選項**：帳號選單裡是三個勾選型的項目（`Menu` 的 `isChecked`，`menuitemradio`）「主題跟著系統」「淺色主題」「深色主題」，目前的那一個帶 `aria-checked` 並畫打勾，不再在名稱後面寫「（使用中）」；後面接著「一週從週一開始」「一週從週日開始」兩個同樣的項目（8.3「網址就是狀態」）。理由：共用的 `Menu` 有了勾選型的項目，報讀軟體唸得到哪一項是目前的，看得到也不只靠圖示或顏色；兩組寫法一致。這幾項不帶圖示（勾選的那一項自己畫打勾）。
- **頁列**（`PageBar`）：每一頁一個。左邊是位置（`<nav aria-label="位置">`）與標題，右邊是這一頁的動作，最多兩顆看得到的按鈕，其餘收進「更多動作」選單（圖示按鈕，名稱帶上對象，例如項目頁的「AGY-3 的更多動作」；專案頁是例外：「資訊」「設定」「規劃」「成員」四顆照舊，之後接一顆「專案的更多動作」，理由見 8.3「專案的改名與封存」）。高度固定 `--page-bar-height`，黏在內容區上方。頁面的說明文字不放在頁列。**窄螢幕（48rem 以下）頁列右邊的動作多於兩顆時收進一顆「更多」的圖示按鈕**（`IconButton` 加 `Menu`，名稱帶上對象，專案頁是「專案的動作」：資訊、設定、規劃、成員，再加上寬螢幕「更多」選單裡的項目（匯入項目…、已刪除的項目，分隔線，重新命名…、封存專案或取消封存，8.3「專案的改名與封存」），組與組之間用分隔線，選了就導過去或打開對話框；沒有權限的項目照舊不出現）。理由：實測 390px 寬時「設定」「規劃」「成員」三顆按鈕把專案名稱擠到只剩「Scru…」、代號只剩「S」。寬螢幕照舊排在頁列上。**專案頁頁列上的「我的角色：…」在 64rem 以下只給報讀軟體**（視覺上隱藏、文字還在 DOM 裡，和窄螢幕原本的做法一樣，`ProjectPage.module.css`，斷點照第 13 節只寫 `min-width: 64rem`）。理由：多了「資訊」之後 48～64rem 的頁列放不下（2026-11-20 實測：769 寬名稱只剩 8px、800 寬代號整個不見名稱剩 26px、900 寬仍被截斷，1024 以上正常）；角色是次要資訊，名稱才是這一頁的位置。頁列上有標題時，目前的頁面就是那個標題，位置裡不標 `aria-current`；標題在內容區時（項目頁、變更集預覽）位置的最後一段才是目前的頁面。
- **窄螢幕的位置**（48rem 以下，CSS）：只留最近的上一層與目前那一層——頁列上有標題時只留位置的最後一段，標題不在頁列時留最後兩段（「變更集 › #3」）。其餘 `display: none`，畫面上與報讀軟體都略過；`<nav>` 與它的名稱不變。理由：390px 寬的頁列放四層位置加兩顆按鈕會擠到標題看不見；完整的位置在寬螢幕看得到，窄螢幕的畫面也沒有，報讀軟體跟著畫面走。
- **工具列**（`Toolbar`）：檢視切換、搜尋、篩選這類「影響下面內容」的控制項放這裡，一列；放不下就把次要的收進「篩選」（專案的表格與看板都是：看板的流程、搜尋、負責人也在工具列上，內容裡不再另外放一列篩選）。欄位用 `size="sm"`、標籤視覺上隱藏（`isLabelHidden`，名稱還在），意思由選項文字（「所有類型」「所有狀態」「所有人」）、搜尋框的放大鏡與提示文字帶出來。按了會跟著不見的「清除條件」，焦點放到搜尋框（窄螢幕是「篩選」按鈕）。48rem 以下（`useIsCompact()`）篩選與排序收進「篩選」（`Popover`，按鈕上是目前有幾個條件的數字，完整的說法用 `aria-describedby`），新增換成右下角的圓形按鈕「新增項目」（打開對話框，見 8.3「新增項目（窄螢幕）」）。**窄螢幕的工具列是一行、左右滑**〔2026-11-27 使用者看過手機版設計稿後採用，`Toolbar` 的 `isScrollable`，專案頁與我的工作用〕：版面、檢視、篩選（我的工作再加分組的收納）放不下時不折行，橫向捲動、藏捲軸（露出一半的控制項就是提示）；`position: relative`（第 5 節，隱藏文字的定位基準）；捲動容器會裁掉外面的焦點外框，所以裡面的控制項焦點外框畫在內側（`outline-offset: -2px`），捲到邊也不被切；控制項在觸控時本來就是 44px。理由：折成兩列會把內容往下推，設計稿的做法是第一個畫面留給清單。工具列裡的下拉（版面、範圍）照內容的寬度（最窄 4.5rem、左右內距 `--space-3`，和旁邊的按鈕一樣），不用平常的 8rem 下限（兩個字的值右邊會空一大塊；2026-11-27 使用者回報手機版空間比例不協調，照 4/8 的間距節奏與對齊重新調整）。其他頁的工具列（總覽、設定、收件匣）照舊折行。48rem 到 64rem 之間允許排成兩列：理由是這個寬度的表格仍然是主要的工作畫面，篩選常用，收進浮層要多點一下；高度預算只在寬螢幕（1440）與手機量。專案頁的「版面」（表格、看板、行事曆、時間軸）寬螢幕是分頁，48rem 以下改成一個下拉（標籤視覺上隱藏），讓「版面」「檢視」「篩選」留在同一列：四個分頁加「檢視」會把手機的第一列排滿，「篩選」掉到第二列、內容往下推（8.3「版面的切換」）。寬螢幕上放不下的條件依序收進「更多條件」（優先度、到期、類型、狀態、負責人，搜尋一律留著），不是整組收（8.3「篩選與搜尋」）。

### 6.2 三種頁面

| 類型 | 例子 | 捲動 | 寬度 |
|---|---|---|---|
| **工作區頁** | 專案的表格、看板、行事曆與時間軸 | 頁面剛好一個畫面高；內容區自己捲（表格兩個方向、看板每一欄各自直向、行事曆的月曆與時間軸在內容區裡自己捲，上方一列的月份與刻度不捲走） | 用滿，不設上限 |
| **清單頁** | 我的工作、專案總覽、收件匣、專案、人員、說明格式、變更集清單 | 整頁捲動；表頭黏在頁列下面（`TableScroll layout="page"`；表格比內容區寬時退回橫向捲動，那時表頭不黏） | 用滿，不設上限（和工作區頁一樣）；項目面板開著時面板貼著內容區右緣，清單用掉剩下的寬度 |
| **閱讀頁** | 項目頁、設定頁、變更集預覽、設定中心的表單頁（我的帳號、寄信設定…）、使用說明 | 整頁捲動 | 上限 `--content-max`、靠左；純文字一行 `--reading-max`（項目頁左欄的下層項目與活動也以它為限，右緣和說明對齊）。項目面板排成右邊一欄（80rem 以上）時內容區不設上限：面板貼著內容區右緣，閱讀的內容用掉面板以外的寬度，中間不留空（長段文字照樣以 `--reading-max` 為限） |

- **設定中心**〔2026-11-24，`features/settings-hub/`〕：個人的設定（我的帳號、通知、AI 帳號、命令列與整合）與組織的設定（說明格式、寄信設定、儲存空間、AI 設定、主機 AI 代理）共用一個外框：頁列是位置「設定」加頁名（h1），內容區 64rem 以上左邊一欄次導覽（11rem，在紙上、沒有自己的底色，黏在頁列下面）、右邊是這一頁的內容；64rem 以下次導覽換成工具列上的下拉。每一頁照自己的內容是閱讀頁（表單）或清單頁（說明格式的表格用滿寬度）。表單頁的內容是一塊塊 `SettingsSection`（第 7 節）：左欄標題與說明、右欄整塊，內容欄 46rem 以上左右、以下上下。規則見 8.3「設定中心」。**儲存空間**（`/storage-usage`，`features/storage-usage/`，閱讀頁，只有擁有者與管理員，2026-11-25）：附件用了多少、上限多少，只讀（上限在部署的設定 `Attachments:Quota:*`，網頁不能改）。幾塊 `SettingsSection`：組織的附件（「已用 1.2 GiB／20.0 GiB」加一條原生 `<progress>` 用量條，數字一定寫在旁邊；超過上限時填色換警告色、下面一則警告的 `Notice`，說新的上傳會被擋、下載與刪除照常）、項目的附件與知識庫的附件（各自的大小與檔案數）、每人每日的上傳量（上限；沒有上限寫「不限制」且不畫用量條）。沒有裝飾色條。
- **使用說明**〔2026-11-27，`features/help/`〕：給第一次用的人的手冊，一章一頁（`/help/:chapter`，`/help` 是第一章；網址的錨點連到一節，例如 `/help/quick-start#notifications`：捲過去、焦點放到那一節的標題，和 `SettingsSection` 共用 `lib/useRevealWhenTargeted.ts`）。版面照設定中心：頁列是位置「使用說明」加章名（h1），64rem 以上左邊是章節的次導覽（`SubNav`，依組列出，現在只有「開始使用」一組），以下換成工具列上的下拉。內容是 `features/help/chapters/` 裡寫好的元件、不是 Markdown：說明裡提到的頁面（「我的工作」「設定 → 通知」）是站內的連結，標題是頁面真正的結構（節是 h2、小節是 h3，每一節是有名稱的 `section`），一行以 `--reading-max` 為限；清單、表格、行內程式碼的長相照 Markdown（7.4），表格是有名稱、鍵盤捲得動的區塊。章裡寫的按鈕與頁面名稱要和畫面一致：改了畫面上的名稱或流程，同一個提交裡改說明。實測（2026-11-27，開發伺服器）：`contentStart` 寬螢幕 141、390 與 320 觸控模擬 216，都不橫向溢出。理由：Markdown 顯示元件刻意把標題壓在 h4 以下、不認站內的相對連結（內容是別人寫的），手冊是自己寫的內容，要的正好相反。
- **知識庫**〔2026-11-25，`features/knowledge/space/`，交接 `internal/HANDOFF-knowledge-base.md`〕的空間與頁面是閱讀頁：頁列是位置（知識庫 › 空間 › 上層們 › 這一頁，這一頁沒有連結；h1 在內容區，和項目頁一樣）加右邊的「垃圾桶」「空間設定」（有 `canManage` 才有）；內容區 64rem 以上分兩欄，左邊頁面樹（16rem，在紙上、沒有自己的底色，黏在頁列下面、自己捲）、右邊這一頁或空間首頁（一行以 `--reading-max` 為限）；64rem 以下只有內容，頁面樹換成工具列上的「頁面」按鈕（元件見 7.5）。空間首頁是空間名稱、簡介、最上層的頁面與最近更新的 10 頁。封存的空間（或它綁的專案封存了）頁面上方一則中性的提示「這個空間已經封存，只能看。」（不是錯誤，一開始就在，不唸出來），沒有任何寫入的按鈕。理由：兩欄與次導覽沿用設定中心的做法（64rem 的斷點、不要第三欄），讀文件的人要的是寬一點的樹加長文字的欄寬；頁面樹要一直看得到才知道自己在哪、才拖得動，所以不收進按鈕（只有窄螢幕才收）。
- 行事曆與時間軸也是工作區頁〔已有：PM-3b〕：和表格、看板用同一個 `PageLayout variant="workspace"` 與同一條工具列（版面分頁、檢視選單、篩選），差別只在內容區：上面一列放這個版面自己的控制（行事曆的月份、時間軸的刻度），下面是自己捲的內容。理由：月份與刻度是「看哪一段」，跟著內容走、換版面就沒有意義，放工具列會把篩選的位置擠掉；內容捲動時這一列不捲走，使用者不必捲回最上面才能換月。規則見 `docs/design/08-interaction.md` 的「版面的切換」「行事曆」「時間軸」。
- 工作區頁**一定**讓橫向捲軸留在畫面裡：表格有幾百列時，使用者不必捲到最底才能往右捲。
- 清單頁不設 `--content-max` 的上限〔已有：2026-11-17 版面寬度〕。理由：清單頁的內容是表格，側欄收起來或寬螢幕時設上限只會在右邊留一大塊空白（使用者回報：1900 寬、側欄收起、開著項目面板，清單加面板只到約 1640px）；表格比內容區寬時本來就自己捲。原本的上限是給「長段文字」的，長段文字由內容自己限在 `--reading-max`。
- 閱讀頁開著項目面板（80rem 以上）時，內容用掉面板以外的寬度、面板貼著右緣〔已有：2026-11-17〕；沒開面板時照舊以 `--content-max` 為限、靠左。不用原本的「上限加上面板的寬度」：面板可以拖拉調整寬度之後，有空間時加寬面板只會把面板的右緣往右推，把手不跟著指標走。也不把內容限在 `--content-max`、面板貼右緣：審查量到 1920 寬、側欄收起時內容與面板中間空了 281px。說明這類長段文字本來就以 `--reading-max` 為限，內容變寬不會讓一行太長。
- 閱讀頁可以在標題下面放一段說明（一到兩句），跟著內容捲走。清單頁不放說明：要說的話放在空白狀態裡。
- 還沒有內容可以顯示時（載入中、讀不到、找不到、沒有權限）照樣有頁列（`StatusPage`，第 7 節），外框不會等資料到了才出現；分頁標題和載入好之後的一樣（設定、變更集清單與預覽；專案與項目要讀到才知道名稱，先用代號與編號）；錯誤頁的 h1 是內容區的大標題。
- 每一頁在「第一筆內容」的元素上標 `data-content-start`（表格的第一列、看板的第一張卡片、項目頁的欄位面板…），給 `scripts/ui-audit.js` 量高度預算用。例外：看板每一欄的第一張卡片都標——欄各自載入，畫面不知道哪一欄先有卡片（第一欄可能是空的）；各欄的標題列一樣高，腳本取文件順序裡第一個，量到的高度一樣。其他頁只標一個，不隨版面換位置：版面用容器查詢排的頁面（項目頁），程式不知道現在排成哪一種，標在兩種排法裡都是第一筆的那一塊（第 14 節）。
- 對話框（`Dialog`）用在：要先填幾個欄位才能完成的動作、確認。**不要**用對話框顯示整個頁面的內容；一個對話框上面不再開對話框。對話框裡要多做一件需要填欄位的事時，在原地展開一塊表單（凹下去的底色、自己的標題，Esc 只收起這一塊）：例如成員對話框裡要加的人還不在組織時，「新增人員…」就地展開人員頁同一套欄位。對話框裡凹下去的就地展開區塊算另一個區，可以有自己的主要按鈕（第 7 節「一個區域最多一顆 primary」）：送出按鈕的名稱說出結果（「新增人員」），和對話框本身的主要動作（「加入」）分得開。

### 6.3 斷點

- `@media` 的寬度**一定**只用這三個值：`48rem`（以下是窄螢幕：抽屜、清單取代表格、單欄）、`64rem`、`80rem`。寫法一律是 `max-width: 48rem` 與 `min-width: 64rem`／`80rem`。
- 元件要隨「自己有多寬」變化時用容器查詢（項目頁的兩欄〔已有〕），數值不限。
- 要用程式判斷窄螢幕（換一種元件，不只是換樣式）時用 `lib/useMediaQuery.ts` 的 `useIsCompact()`〔已有〕，查詢字串和 CSS 同一個。沒有 `matchMedia` 的環境（測試）當成寬螢幕。
- **一定**在 320、390、768、1024、1440 這幾個寬度下整頁都不會橫向捲動；要橫向捲動的內容（表格、看板、轉換表格）放進自己的捲動容器。
- 手機的安全區域：黏在底部的列加 `padding-bottom: env(safe-area-inset-bottom)`。

## 9. 無障礙

目標是 WCAG 2.2 AA。專案裡**一定**要做到的：

- 每個可以操作的元素有無障礙名稱；同一頁有好幾個同名的動作時，名稱帶上對象（「把需求確認往上移」「AGY-3 移到…」）〔已有〕。
- **無障礙名稱與角色是合約**：測試用 `getByRole(…, { name })` 找元素。把看得到的文字換成圖示時，名稱要原封不動留在 `aria-label` 或隱藏文字裡；真的要改名稱，測試一起改，並在提交訊息說明。
- 焦點外框一律看得到（`:focus-visible`，2px `--color-focus`）；`outline: none` 只能出現在「用別的方式畫出焦點」的地方。表格裡自己停得到的格子（唯讀、不適用、表頭）外框畫在格子裡（`outline-offset: -2px`），不被隔壁的格子與固定欄蓋住。黏住的列不能蓋住取得焦點的元素（`scroll-padding`）。
- 焦點的兩種畫法〔已有：視覺翻新〕：按鈕、連結、格子用全域的 `:focus-visible`（2px `--color-focus`，間隔 2px）。**輸入框、多行文字框、`Select` 的按鈕**是外框換成 2px 的 `--color-focus`（1px 的外框加 `inset 0 0 0 1px` 同色的環線，和全域的焦點外框一樣粗），外面加一圈 `0 0 0 3px var(--color-focus-ring)` 的光暈，`outline` 設成 `2px solid transparent`——只有一圈，不再「外框加外框」；透明的 `outline` 在強制色彩模式下由系統畫出來（光暈會被拿掉）。有錯（`aria-invalid`）時外框一直是 `--color-danger`；取得焦點時外框維持危險色、裡面多一圈 1px `--color-focus` 的內環線（`inset 0 0 0 1px`），外面照樣是光暈——紅框加紫色內環加光暈。理由：只靠光暈的話，有錯的欄位取得焦點前後幾乎一樣（紅框只多一圈淡淡的光暈），看不出焦點在哪一個。不能選的選項、不能用的選單項目反白時不是實心的，所以也加一圈 2px 的焦點色（7.3）。編輯中的格子只有格子自己那一圈（8.3「就地編輯」），裡面的輸入框與下拉（`bare`）不再畫焦點。`Select` 與 `Menu` 的反白也是焦點的位置：實心的強調色底本身就看得出來，不另外畫外框（強制色彩時是 `Highlight`）。
- 不只靠顏色（第 4 節）；不只靠滑過才出現的東西——滑過才出現的按鈕，取得焦點時也要出現，觸控時一直顯示。
- **沒有裝飾用的色條**〔已有：視覺翻新〕：不用 `inset 3px 0 0 …`、`border-left: 3px …` 這類左邊（或上方）的色條表示選取、反白、提示或狀態。原本加色條的理由是「淡底和紙的對比太低，要有形狀上的差別」；換成這幾種之後不需要了：
  - 目前所在、已選取（側欄目前的頁面與專案、表格與清單選取的那一筆）：`--color-selected` 的底，字與圖示是 `--color-accent`；說出是哪一筆的是 `aria-current` 與面板的標題，不是顏色。`NavTabs` 目前的分頁是浮起來的紙（第 7 節）。
  - 反白（`Select`、`Menu` 的選項、快速跳轉的結果，同時只有一個）：實心的 `--color-accent-solid` 底加白字（對比 5.96／5.30）——實心的底本身就是很明顯的差別，鍵盤走到哪一個一眼看得出來。
  - 提示（`Notice`、格子與說明的錯誤、`TransitionProblem`）：語意的淡底、圖示與標題是語意的顏色，本身就有圖示與文字（第 7 節 `Notice`）。
  - 狀態（看板的欄）：標題列的 `StateBadge`（形狀、顏色、文字）。
  - 時間軸（活動）那條灰色的直線是結構（把一筆筆串起來），不是色條，可以留。
- 會自己變的內容用 live region：錯誤 `role="alert"`，其他 `role="status"` 或 `aria-live="polite"`；區域先掛著再填內容；一頁只有一個全域的 status。
- 表單：標籤看得到、錯誤連到欄位、`aria-invalid`、一組勾選用 `fieldset` 與 `legend`。
- 拖曳、滑動、長按都有不用手勢的替代操作（WCAG 2.5.7）。表格的欄寬：點兩下把手照內容調整、「重設欄寬」，鍵盤是表頭的 Shift+←／→ 與 Shift+Enter（7.1「欄寬」）。項目面板的寬度：點兩下把手（或焦點在把手上按 Enter）回到預設寬度；鍵盤是焦點在把手上的 ←／→（Shift 一次 64px）、Home／End（第 7 節 `SidePanel`）；要更大的地方看項目時用標題列的「展開成整頁」。不另外做「窄／預設／寬」的選單（2026-11-17 決定）：點兩下、鍵盤與整頁已經涵蓋不用拖的需要。
- 地標要包住它自己的東西：看板的區域（`role="region"`「看板」）與表格的區域「項目」都只包內容，篩選在頁面的工具列上，旁邊的項目面板不在裡面。
- 尊重 `prefers-reduced-motion`（全域樣式已經處理〔已有〕）；放大到 200%、寬度 320px 時內容不被切掉。
- 語言是 `zh-Hant-TW`〔已有〕；圖示與裝飾 `aria-hidden`。

## 10. 動態

- 只有兩個時間：`--duration-fast`（滑過、按下、顏色）與 `--duration-normal`（對話框、抽屜、選單出現）；曲線一律 `--ease-out`。離開比進入快或一樣快。例外各有一個變數：載入指示轉一圈 `--duration-spin`、看板的卡片剛移好時閃一下 `--duration-highlight`（要慢到看得出落在哪裡）、點通知後被標出來的那一筆留言（卡片外框與底色換成強調色，停一下再淡回，和卡片剛放下同一套）`--duration-target`（要停得夠久，看得到捲到了哪一筆；減少動態效果與強制色彩時不用動畫，見 8.3「收件匣」）、骨架明暗變化一次 `--duration-pulse`（慢到不搶眼，又看得出還在載入）。理由：前兩個原本是寫死在 CSS 裡的時間，樣式檢查擋下之後要有變數可用；四個都不該借用意思不同的變數（例如拿 `--duration-spin` 乘兩倍當骨架的節奏），各自一個，之後才調得動。
- 只動 `transform` 與 `opacity`（以及顏色）；不動 `width`、`height`、`top`、`left`、`margin`。
- 動態要有意思：出現的位置說明它從哪裡來（選單從按鈕長出來、抽屜從左邊滑進來、卡片滑到落點）。不做進場動畫、不做捲動觸發的動畫、不做無限循環（載入指示除外）。

## 13. 實作規則

- 樣式是 CSS Modules 加設計變數；不加 UI 元件庫、不加 CSS 框架。
- 字型〔已有：視覺翻新〕**一定**自帶、不從外部網域載入（不用 Google Fonts 這類 CDN：內容安全政策 `default-src 'self'` 不允許，也不想讓使用者的瀏覽器連到第三方）：字型檔從 npm 的 `@fontsource-variable/*` 安裝、在 `src/main.tsx` 匯入，由 Vite 打包成和網站同網域的檔案。授權**一定**允許隨另外賣商業授權的產品散布（現在的 Plus Jakarta Sans、Geist Mono 都是 OFL-1.1）。用可變字重的版本（一個檔案涵蓋所有字重），字重只用 `--weight-*`。中文不自帶（一套好幾 MB），落到系統的台灣字體（第 3 節）。要加新的字型先改第 3 節與本條。
- **內容安全政策是 `default-src 'self'`**：不寫行內的 `<style>`、`<script>`，不寫 HTML 的 `style` 屬性，不從外部網域載入任何東西。React 的 `style` 物件是用程式設樣式，政策允許，但只准用在「數值要執行時才算得出來」的地方：拖曳中的位移（dnd-kit 自己設）、浮層的座標（只在 `components/Floating/Floating.tsx`）、項目面板拖拉調整的寬度與最高要扣掉的高度（只在 `components/SidePanel/SidePanelLayout.tsx`：設 `--side-panel-current-width` 與 `--side-panel-block-offset` 兩個 CSS 變數，其餘由 CSS 照它們排）、表格使用者拉的欄寬（只在 `components/Table/Table.tsx`：`col` 的寬度，與捲動區塊上換掉表格自己區域變數的 CSS 變數）、時間軸上依日期排的東西（只在 `features/timeline/At.tsx`：設 `--col`、`--span`、`--days` 三個天數的 CSS 變數）、項目的浮動視窗拖拉調整的寬度（只在 `components/Dialog/ModalFrame.tsx`：外框上一個 `--floating-panel-width`，由 `FloatingPanel` 給）、專案總覽的狀態分段橫條（只在 `features/overview/StateBar.tsx`：每一段上一個 `--count`，是那個狀態的項目數，段的長度照比例分）。其他一律用 class。理由（狀態分段橫條，2026-11-26）：一段的長度是項目數佔全部的比例，數字是執行時才有的，class 表達不了（用 `<progress>` 只能畫一段，這裡要一個狀態一段、每段可以點）；只設變數，顏色、縫、最小寬度與換算（`flex-grow` 照它）仍寫在 `StateBar.module.css`。理由（面板，2026-11-17）：寬度是使用者拉出來的，又要夾在執行時才量得到的範圍裡（清單那一塊有多寬）；最高要扣掉的高度跟著頁面捲到哪裡變；class 都表達不了。只設變數，長相與規則仍然寫在 CSS。理由（欄寬，2026-11-17）：寬度是使用者拉出來的，欄又是照藍圖動態產生的（自訂欄位），class 表達不了；固定欄與我的工作的欄只換一個變數，長相與規則仍然寫在 CSS，`style` 只出現在 `Table.tsx` 一個檔案。理由（時間軸，PM-3b）：條的位置與寬度是項目的日期換算出來的天數，一個畫面幾十到上千個，class 表達不了；長相與一天多寬（週 2rem、月 0.5rem）仍寫在 CSS。
- class 名稱用 camelCase（CSS Modules）；狀態用屬性選取（`[aria-busy='true']`、`[aria-current='page']`、`[data-open='true']`），不要另外加一個 `isActive` 的 class 重複表達同一件事。
- 元件不寫死顏色與尺寸（第 2.2 節）；`!important` 只准出現在 `global.css`。
- 〔已有〕功能的程式裡不寫 `<select>`、`<option>`，一律用 `components/Select`（7.3）；樣式檢查腳本會擋，允許清單是空的。
- 浮層（`Menu`、`Popover`，以及〔已有：自訂控制項〕`Select` 的清單：`matchAnchorWidth` 讓清單至少和按鈕一樣寬，寬度要執行時才量得到，所以由 `Floating` 設；`keepsAnchorFocus` 讓在浮層上按下滑鼠不改變焦點；`onPositioned` 在座標與 `maxHeight` 套上之後通知，清單在這時把反白的選項捲到看得到）**一律**經過 `components/Floating`：元素留在觸發它的元件旁邊的 DOM 裡，用 `popover="manual"` 放進瀏覽器的 top layer，`position: fixed` 加程式算的座標（`lib/useAnchoredPosition.ts`）。放在會裁切的捲動容器裡不會被切掉，也不受祖先的 `transform`、`container-type` 影響。理由（原本寫的是「渲染到 `document.body`」）：留在原本的 DOM 位置，Tab 的順序自然接在按鈕後面、「點在裡面」與事件往上傳不必特別處理，既有的測試（例如在卡片裡找「移到…」的選單）也不必改；top layer 達到渲染到 `body` 想要的「不被裁掉」，而且比 `body` 加 `position: fixed` 更不怕祖先的 `transform`。沒有 `showPopover` 的環境（jsdom）退回一般的 `position: fixed` 加 `--z-popover`。
- 圖示只從 `components/Icon` 拿；要新的圖示就加進那個檔案的對照表。
- 網頁的例外回報到伺服器〔已有：帳號安全那一輪，`lib/errorReporting.ts`〕：`main.tsx` 一開始就在 `window` 上聽 `error` 與 `unhandledrejection`，路由的錯誤頁（`RouteErrorPage`）也回報（`kind: "render"`；被錯誤頁接住的例外不會再傳到 `window`）。`POST /v1/client-errors`，用 `fetch` 加 `keepalive`。規則：`ApiError` 不回報（4xx 是預期中的結果）；同一個訊息一次載入只送一次、一次載入最多 20 筆；`message` 截到 1000 字、`stack` 截到 4000 字，`path` 只用 `location.pathname`（查詢字串裡可能有搜尋的字）；回應是什麼（401、429、網路失敗）都靜靜放掉，回報本身絕不丟例外。功能的程式不必自己呼叫它：沒接住的例外自然會被送出去；要看就到伺服器的記錄（`scripts/ops/errors.sh`）。
- 測試：新的共用元件先寫測試（鍵盤、焦點、無障礙名稱）；用角色與名稱找元素，不用 class 或 `querySelector`。
- 自動檢查〔已有〕：`npm run lint` 會跑 `web/scripts/check-styles.mjs`，擋下：
  - 變數檔以外的顏色（包含 `var()` 的備用值；`url(#…)` 不算）。
  - 沒用變數的字級（只接受單一的 `var(--text-*)` 與 `inherit` 這類關鍵字，不接受 `calc`、備用值、百分比）、圓角、層級、動畫時間（包含負的延遲）。
  - 有模糊的陰影（`box-shadow`、`text-shadow` 的第三個長度不是 0）沒用 `--shadow-*`；沒有模糊的環線（`inset 0 0 0 2px var(--color-focus)`）可以直接寫，顏色要用變數。
  - 清單以外的斷點、`device-width`、範圍的寫法；`global.css` 以外的 `!important`（中間有空白也算；減少動態的那一段寫死的時間也只准在 `global.css`）。
  - 允許清單以外的 `style` 屬性、`element.style.x =`、`style.setProperty`、`cssText`，以及一律不行的 `setAttribute('style', …)`；程式裡的字串與註解不算。HTML 裡行內的 `<script>`、`<style>` 與 `style` 屬性。
  - 〔已有：自訂控制項 P2〕`src/` 的元件（`.tsx`，測試與 `src/test/` 除外）裡的 `<select`、`<option` 標籤：允許清單是空的；字串與註解裡的不算，`role="option"` 的 `li` 也不算。
  - 〔已有：2026-11-24〕元件用到、樣式檔裡卻沒有定義的 class（`import styles from './A.module.css'` 之後的 `styles.x`，`A.module.css` 的選取器裡沒有 `.x`）；註解與字串裡的不算，動態的 `styles[x]` 看不出名稱、不檢查。理由：CSS Modules 拿不存在的名稱只會得到 `undefined`，不報錯、型別也過，畫面默默少一段樣式；2026-11-23 改提示的位置時誤刪了 `NotificationToasts.module.css` 的 `.toast` 等樣式，新通知的提示變成沒有底色的文字疊在頁面上，所有測試都沒抓到。
  - 同一個檔案裡的區域變數（`--x: …`）展開成它的值再檢查，寫死的尺寸不能只是換個名字藏起來；同一個名字在好幾條規則裡有不同的值時，每一種都要通過。允許清單寫在那支腳本最上面。
