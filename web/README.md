# pm-tool-web

專案管理工具的網頁版。React 19、TypeScript（strict）、Vite；路由用 React Router，伺服器資料用 TanStack Query。樣式是 CSS Modules 加上 `src/styles/tokens.css` 的設計變數，沒有 UI 元件庫；圖示用 `lucide-react`（只在 `components/Icon` 匯入）。畫面照 [`docs/DESIGN.md`](../docs/DESIGN.md) 的設計規範做（規範分成五份、節號共用：設計變數、元件、控制項、流程與互動在 [`docs/design/`](../docs/design/)，對照表在它的第 0 節）。方向是「明亮的工作室」（規範第 1 節，視覺翻新）：紫藍的強調色（大片的實心底用 `--color-accent-solid`）、帶一點紫藍的中性色、圓一點的角（`--radius-sm`～`--radius-xl`）與柔和帶色相的陰影；拉丁字母與數字用自帶的 Plus Jakarta Sans、編號與代號的等寬字用自帶的 Geist Mono（`@fontsource-variable/*`，`main.tsx` 匯入、由 Vite 打包、和網站同網域，OFL-1.1），中文是系統的台灣字體。選取、反白、提示、狀態都不畫左邊或上方的色條：選取是 `--color-selected` 的底加強調色的字，反白是實心的強調色，提示與還沒送出的修改是淡底加文字。

## 開發

```sh
npm install
npm run dev            # http://localhost:5173，/v1 與 /health 代理到 http://localhost:8080
npm run typecheck
npm run lint           # 警告也算失敗；函式 50 行、檔案 400 行、巢狀 4 層由 ESLint 檢查；接著跑樣式檢查（scripts/check-styles.mjs）
npm test               # 跑一次就結束
npm run test:coverage  # 行覆蓋率低於 80% 會失敗
npm run build          # 先型別檢查，再輸出到 dist/
node scripts/check-styles.mjs  # 只跑樣式檢查
```

開發伺服器有一頁 `/design`（不必登入、不打 API）：每個共用元件的每種狀態各一個，右上角可以切換主題。只在開發模式有，正式建置裡沒有。

正式環境由 API 主機提供 `dist/` 裡的檔案，網頁與 API 同一個來源，所以 API 一律用相對路徑。內容安全政策是 `default-src 'self'`：不要加行內的 `<script>`、`<style>` 或 `style` 屬性，不要從外部網域載入字型、圖片或腳本。

## 外框與每一頁的骨架

`features/shell/`，照規範 6.1 節。

- **外框**（`AppShell.tsx`）：側欄是桌面（`--color-sidebar`），內容區是紙（`--color-surface`），外框自己不加內距，每一頁用 `PageLayout` 排頁列、工具列與內容。頁列左上角疊著外框的按鈕（`BarStart`）：寬螢幕是收合側欄的「側欄」，窄螢幕（48rem 以下）是打開抽屜的「選單」，兩顆都用 `aria-expanded` 說開著沒有，名稱固定。兩顆都在 DOM 裡、CSS 依寬度只顯示一顆（測試環境沒有 CSS，兩顆都找得到）；放在外框而不是頁列裡，沒有頁列的畫面（程式出錯的 `RouteErrorPage`）也按得到。頁列的開頭讓出這顆按鈕的寬度：外框設 `--page-bar-inset`，`PageBar` 的左內距加上它（沒有外框時是 0；不在內容區左上角的頁列要把它設回 0）。這兩顆按鈕不在任何地標裡（`<main>` 是「跳到主要內容」的目標），視同頁列的一部分（規範 6.1）。窄螢幕原本的頂端列拿掉了，產品名稱只在抽屜裡。
- **收起側欄**（`sidebarPreference.ts`）：記在 `localStorage` 的 `shell.sidebar`（收起來是 `collapsed`，展開就拿掉），讀寫失敗當成展開。收起來時側欄是 `hidden`（不在 Tab 順序與無障礙樹裡），內容用滿整個寬度，焦點留在按鈕上。只在寬螢幕有效（`useIsCompact()`）：窄螢幕的側欄一律是抽屜，記著收起來也照樣打得開。
- **抽屜**（`useDrawer.ts`）：「選單」打開時焦點到第一個導覽連結，Esc 關上並回到「選單」，點背景或換頁就關上。開著時視窗從窄變寬也關上（看的是「變寬的那一下」：沒有 `matchMedia` 的測試環境一律當成寬螢幕，抽屜照樣打得開），再變窄不會自己跳出來。
- **側欄**（`Sidebar.tsx`）：產品名稱 Kumi（`config/product.ts`；前面一個 24px 的標誌，就是瀏覽器分頁的圖示 `public/favicon.svg`：裝飾、`alt=""`、`aria-hidden`，連結的名稱只有產品名稱；高解析的原稿在 `docs/brand/kumi-icon-512.svg`）、主要導覽（我的工作、收件匣、專案、人員、設定，各有圖示，名稱只有文字；「設定」連到設定中心 `/account`，在設定中心任一頁與說明格式的編輯頁都是目前所在，見「設定中心」）、專案清單接在「專案」底下（專案連結照這個專案上次用的檢視開，見「專案頁與表格檢視」的記住檢視）。整條剛好一個畫面高，專案多了只有專案清單自己捲，「人員」與帳號選單一直看得到；捲動的容器四邊留出焦點外框的寬度（再用負的外距抵銷），專案連結的外框不會被裁掉。目前所在的那一項照 `NavLink` 標的 `aria-current` 上色：`--color-selected` 的底、字與圖示是強調色、semibold，沒有左邊的色條（規範 6.1）。
- **快速跳轉**（`features/jump/`，規範 8.3）：`AppShell` 包一層 `JumpProvider`，⌘K／Ctrl+K（`SHORTCUTS.openJump`）與側欄最上面的「搜尋或跳到…」（`JumpButton`：名稱只有這句，看得到的快捷鍵寫法 `aria-hidden`、觸控時不顯示，報讀軟體看 `aria-keyshortcuts`）打開 `JumpDialog`（標題「搜尋或跳到」，不帶省略號）。窄螢幕的抽屜開著時打開（按鈕或 ⌘K），外框先收起抽屜、焦點交給「選單」（`JumpProvider` 的 `onOpen`），對話框不疊在抽屜上，關上後焦點回到「選單」。別的強制回應對話框開著時 ⌘K 不作用（`useIsModalDialogOpen` 看 `body` 底下有沒有 `aria-modal` 的對話框）；自己開著時再按一次照樣收下，焦點留在輸入框。對話框裡是 combobox（`TextField` 的 `role="combobox"` 加 `leadingIcon="search"`，名稱和對話框的標題同一句；`aria-expanded`、`aria-controls`、`aria-autocomplete="list"`、`aria-activedescendant`）加 `JumpResults` 的 `listbox`：焦點一直在輸入框，按在選項上不會搶走焦點；↑／↓ 選（繞回另一端，記的是選項的 key，搜尋結果晚到時選起來的那一個不變）、Enter 前往、Esc 關上；輸入法選字中的 Enter、方向鍵、Esc 都交給輸入法（`isComposingKey`，Esc 不往外傳給 Dialog）。分組與比對是純邏輯（`jumpGroups.ts`：編號、最近看過、專案（最多 8 個，照上次用的檢視開，`projectPageLink`）、頁面、這個專案的項目，同一個項目只出現一次；`jumpPages.ts`：頁面照權限，網址在哪個專案底下）。最近看過的項目在 `recentItems.ts`（`localStorage` 的 `jump.recentItems`，最多 8 個，讀寫失敗當成沒有；項目頁與面板呼叫 `recordRecentItem`；登出與工作階段失效時 `auth/session.ts` 的 `markSignedOut` 呼叫 `clearRecentItems` 清掉，記錄帶著標題，共用電腦上下一個人不能看到）。這個專案的搜尋是 `useItemSearch.ts`（`useProjectItems` 加 `q` 與 `limit: 8`，停 300ms 才送；換字之後舊的結果不留著）。下面一行 `role="status"` 說「找到 N 筆」「正在搜尋這個專案的項目…」「這個專案沒有符合的項目。」：打字中不換，停下來（`useItemSearch` 的 `isSettled`，和送出搜尋同一個 300ms）才換，不和字元的回音搶著唸；搜尋失敗是危險的 `Notice`。分組的標題和表頭一樣（`--text-xs`、semibold、灰字），選起來的那一個是反白（和 `Select`、`Menu` 一樣：實心的 `--color-accent-solid` 底、白字，圖示與編號跟著字色，不畫色條），強制色彩下改用 `Highlight`／`HighlightText`。選了一頁先關上再換頁，`headingFocus.ts` 等新頁面的 h1 出現就把焦點放上去並捲回最上面（沒有 `tabIndex` 的補 -1；等的期間使用者按鍵或點擊就不搶，10 秒後放棄）；選「成員」關上之後在原地開 `MembersDialog`。沒換頁就關上時焦點回到打開它的元素（`Dialog` 自己做；側欄的按鈕在點的時候先拿到焦點，Safari 才回得來）。
- **帳號選單**（`AccountMenu.tsx`，共用的 `Menu`）：最下面的按鈕是頭像、名稱與「組織 · 組織角色」（無障礙名稱「範例使用者（範例組織 · 擁有者）」），打開是「我的帳號」（到 `/account`，見「我的帳號」）、主題三選一（「主題跟著系統」「淺色主題」「深色主題」，目前的那一個後面寫「（使用中）」）與「登出」，組與組之間一條分隔線。登出送出中，按鈕上「組織 · 角色」那一行換成「登出中…」（名稱跟著變成「範例使用者（登出中…）」）、按鈕標 `aria-disabled`、選單打不開；失敗時「登出失敗：…」用 `role="alert"` 留在按鈕下面，畫面不動。登出成功時（和任何請求收到 401 一樣，都經過 `auth/session.ts` 的 `markSignedOut`）`sessionStorage` 裡的 `draft.*`（留言與說明的草稿，`lib/draftStorage.ts` 的 `clearAllDrafts`）全部清掉：共用電腦上下一個人看不到；登出失敗時草稿留著。
- **主題**：選了就記在 `localStorage` 的 `shell.theme`、套到 `<html data-theme>`（`lib/theme.ts` 的 `useThemeChoice`），跟著系統就拿掉。載入時由 `public/theme-init.js` 在畫面出現之前先設好（`index.html` 的 `<head>` 用一般的 `<script src>`，不是 module，比應用程式先執行；內容安全政策不允許行內腳本），不會先閃一下另一個主題。鍵名與可選的值和 `lib/theme.ts` 一致，`lib/themeInit.test.ts` 用同一個常數執行這支腳本檢查。
- **每一頁的骨架**：一律是 `PageLayout` 加 `PageBar`。清單頁（我的工作、專案、人員、變更集清單，`list`）、專案頁（表格與看板都是工作區 `workspace`）與設定頁的 h1 在頁列上；項目頁與變更集預覽的 h1 在內容區（頁列是位置；項目頁右邊還有「更多動作」）。閱讀頁（項目頁、設定頁、變更集預覽，`reading`）的說明放在標題下面、跟著內容捲走，頁列不放說明。清單頁原本的說明文字拿掉了。還沒有內容可以顯示時（載入中、讀不到、找不到、沒有權限，以及設定與變更集的檔案還在下載）用 `components/StatusPage`：照樣有頁列（只有分頁的標題，沒有 h1），h1 交給內容（錯誤頁的大標題）。分頁標題和載入好之後的一樣：設定頁是「設定」（載入好之後帶上區塊「設定 · 流程」，`PageBar` 的 `documentTitle`）、變更集清單是「變更集」、預覽是「變更集 #N」（檔案下載中也是）；專案頁與項目頁要讀到才知道名稱，先用代號與編號。
- **焦點到標題時捲回最上面**（`lib/pageTop.ts` 的 `focusPageHeading`、`scrollToPageTop`）：標題在黏住的頁列上，焦點過去瀏覽器不會捲動。換頁後帶著提示到達（`useArrivalNotice`）、設定頁的「捨棄修改」「以最新版本重新開始」、變更集預覽的放棄與「知道了」之後，焦點到標題、畫面捲回最上面。背景重抓失敗的提示放在內容的最上面（頁面元件收 `notice`／`notices`），出現或消失都不會讓頁面重新掛載。
- **沒有外框的頁面**：登入頁（`auth/LoginPage.tsx`）與在外框外面出錯的 `RouteErrorPage` 直接放在桌面（`--color-canvas`，`body` 的底色）上；登入表單是置中的一張紙（`--color-surface`、細線、`--radius-lg`，不加陰影：陰影只給浮起來的東西），確認登入狀態時的「正在確認登入狀態…」也在同一個置中的版面裡。找不到、沒有權限的頁面（`features/errors/NotFoundPage.tsx`）在外框裡，照 `StatusPage` 走。
- **窄螢幕的清單**（48rem 以下，`useIsCompact()`，規範 7.1）：專案的項目、我的工作、專案清單、人員、成員對話框、變更集清單都不用橫向捲動的表格，換成同一個 `components/List`（換元件，不是把表格擠小；長相與 API 見「共用元件」）。清單的名稱和寬螢幕的表格一樣（「項目」「我的工作」「專案」「人員」「成員」「變更集」），第一筆標 `data-content-start`。能點進去的（項目、我的工作、專案、變更集）整筆是一個連結，名稱是這一筆所有的文字：編號、標題，再接第二行，所以第二行的欄位都帶只給報讀軟體的說法——項目是「狀態：」「負責人：」「到期：」（沒有負責人時只唸「沒有負責人」），我的工作是「狀態：」「專案：」「優先度：」「到期：」（優先度、到期日有設才有），變更集是「狀態：」「提出的人：」「提出時間：」，專案是右邊的「我的角色：」。人員與成員是靜態的一筆（頭像、名稱與「你」；人員的第二行是 Email、右邊是組織角色，「組織角色：」只給報讀軟體；成員的第二行是角色選單或角色、右邊是「移除」）。測試環境沒有 `matchMedia`，既有的測試看到的照樣是表格；窄螢幕的測試在 `CompactList.test.tsx`、`ProjectItemList.test.tsx`、`MyWorkCompact.test.tsx`、`MyWorkList.test.tsx`、`ProjectListCompact.test.tsx`、`PeopleList.test.tsx`、`MemberList.test.tsx`、`ChangeSetCompactList.test.tsx`。
- **高度預算的記號**：每一頁「第一筆內容」標 `data-content-start`，給 `scripts/ui-audit.js` 量：表格的第一列（我的工作、專案、人員、變更集清單、專案的表格；窄螢幕是清單的第一筆）、看板每一欄的第一張卡片（規範 6.2 的例外：欄各自載入，不知道哪一欄先有卡片；各欄的標題列一樣高，腳本取文件順序裡的第一個）、項目頁的欄位面板（寬螢幕和說明同一列、窄螢幕在最上面）、設定頁目前的那個區塊、變更集預覽的三格摘要。

## API 用戶端

- 型別在 `src/api/types.ts`（第 5 節的資料形狀，加上 `internal/HANDOFF-week2-item-page-activity.md` 3.3 節的活動與留言）與 `src/api/blueprint.ts`（藍圖文件）。

- **記住檢視**（`features/projects/projectViewPreference.ts`）：每個專案上次用的是表格還是看板記在 `localStorage` 的 `project.view.<專案代號>`（看板是 `board`，表格就拿掉；讀寫失敗當成表格），在 `ProjectWorkspace` 照網址的 `view` 記下。側欄的專案連結與項目頁麵包屑的專案連結照它開（`useProjectPageLink`，記下新的檢視時跟著換）；網址有 `view` 時以網址為準。只記檢視，不記條件。
- **顯示哪些欄**：`columnVisibility.ts`，存在 `localStorage` 的 `item-table.columns.<專案代號>`；讀寫失敗或內容壞掉都當成沒有設定。
- **欄寬**（規範 7.1「欄寬」；`ItemTable.tsx`、`itemColumnWidths.ts`，共用的部分見「共用元件」的欄寬）：表格是 `table-layout: fixed`，每一欄是預設寬度或使用者拉的寬度，不隨內容變寬。編號與標題以外沒拉過的欄，第一次有資料時照內容量一次（`ItemColumns` 的 `useMeasuredWidths`，`measuredColumnsOf`），不存；載入更多、重抓不重新量，換了顯示的欄位、換專案（`useItemTableState` 換一個 store）、「重設欄寬」才重新量。表格只在有資料時才掛上，重新掛上（表格與看板切換、篩到 0 筆再回來、寬窄切換）時 `useMeasuredWidths` 的 `useLayoutEffect` 會再跑一次：照當下的內容重新量（拉過的欄不受影響）。沒調過欄寬時和這一輪之前的表格幾乎一樣寬（1440：DEMO 1753→1757px、AGY 1555→1556px）。量不到（測試）時用 `columns.tsx` 的 `meta.width`（`short` 5rem、`name` 7rem、`date` 7rem、`due` 10.5rem、`text` 12rem，`ItemTable.module.css` 最上面的區域變數）。值放不下時一行、用省略號（`cells/Cells.module.css`：只有文字的按鈕換成 `display: block`、行高一列；一個元素的值跟著縮；到期日的日期先縮、「已過期」留著；勾選欄位的標籤不縮），完整的值在按鈕的名稱；裁的是按鈕，不是格子，浮起來的編輯器照樣長得出格子。每一欄（包含編號與標題）的表頭右緣是把手：拖曳、點兩下照內容調整、焦點在表頭時 Shift+←／→（1rem）與 Shift+Enter。範圍：一般的欄 3～40rem（照內容量的預設最寬 17.5rem），編號 3～16rem，標題 6～32rem；拉過的標題欄另外夾在表格寬度（容器 `item-table` 的 `100cqi`）減掉編號欄與 `--item-scroll-reserve`（8rem）之內，開了面板表格變窄時固定欄不會蓋滿畫面。編號與標題拉過的寬度換掉捲動區塊上的 `--item-key-width`、`--item-title-width`（`pinnedVariables`），其他欄寫在 `col` 上（`tableColumnOf`）；最後一個空的欄吃掉剩下的寬度（比容器窄時最後留白，比容器寬時橫向捲動）。記在 `localStorage` 的 `item-table.widths.<專案代號>`（`useItemTableState` 建 `createColumnWidthStore`），「顯示的欄位」的浮層最下面有「重設欄寬」（回到預設；按了不會不見，焦點留在它身上）。拖曳中只有表頭、`colgroup`（`ItemColumns`）與捲動區塊（`ItemTableScroll`）重畫，表身不動。表頭的固定欄在表頭那一層裡比把手高（編號 3、標題 2、把手 1）：橫向捲過去的欄的把手在固定欄底下。沒有用 TanStack Table v9 的 `columnSizingFeature`／`columnResizingFeature`：它的把手接的是 mouse／touch 事件（不是 pointer events 加 `setPointerCapture`）、寬度是 px 的數字（預設 150），也沒有照內容量寬度；我們的預設寬度是 rem、標題欄跟著容器查詢換，用它只剩一份 `Record<string, number>`，所以自己做。測試在 `ColumnWidths.test.tsx`。
- **篩選與排序**：`domain/itemFilters.ts` 在網址查詢字串和 `ItemQuery` 之間轉換（`type`、`state`、`assignee`、`q`、`sort`）。不認得的排序直接略過。沒有排序時依編號遞增（和後端預設一樣）。一頁 50 個，往下用游標載入（`useProjectItems`，`useInfiniteQuery`）。換條件時先留著舊的結果（表格變淡，`aria-busy`）。各頁接起來時以編號去重（`itemCache.ts` 的 `flattenItemPages`，留最後出現的那一個）：快速新增先放進清單的項目，之後載入的頁又帶到它時只出現一次。
- **權限**：`ProjectTableContext.tsx` 的 `abilitiesOf(detail)`：`item.create` 才有快速新增，`item.update` 才能改欄位，`item.transition` 才能改狀態。格子、成員對話框都從 Context 拿專案內容，不必經過每一層欄位定義。

### 格內編輯

- **長相**（`cells/Cells.module.css`）：每一格至少 `--row-height`（觸控時 44px）。可以改的格子滑過時出現 `--color-control-border` 的外框（唯讀的沒有反應）；編輯器（輸入框、下拉）是 `--control-height-sm`，上下的留白補到剛好一列高（觸控時兩個都是 44px）。編輯中的格子只有一圈框（視覺翻新）：編輯器是疊在格子上面的一層（`cells/EditorFrame.tsx`），畫 2px 的焦點色框，裡面的輸入框沒有外框、下拉是 `Select` 的 `bare`；原本的按鈕留在原位撐住格子，欄寬與列高不變，需要更寬時（日期、長文字、錯誤說明）那一層往旁邊長、不撐出橫向捲軸。細節見規範 8.3「就地編輯」。勾選欄位的點擊範圍是包住勾選框的標籤、連結欄位的「開啟」，都至少 `--target-min`。
- `cells/EditableCell.tsx` 是每一格的共同行為：平常是一個按鈕（`aria-label` 是「欄位：值」），Enter 或點一下進入編輯（表格裡 F2 也是，見上面的「鍵盤」）；輸入框類的 Enter 或離開格子儲存、Esc 取消（下拉是選了就存，見下面的「下拉選單」）；用鍵盤結束時焦點回到這一格。編輯器外面的 `data-cell-editor` 讓表格的方向鍵不碰編輯中的按鍵與 `tabIndex`；編輯中按 Tab 是離開格子（儲存）、離開表格。沒改就不送；前端看得出來的錯（標題空白、數字打錯）不送出，直接說明。失敗時編輯器留著使用者輸入的值，後端訊息（有對到這一格的 `details` 就用細項）顯示在格子裡，編輯器用 `aria-describedby` 指向它。剛失敗的同一個值，焦點離開時不重送，要再按 Enter（下拉是打開清單再選一次：清單關著時的 Enter 是打開）。
- 送出用 `cells/useItemCommand.ts`：一般欄位 `PATCH`（只送改的那一個屬性；清掉是 `null`，自訂欄位放在 `fields`），狀態走 `POST …/transitions`。成功後用回傳的項目換掉快取裡的那一個（`itemCache.ts`），不重抓清單；只有清單還有下一頁、而且條件或排序看的欄位變了（例如篩選狀態時改了狀態、照標題排時改了標題，`listConditions.ts` 的 `touchesConditions`）時，那一份清單在原位換掉之後再重抓：後端的游標是位移量，已載入的範圍少一個或換了位置，「載入更多」就會漏掉，所以這時那一列可能在重抓後離開清單。重抓中「載入更多」先停用（手上的游標可能對不上）。同時寫進項目頁用的單一項目、讓它的活動重抓；下層項目的清單裡上層換掉的就拿掉；我的工作與上層項目的選項只標成過期。表格與項目頁都走這一條，兩邊看到的永遠是同一份。
- 輸入法選字用的 Enter 不算數：`lib/keyboard.ts` 的 `isComposingKey`（`isComposing`，或 Safari 在 `compositionend` 之後才送出、`keyCode` 是 229 的 Enter）。格內編輯、標題、說明、留言都用 `isCommitEnter`；`TextField` 擋下選字 Enter 的預設動作，快速新增與對話框的表單不會被提早送出。
- 每種型別的編輯器在 `cells/editors.tsx`、`CoreCells.tsx`、`FieldCells.tsx`：文字、連結是輸入框；日期是自己畫的日曆（`cells/DateEditor.tsx`，`components/DatePicker` 的 `bare`：用滑鼠點開時直接打開日曆，從日曆選了就存，打字照舊 Enter 或離開才存；規範 7.3「日期」）；數字與金額用文字框加 `inputMode="decimal"`（接受千分位，打錯字會說明，不會被當成清掉）；長文字是 textarea（Enter 換行、Ctrl+Enter 或 ⌘+Enter 儲存）；單選、人員、負責人、優先度、上層項目、狀態是下拉選單；多選是一組勾選框（Enter 或「完成」儲存）；勾選不進編輯，勾了就存（取消勾選送 `null`）。
- 下拉選單（`editors.tsx` 的 `SelectEditor`，`components/Select`，規範 7.3）：進入編輯時清單直接打開，反白在目前的值。選了（點選、Enter、空白鍵）就儲存並結束編輯，焦點回到格子；選了目前的值也結束、不送出。方向鍵與打字只移動清單裡的反白（表格的格子不跟著動），不分滑鼠與鍵盤。Esc 一次就關上清單並取消編輯；再按一次下拉也是取消、焦點回到格子；按鈕被捲出畫面（`scrolled`）也是取消、焦點回到格子（項目頁與面板沒有表格幫忙找回停駐點）；點在外面、Tab 是關上、不改、結束編輯（Tab 照常離開表格）。送出中（`aria-busy`）打得開、選了不收。選項 10 個以上（負責人、人員欄位、上層項目）時進入編輯焦點在篩選框，格子的語意照舊（`SelectFilterEditing.test.tsx`）。
- 改狀態（`cells/StateCell.tsx`）：選單只列從目前狀態走得到的（`domain/workflow.ts`；流程沒有 `transitions` 這個屬性時其他狀態都可以；和後端一樣，空陣列是一條路都沒有）。被擋下時：`item.transition_role_required` 列出需要的角色（用藍圖的名稱，從轉換的 `allowedRoles` 來）與我現在的角色，有 `project.manage` 的人有「到『成員』調整角色」；`item.transition_not_allowed` 顯示後端的說明。這些說明在 `cells/TransitionProblem.tsx`，表格、項目頁、看板共用。`item.transition_fields_required` 見下一點（補填）；不能改欄位的人（沒有 `item.update`）、有欄位對不到編輯器（藍圖剛改過）、已經有別的對話框開著時照舊列出要先填的欄位名稱，沒有 `item.update` 的再加一句「你不能修改這個項目的欄位，請有權限修改項目的人先填好。」。
- **補填再前進**（規範 8.3；`cells/FillFieldsDialog.tsx`、`useFillSubmit.ts`、`fillFields.tsx`、`fillPlan.ts`）：改狀態收到 `item.transition_fields_required` 時，格子結束編輯（焦點回到狀態格）、原地開對話框「移到「結案」之前要先填」，只列回應 `details` 裡缺的欄位（後端的 path：核心欄位 `assignee`、`priority`、`start_date`、`due_date`、`estimate`、`parent`、`description`，或自訂欄位的鍵），規則以後端為準，前端不另外猜。每個欄位是表格的那個編輯器：每個欄位的編輯方式寫成 `FieldEditSpec`（`EditableCell.tsx`；`CoreCells.tsx` 的 `assigneeSpec`…、`FieldCells.tsx` 的 `textFieldSpec`、`multiSelectFieldSpec`、`checkboxFieldSpec`），格子與對話框用同一份；編輯器的 `placement: 'dialog'` 不自己搶焦點、不自己打開下拉，下拉選了不馬上存、關著時的 Esc 交給對話框（開著時 Esc 只關清單）（說明沒有格子，用長文字的編輯器）。欄位的外框是 `components/Field` 的 `FieldShell`（看得到的標籤、錯誤用 `aria-describedby` 連過去），輸入框、下拉、長文字的長相是 `fieldControlClassName`（和 `TextField`／`SelectField` 一樣）；多選是一組勾選（`choiceEditors.tsx`），看得到的 `legend` 就是標籤、選項是 `CheckboxField`，勾選欄位也是 `CheckboxField`（`FieldEditSpec.hasOwnLabel`，外框不再畫 label）。送出中編輯器不收新的值（輸入框 `readOnly`，勾選標 `aria-readonly` 並忽略改變，下拉標 `aria-busy`、選了不收）。「填好並移到「結案」」（或在欄位裡按 Enter；下拉上的 Enter 是打開清單、不是送出；長文字的 Enter 是換行，要 Ctrl+Enter（Mac 是 ⌘+Enter），提示連到文字框；輸入法選字的 Enter 不算）：還沒填、填錯的先說明（焦點到第一個有問題的欄位，多選是它的第一個勾選框；不送出）；有修改的合成一個 `PATCH`，成功才送改狀態。兩個請求不是一次完成的：`PATCH` 失敗留在對話框、輸入留著、錯誤照 `EditableCell` 的對應（有對到欄位的細項放在那個欄位，其他的在上方）；欄位存好了但改狀態又被擋下時，上方的 `role="alert"` 說「欄位已經存好，但還沒有移到「…」。」加上原因（`TransitionProblem`），再按一次只重送改狀態（存過、沒再改的不重送）；又是缺欄位就換成新的清單：以後端為準當成空的（`fillPlan.ts` 的 `clearedFields`：比對的基準清空、從「已經存好」拿掉、欄位重新掛上），不說「只會重送改狀態」，焦點到新清單的第一個欄位。送出中主要按鈕是「送出中…」並標 `aria-disabled`（`DialogFormActions` 的 `keepsFocusWhilePending`：不停用，焦點不會掉），「取消」與 Esc 不關。說明裡的「到『成員』調整角色」先關上補填的對話框再開成員（不疊兩層）。成功之後對話框關上、焦點回到打開它的元素（表格與項目頁是狀態格），格子旁邊一個先掛著的 `role="status"` 唸「已填好「客戶驗收日」，AGY-4 已移到「結案」。」。看板見「看板檢視」的改狀態；我的工作的狀態格是同一個 `StateCell`。

### 成員對話框

`features/members/`：列出成員與角色（內建角色前端對照，自訂角色用藍圖的 `name`）。對話框是寬的（`Dialog size="lg"`，`--dialog-width-lg`）。`MemberRoster.tsx` 決定畫法：寬螢幕是表格（`MemberTable.tsx`，`TableScroll`（有名稱「成員」、鍵盤捲得動）加細線樣式，一列一行 `--row-height`、觸控時 44px；成員多時表格自己直向捲動、表頭黏住，`scroll-padding-top` 讓出表頭，方向鍵走到的格子不會被蓋住；名稱一欄是 `tableStyles.primaryCell`），窄螢幕是 `components/List`（`MemberList.tsx`）。兩種畫法的每一位成員都由 `MemberParts.tsx` 的 `useMemberParts` 組出同一份內容（頭像、名稱與「你」、角色選單或文字、「移除」）；角色選單（`RoleSelect.tsx`）是共用的小型下拉（`SelectField size="sm"`，標籤「某某的角色」只給報讀軟體），選了就存（點選、Enter、空白鍵都是；方向鍵與打字只移動反白，Esc 關上不送）；送出中 `aria-busy`、選了不收，失敗時退回原本的角色。最後一位管理員時其他角色是不能選的選項，選項的第二行是短語「最後一位管理員不能換角色」，完整的句子只在表格下面那一段（選單用 `aria-describedby` 連過去）。人員選單讀取中是停用加「載入中…」（和模板的選單一樣），選項帶 Email 當 `keywords`。寬螢幕的表格只有一個 Tab 停駐點（規範 8.3「清單的鍵盤操作」，`lib/useRovingGrid.ts`；接法照我的工作那張表：列帶 `data-row-key`、`TableScroll` 給 `isFocusable={false}`、操作說明是 `item-table/tableHint.ts`，能管理的人是「用方向鍵在格子之間移動，Enter 或 F2 編輯，Tab 離開表格。」、只能看的人不提編輯）：名稱是 `th` 自己（焦點外框畫在格子裡），角色的下拉上 ↑／↓、Home、End 照規範 7.3 是打開清單（不換角色、不移動格子；要上下移動先用 ← 回到名稱），開著時方向鍵都是清單的（表格不接手 `aria-expanded="true"` 的元素）；「移除」標 `data-grid-action`，F2 不按它（Enter 才是）。對話框打開時焦點到表格的停駐點（第一位的名稱）。測試在 `MemberTableKeyboard.test.tsx`。「移除」的 id 兩邊一樣，移除之後焦點的去處照舊。最後一位管理員的說明放在表格（清單）下面一段（`Notice`，`role="none"`），那一列維持一行；被擋住的角色選單與「移除」照舊用 `aria-describedby` 連到它。名字旁邊的頭像是裝飾（`aria-hidden`）。改角色、加入、移除成功的訊息是一直掛著的 `Notice`（`role="status"`，沒有訊息時看不見）；第一次讀專案內容時是骨架（`Skeleton`，「正在載入成員…」只給報讀軟體）。讀不到組織的人員時，「加入成員」換成錯誤的 `Notice`（`role="alert"`），上面的成員清單照樣可以用。有 `project.manage` 的人（組織管理員的 `myPermissions` 一律是全部，也有）可以改角色（角色的下拉，選了就存）、從 `GET /v1/people` 挑還不是成員的人加進來（預設角色是編輯者）、移除成員。改完重新讀專案內容（只重讀專案本身，不重抓項目清單），我的角色與 `myPermissions` 跟著更新。

- **要加的人不在清單裡**（`AddMemberForm.tsx`、`InlineNewPerson.tsx`，規範 8.1 第 3 點）：組織的管理員（`isOrganizationAdmin`）在人員選單下面有「新增人員…」（`aria-expanded`，開著時 `aria-controls` 指到表單）：不再開一層對話框（規範 6.2），在「加入成員」表單後面就地展開「新增人員」表單（凹下去的一塊，h4；欄位、檢查與送出是人員頁那一套 `people/NewPersonFields.tsx`），打開時焦點到「名稱」，Esc 或「取消」只收起這一塊（不往外傳，成員對話框不會跟著關）、焦點回到「新增人員…」，送出中不收；輸入法選字中的 Esc 也不往外傳，但不收起。說明是「新的人用這裡設定的 Email 與密碼登入；建好之後會自動選進上面的「人員」。」，送出按鈕是「新增人員」（這一塊是對話框裡的另一個區，有自己的主要按鈕；名稱和旁邊的「加入」分得開）。「新增人員…」不加負外距：按鈕的左緣對齊人員選單，裡面的字也就和選單的字對齊（兩邊的左內距都是 `--space-3`）。建好之後人員清單先重抓完，新的人自動選在「人員」裡、焦點回到人員選單，一直掛著的 status 說「已新增人員「範例新人」，選好角色後按「加入」。」。其他人（不是組織管理員的專案管理員）的人員選單說明是「要加的人不在清單裡？請組織的管理員先到「人員」新增。」（組織裡的人都已經是成員時是「組織裡的人都已經是成員了。要加別人，請組織的管理員先到「人員」新增。」）：只有文字，不給連到人員頁的連結（訪客看不到那一頁，看得到的成員也不能新增）。「加入」送出中標 `aria-disabled`、不用 `disabled`：按下的按鈕一停用，焦點就掉回頁面本體，Esc 也關不掉對話框。
- **移除**（`RemoveMember.tsx`、`memberRoles.ts` 的 `useRemoveMember`）：每一列一個「移除」（`aria-label` 是「移除範例成員」），確認對話框的標題與內文把名字放在引號裡（「把「範例成員」移出專案？」「「範例成員」負責的項目與成員欄位的值會留著，之後不能再把他指派進去。」），成功與改角色的提示也是（「已把「範例成員」移出專案。…」「已把「範例成員」的角色改成「編輯者」。」）。成功後先從快取的成員裡拿掉（那一列馬上不見），再重新讀專案內容；焦點到下一列的「移除」，沒有就上一列，都沒有了到「關閉」（`updateThenFocus`）。確認對話框放在表格這一層，不跟著那一列卸下。失敗（例如 409）留在確認對話框裡說明。
- **最後一位管理員**（`internal/HANDOFF-week4-admin-ops.md` 3A.1）：自己**不是**組織管理員時，他那一列的「移除」停用但仍然停得到（`aria-disabled`），角色選單裡管理員以外的選項停用，兩者都用 `aria-describedby` 連到看得到的說明「最後一位管理員：要先把另一位成員設成管理員，才能換掉角色或移出專案。」。自己是組織管理員（session 的組織角色是 owner 或 admin，`isOrganizationAdmin`）時不擋：伺服器也放行（他們在每個專案都有全部權限，單人使用時要能把自己換成專案經理去走受限的轉換）。伺服器的 409 `project.last_admin` 為準（改角色被擋時選單退回原本的角色、顯示伺服器的訊息）。
- **移除自己**：不是組織管理員時，確認對話框多說「你會看不到這個專案，畫面會回到專案清單。」；成功後專案清單的快取先拿掉它，換到 `/projects`，「你已經不是「接案測試」的成員，看不到這個專案了。」填進 `role="status"`、焦點到標題，讓專案清單與我的工作重抓；這個專案的快取等專案頁卸下（沒有元件在看）才丟掉（`lib/removeQueriesWhenUnobserved.ts`，先取消正在讀的）：專案頁還掛著時丟掉，它會再讀一次 `GET /v1/projects/{key}`、拿到 404。組織管理員移除自己還看得到，留在原地，我的角色變成「未加入」（`myRole` 是 null）。
- 被移除的人負責的項目：負責人照樣顯示他的名字（伺服器回的 `displayName`）；編輯負責人時選單最後多一個他（選回他就是沒改，不會送出），不另外標記。自訂的成員欄位（`person`）的值是他時，格子顯示「不是成員的人」（`domain/fields.ts` 的 `NOT_A_MEMBER`，值只有人員編號，查不到名字），編輯器的選單也把他接在最後、用同一個說法（`FieldCells.tsx`），選單才選著目前的值、不會看起來像「沒有人」；選回他一樣不送出。

## 看板檢視

`/projects/<代號>?view=board`，在 `features/board/`。依狀態分欄（藍圖 `views` 的 `groupBy` 其他選項、自訂的欄與排序之後再做）。

- **版面**（規範 6.2、7.2）：工作區頁（`PageLayout variant="workspace"`），整頁剛好一個畫面高（`100dvh`）。內容區由上而下：被擋下來的說明（有才出現，很多則時自己捲）、一直佔著一行的 `role="status"`（「正在把…移到…」「已把…移到…」；文字出現或換掉時欄不會跳動，也是工具列與欄之間的留白）、欄的橫向捲動容器（`Board.module.css` 的 `.lanes`，撐滿剩下的高度，用負的外距抵掉頁面左右的留白、自己再加回內距，捲過去的欄貼著邊走；底部留出安全區域）。每一欄剛好是這個高度，欄裡的捲動容器（`.laneScroll`）自己直向捲，標題列（`position: sticky`）黏在它的上方；每一欄的標題列一樣高，卡片在各欄對齊，用 Tab 走到被標題列蓋住的卡片時 `scroll-padding-top` 讓出標題列。寬螢幕第一張卡片離頂端 164px、觸控時 189px（拆解在規範第 14 節）。
- **「看板」區域**（`projects/ProjectWorkspace.tsx`）：看板的篩選在頁面的工具列上，所以名稱是「看板」的區域（`role="region"`）包住整個版面（頁列、工具列、欄），在「看板」裡找得到它的篩選；表格沒有這一層。兩種檢視是同一個 `div`、只換屬性，切換時版面不重新掛載。看板的程式還在下載時（lazy）先不是區域，`BoardView` 畫出來之後（`onShown`）才標上，區域和它的欄一起出現。
- **流程與篩選**（`BoardToolbar.tsx`、`useBoardFilters.ts`）：在頁面的工具列上、檢視的分頁後面（和表格同一個位置），寬螢幕是一組 `FilterBar`「篩選看板」：流程（專案有多個流程時，例如接案模板的需求與任務）、搜尋、負責人（和表格同一套欄位，`size="sm"`、標籤視覺上隱藏），有條件時多「清除條件」；窄螢幕收進「篩選」（`FilterPopover`，數字只算搜尋與負責人，流程是「看哪一個看板」不算條件）。流程記在網址的 `workflow`（選的是預設的就不寫）；預設是第一個項目類型用的流程（`domain/workflow.ts` 的 `boardWorkflows`），網址上不認得的也當成預設。每一欄只放用這個流程的類型（`workflowTypes`）。搜尋與負責人套用到每一欄；「清除條件」留著流程，按了跟著不見，焦點到搜尋框（窄螢幕到「篩選」，`lib/updateThenFocus.ts`）。`BoardToolbar.tsx` 與 `useBoardFilters.ts` 由工具列直接匯入，不能匯入拖曳的套件（看板的其他部分才是 lazy 載入的）。
- **欄**（`BoardColumn.tsx`、`BoardColumnParts.tsx`）：一欄一個狀態，照流程裡的順序；凹下去的軌道（`--color-surface-sunken`、`--radius-xl`）。標題列是狀態的形狀與名稱（`StateBadge`，h2 的文字只有狀態名稱，名稱很長時截掉、完整的在 `title`）、已載入的數量（還有更多時加「+」，螢幕閱讀器唸「已載入 N 個項目，還有更多」）；欄沒有色條，狀態只看標題列的 `StateBadge`。每一欄各自 `GET …/items?type=…&state=…&sort=number:asc&limit=50`（`api/queries.ts` 的 `useBoardColumnItems`，查詢鍵是 `queryKeys.boardColumn`），各自「載入更多」。第一次載入是一張卡片形狀的骨架（`BoardCard.tsx` 的 `CardSkeleton`：卡片的紙裡放 `Skeleton` 的灰條，「載入中…」只給報讀軟體）；第一次就讀不到的欄換成錯誤與「重試」，其他欄照常；「載入更多」失敗是危險的 `Notice`；背景重抓失敗時卡片留著，欄裡多一行 `RefetchErrorNotice`。欄寬一致（`--lane-width`），欄多時看板自己橫向捲動，頁面不會被撐寬；窄螢幕時一欄是八成寬，看得到下一欄的邊，滑完吸附在欄的開頭。
- **卡片**（`BoardCard.tsx`，規範 7.2）：浮在軌道上的紙（`--color-surface-raised`：淺色是白紙、深色比內容區的紙亮一階；細線、`--shadow-raised`、`--radius-lg`）。拿得起來的卡片滑鼠滑過時浮起來一點（`--shadow-raised-hover` 加深一點的外框，只在 `hover: hover`）；項目面板開著的那一張和表格、清單選取的那一筆一樣（`--color-selected` 的底、標題是強調色，外框照一般的）。第一列是編號（等寬字）與類型（`Badge`，流程有多種類型時），右上角是「移到…」；標題最多三行，連結整列都點得到（至少 `--target-min` 高，觸控時 44px）；底下一列是優先度（有設才有；「中」是一般的字色、「低」是灰字）、到期日（有設才有；過期標「已過期」，完成或取消的不算）、負責人的頭像與名字（靠右）：這一列一定是一行，空間不夠時名字先縮成省略號（優先度與到期日不縮），卡片不會變高；頭像是裝飾（`aria-hidden`），滑過頭像的 `title` 是完整的名字，名字本身是唸得到的文字（只唸一次）；沒有負責人是虛線的圓加隱藏文字「沒有負責人」。觸控與滑鼠一樣顯示名字（規範 7.2、第 9 節：不只靠滑過才看得到）。拖曳中跟著指標走的那一份（`CardPreview`）第一列一樣高，大小不會跳。
- **快速新增**（`BoardQuickAdd.tsx`）：只在第一欄（新項目一律從流程的第一個狀態開始）。標題列上的「新增項目」圖示按鈕（`aria-expanded`、打開時 `aria-controls` 指到表單），打開的表單在標題列下面、跟著卡片捲：類型（流程有多種類型時，只列用這個流程的）加標題，可以連續新增；Esc、「取消」或再按一次按鈕收起來，焦點回到按鈕（`updateThenFocus`，用按鈕的 id）。用 `item-table/useCreateItem.ts`，新的項目放在第一欄的最上面。負責人帶看板的負責人條件（`createDefaults.ts` 的 `assigneeFromFilter`），不符合搜尋或負責人時訊息多一句（`matchesBoardFilters`）；「已新增」與「開啟」是表格那一個 `CreatedStatus`。沒有 `item.create` 時沒有。
- **還沒有流程**（`BoardView.tsx` 的 `NoWorkflow`：藍圖沒有項目類型或流程）：「這個專案還沒有流程」，說明「設定裡有項目類型與流程之後，這裡才會有欄。」，有 `blueprint.read` 的人多一顆連到設定頁的「到設定加上流程」；其他人看到「請有設定權限的人在設定裡加上項目類型與流程，這裡才會有欄。」
- **改狀態**有兩條路，最後都經過 `useBoardMoves.ts`：
  - 滑鼠與觸控：dnd-kit（`boardDnd.ts`）。Pointer 感應器要移動 6px 才開始拖（點一下標題是在旁邊開項目面板，窄螢幕是進項目頁；拖完 dnd-kit 擋掉 50ms 內的點擊，不會順便開面板），而且只接滑鼠與觸控筆（`CardPointerSensor`）：dnd-kit 一次只讓一個感應器接手，手指的 pointerdown 不擋掉的話會用「移動一點就拖」的規則，捲動就變成拖曳。手指交給 Touch 感應器，按住 250ms（期間移動不超過 8px）才開始，一碰就滑是捲動。拖曳中走得到的欄有虛線框、指標所在的那一欄填強調色的淡底；走不到的（`domain/workflow.ts` 的 `moveAvailability`：流程沒有這條路、轉換的 `allowedRoles` 沒有我在專案裡的角色）換成 `--color-canvas` 的底、卡片淡掉，原因（「走不到：…」）貼在黏住的標題列下緣、蓋在淡掉的卡片上（絕對定位，不撐高標題列，卡片在拖曳開始與結束時不跳動）。放下時先看指標在不在看板（欄的橫向捲動容器）看得到的範圍內，再用 `pointerWithin` 判斷落在哪一欄（`pointerWithinVisibleLanes`、`dropTarget`）：dnd-kit 量的是沒有裁切的位置，看板橫向捲過之後捲出去的欄還「在」側欄底下，不擋掉就會放進看不見的欄。放回原欄、拖出看板都不送請求；拖到看起來走不到的欄照樣送，以後端為準（「移到…」選單裡走不到的是停用的，選不了）。跟著指標走的是 `DragOverlay`（不會被欄裁掉，陰影是 `--shadow-popover`），原位留虛線的空位；放下時滑到落點，時間與曲線在執行時讀設計變數 `--duration-normal`、`--ease-out`（dnd-kit 要數字與字串；讀不到時的預設值和變數同一組數字，寫在 `boardDnd.ts` 一處），使用者要求減少動態時不滑。
  - 落點與自動捲動：落點（`useDroppable`）是整欄（含標題列）。自動捲動（`boardDnd.ts` 的 `boardAutoScroll`）只有看板（欄的橫向捲動容器）會捲（`canScroll`），用來拖到捲出畫面的欄；欄的直向不自動捲：欄裡照編號排，放在哪個高度結果都一樣，而且指標不在任何一欄上（拖到工具列上取消）時 dnd-kit 會退回捲被拖的卡片的捲動祖先，指標在欄的上方就把原本那一欄一路捲到最上面。觸發的範圍：寬螢幕是看板寬度的 5%、窄螢幕 15%（下一欄只露出一點邊，要摸得到）；速度是 dnd-kit 預設的一半（`acceleration` 5）。預設的 20% 在寬螢幕是右邊兩百多 px，拖到右邊那一欄還沒放下看板就捲走了；預設的速度在手機上不到 0.2 秒就捲過一欄。看板的元素放在 `WorkflowBoard` 的 state（不在渲染時讀 ref），放下的判斷與自動捲動都用它。在真的瀏覽器驗過（2026-11-16，headless Chrome，開發伺服器加假後端）：寬螢幕拖到另一欄、拖到工具列上放開不送（欄捲在中段時放開前後捲動位置不變）、橫向捲過之後拖到捲出去的欄的位置（在側欄上）放開不送、拖到看板右緣停住看板往右捲（欄不動）、拖曳中走不到的欄的卡片位置和拖曳前一樣；手機觸控按住 400ms 再拖到下一欄露出來的邊上放開、拖到右緣等看板捲過一欄再拉回來放開；「移到…」用鍵盤打開、Esc、選了之後焦點跟著卡片；被擋下來的說明、用鍵盤按「知道了」之後焦點到那張卡片的「移到…」。
  - 鍵盤與螢幕閱讀器：卡片右上角的「移到…」（`MoveMenu.tsx`，用共用的 `Menu`，ARIA 的 menu button）。按鈕是 `IconButton`（名稱與滑過的說明都是「AGY-3 移到…」），平常用透明度藏起來（仍然停得到、唸得到），滑鼠滑過卡片、焦點在卡片裡、選單開著或送出中才出現，有觸控能力的裝置（`hover: none` 或 `any-pointer: coarse`：觸控螢幕的筆電接著滑鼠時也算）一直顯示；樣式在 `BoardCard.module.css`（要和卡片的選擇器寫在一起）。列出這個流程的其他狀態，走得到的在前；走不到的停用（`aria-disabled`，仍然停得到）並寫出原因（`aria-describedby`）。方向鍵、Home、End 移動，Esc 關上回到按鈕，Tab 關上照常往下走，點外面關上。卡片移到別的欄時元素會重新掛上，焦點跟著到新位置的「移到…」；失敗回到原欄時焦點原本在它身上的也跟回去。
  - 放下或選了之後先把卡片顯示在新的欄（送出中：變淡、「送出中…」、`aria-busy`，不能再拖、選單打不開）、送 `POST /v1/items/{key}/transitions`。送出中的移動放在 TanStack Query 的 mutation 狀態裡（`useMutationState`），不寫進快取：背景重抓帶回舊位置也不會出現兩張，失敗時什麼都不必復原。每次移動是獨立的 mutation，好幾張卡片可以同時在送出。成功時用回傳的項目更新所有快取（`itemCache.ts` 的 `replaceItemInCache`：表格的清單在原位換掉、看板的欄從舊的欄搬到新的欄照編號放、項目頁、下層清單、活動重抓、我的工作標成過期），落點閃一下。看板的欄有幾條規則：移出或移入一個還有下一頁的欄時，先改快取（不閃回）再讓那一欄重抓（位移量游標）；欄的條件有負責人或搜尋時不自己判斷要不要放進來，交給重抓；狀態、類型與條件看的欄位都沒變的修改（例如在表格只改標題）只在原位換掉，不插入、不移動；欄還有下一頁、而且編號超過已載入的範圍時不插入（還沒載入的較小編號該排在它前面）。送出中的卡片要符合目前這一欄的類型、搜尋與負責人（`projectView.ts` 的 `matchesBoardFilters`，和後端同一套比對）才畫出來，送出中換了流程或條件也不會畫錯欄。被「要先填欄位」擋下、而且能在原地補時（同表格的條件，`useFillableFields`）：卡片回到原欄（送出中的移動不在快取裡，失敗就不畫了），開表格那一個補填的對話框（`MoveFill.tsx`），看板上方不另外加說明；欄位存好之後的改狀態走 `useBoardMoves` 的 `moveFromDialog`（和拖曳、「移到…」同一個 mutation：送出中卡片先畫在新的欄、成功時更新所有快取、落點閃一下、「已把…移到…」），所以卡片是補填成功後才移過去；又被擋下時由對話框說明（`fromDialog` 的移動不進 `MoveProblems`），卡片留在原欄。好幾張接連被擋下時排隊（`useBoardMoves` 的佇列，最新的內容放在 ref：各自的 `onError` 是舊的閉包），一次開一個、換下一個時對話框重新掛上，等著的卡片留在原欄；別的對話框（例如成員）開著時不疊上去，照舊進 `MoveProblems`；從對話框按「到『成員』調整角色」時全部收起來，還沒開的改成看板上方的說明。最後一個對話框關上（取消或移好了）之後焦點到那張卡片現在位置的「移到…」（關上之後才找；拖曳打開時焦點本來不在卡片上），卡片不在畫面上時到工具列的搜尋框（窄螢幕是「篩選」）；後面還有的，下一個對話框自己拿焦點。在真的瀏覽器驗過（2026-11-16，headless Chrome，開發伺服器加假後端）：1440 寬把卡片拖到「結案」1 次、在對話框填日期、Enter 1 步，請求依序是被擋下的改狀態、`PATCH`、改狀態，卡片落在「結案」、焦點在它的「移到…」；390 寬觸控、深色用「移到…」打開，對話框不橫向溢出、按鈕與欄位都是 44px，沒填就按說要先填，Esc 之後焦點回到原欄那張卡片的「移到…」。其他的失敗時卡片回到原欄、紅框，看板上方用危險的 `Notice`（`role="alert"`）說明原因（`MoveProblems.tsx`：標題是「AGY-3「…」沒有移到「…」，留在「…」。」，內容就是表格那一套 `TransitionProblem`，角色不對時有「到『成員』調整角色」），可以「知道了（AGY-3）」關掉。說明連同按鈕一起不見，焦點原本在那則說明裡的話（`MoveProblems.tsx` 的 `dismissKeepingFocus`，`lib/updateThenFocus.ts`）依序交給：那張卡片的「移到…」（卡片已經回到原欄）、下一則（沒有就上一則）說明的「知道了」、工具列的搜尋框（窄螢幕是「篩選」，和「清除條件」同一個去處）。搜尋框是看板內容最前面的控制項，比頁面的標題更接近使用者正在處理的東西；焦點不在說明裡（例如用滑鼠點）就不搬動。看板上方一行 `role="status"` 唸「正在把…移到…」「已把…移到…」。送出中的移動、被擋下來的說明、剛移好的卡片放在 `BoardView`（`useBoardMoves`），不隨流程重建：送出中切換流程，結果與說明切回來都還在。
  - 沒有 `item.transition` 時卡片不能拖、也沒有「移到…」。
- **無障礙文字**：dnd-kit 的 `announcements` 與 `screenReaderInstructions` 是繁體中文（`BOARD_ANNOUNCEMENTS`、`BOARD_INSTRUCTIONS`）。真的要送出時 `onDragEnd` 回空字串（dnd-kit 只略過 null，空字串才會清掉它唸的區域），送出中、成功、被擋下來都只由看板自己的 status 與 alert 唸；放回原欄、拖出看板時才由 dnd-kit 唸「放回原處，狀態沒有改」。卡片不套 dnd-kit 的 `role`、`tabIndex`（鍵盤用「移到…」），只用 `aria-describedby` 連到拖曳的說明。
- **內容安全政策**：拖曳時的位移是 dnd-kit 用 React 的 `style` 物件（DOM API）設的；其他樣子都是 class（欄與看板 `Board.module.css`、卡片與「移到…」`BoardCard.module.css`），包含狀態類別的顏色（CSS 變數）。

## 設定頁（狀態、欄位、轉換、類型、角色）

`/projects/<代號>/settings/<區塊>`，在 `features/settings/`，和變更集的兩頁一起在 `app/lazyPages.tsx` 用 `lazy` 拆成另外的檔案（四個區塊都在設定頁這一個檔案區塊裡，切換區塊不會再下載）。

- **區塊與網址**（`work-items/itemLinks.ts` 的 `SETTINGS_SECTIONS`、`settingsSectionPath`）：`workflows`（流程：每個流程的狀態與轉換）、`types`（類型）、`fields`（欄位）、`roles`（角色），一次只畫一個。`/settings` 本身轉到 `workflows`（`replace`，換頁時帶的 `state` 跟著帶過去）；不認得的區塊是 404。連到設定頁、不指定區塊的地方（專案頁的「設定」、變更集的麵包屑與「到設定頁修改」）照舊用 `projectSettingsPath`，由轉址決定區塊。
- **草稿在外層的版面路由**：路由表裡設定頁（`SettingsPage`）是 `projects/:projectKey/settings` 的元素，四個區塊是它的子路由（`element: null`，不畫自己的元素，React Router 也不會警告），所以切換區塊時設定頁、`SettingsEditor`、`useEditSession` 的草稿、摘要與按過「預覽變更」之後的問題都還在。區塊由網址決定（`settingsPlaceOf`）。頁面的標題（h1）一律是「設定」，瀏覽器分頁的標題帶上區塊（「設定 · 流程」「設定 · 角色」…）：`SettingsEditor` 自己再放一個 `DocumentTitle`，放在頁列之後（React 把後面掛上的 `<title>` 排在 `<head>` 的前面，瀏覽器用第一個）。轉到預設區塊的同時照樣畫著 `SettingsEditor`：從區塊連到 `/settings` 本身也不會丟掉草稿。
- **區塊的分頁**（`SettingsSectionNav.tsx` 的 `SettingsTabs`，工具列上的 `NavTabs`「設定的區塊」）：每個分頁最多帶兩個數字——還沒送出的修改（中性）與要修正的問題（危險色），是 0 的不顯示；報讀軟體聽到的是分頁的說明「2 項還沒送出的修改、1 個要修正的問題」（`aria-describedby`），分頁的名稱只有名字。數字來自 `settingsSections.ts`：`sectionChangeCounts` 和送出列的總數同一套計法、只是照區塊分開（狀態與轉換在流程，類型換流程的搬移在類型；四個加起來就是總數，有測試看著），`sectionIssueCounts` 照問題標在哪一列分（`issueSection`；選項在欄位、類型換流程的搬移在類型，對不到任何一列的不算在分頁上）。分頁放不下時（很窄的螢幕、每個都帶兩個數字）在自己的容器裡橫向捲動。分頁的網址用網址上的專案代號，寫法不同（大小寫）也還是同一頁。

- **權限**：沒有 `blueprint.read` 時看不到入口，直接打網址是「沒有權限看這個專案的設定」（403 的頁面），也不去讀變更集。只有 `blueprint.read` 時整頁唯讀（文字，沒有任何輸入框、勾選框與按鈕；轉換是一條一行的清單，附上限制）。有 `blueprint.propose` 才能編輯。
- **草稿**（`domain/settingsDraft.ts`，每個函式回傳新的草稿；轉換在 `settingsTransitions.ts`、類型在 `settingsTypes.ts`、角色在 `settingsRoles.ts`）：開始編輯時記下藍圖與版本（`useEditSession`），草稿只放設定頁能改的：每個流程的狀態與轉換（`transitions` 是 `undefined` 表示不限制；加上被刪除的狀態要搬去哪裡）、自訂欄位與它套用到哪些類型、類型（名稱、流程、上層）、自訂角色，以及類型換流程時選的搬移目標。送出時由 `domain/settingsChangeSet.ts` 組成變更集：設定頁改不了的部分（檢視、自動化、整合）照目前的帶過去，沒動到的物件原樣送出（伺服器算的差異才只有真的改的地方）；改回原樣（包含勾選的先後不同、名稱只差前後空白）送的是原本的物件。轉換與角色的每個清單分開比：只改了允許的角色時要先填的欄位送原本的陣列（反過來也是），只改了角色名稱時權限送原本的陣列，另一個清單不會被重新排序成多一個「改了」。被刪除的狀態、欄位、角色在別處的引用**組變更集時**才拿掉——兩端不在草稿裡的轉換、類型的 `fields`、轉換的 `requireFields` 與 `allowedRoles`、檢視的欄位、排序、分組與 `visibleTo`——草稿裡留著，所以「復原」時引用跟著回來；剛新增、還沒送出的狀態、欄位、角色刪掉時，轉換裡對它的引用直接拿掉（之後用同一個 key 新增，舊的轉換與限制不會跑回來）。檢視篩選的狀態不在任何流程裡了就換成項目搬去的狀態（去重）：直接拿掉的話，篩選只剩那一個狀態時會變成空的，空的篩選是不篩選，檢視反而變寬。檢視的 `visibleTo` 拿掉角色之後變空就整個不送（和 API 回的形狀一樣，省略是所有成員都看得到）。類型的 `fields` 是「原本有而且還套用的照原本的順序，再接上新套用的」，新類型照欄位的順序。原本沒有 `roles` 屬性、也沒有自訂角色時不送 `roles`。`migrations` 一定帶 `moveStates`（刪除狀態的搬移，再接上類型換流程的搬移，以（流程, 舊狀態）去重、刪除狀態的優先）與 `dropFields` 兩個陣列；`summary` 有填才送。非選項型欄位不帶 `options`、非金額不帶 `currency`。
- **還沒送出的修改**（`domain/settingsStatus.ts`）：每一列一個標籤——新增（強調色）、已修改（警告色）、已移動（中性，只換了先後）、要刪除（危險色，另外列在「要刪除」的清單）；已修改、已移動、要刪除的整列再加同語意的淡底，新增的不加（強調色的淡底就是「已選取」的底色），不畫色條（規範第 4 節）。移回原位、改回原名就不算修改。送出列寫著「還沒送出的修改：N 項」（見下面「送出列」；每個分頁另外帶自己那一區的項數）：每個新增、修改、移動、要刪除的狀態、欄位與角色，每個新增、修改或要刪除的類型各一項（刪除類型而拿掉的上層不另外算）；轉換是每條新增、刪除、修改的各一項（兩端有狀態被刪除的、一端是剛新增的狀態的不另外算：新狀態本身已經算一項，「先新增再切成限制」和「先切成限制再新增」計數一樣），切換限制算一項；新類型套用了既有的欄位算在新類型，欄位不算修改。沒有修改時「預覽變更」停用。
- **送出列**（`SubmitBar.tsx`）：沒有修改時是頁尾的一行（「還沒有修改」與停用的「預覽變更」，上面一條細線，不黏住、沒有摘要）；有修改時（`data-dirty`）黏在畫面底部、往左右延伸到內容區的邊，底下讓出手機的安全區域（`env(safe-area-inset-bottom)`）。寬螢幕一列：幾項修改、摘要（沒有錯誤時標籤與輸入框同一行，有錯誤時照 `Field` 的直排、錯誤寫在下面；說明「一句話說明這次修改，預覽與套用時看得到；可以不填。」是 `SubmitBar` 自己的 `.visually-hidden` 元素，用 `aria-describedby` 連到輸入框，畫面上是 placeholder「一句話說明這次修改，可以不填」）、「捨棄修改」、「預覽變更」。窄螢幕（`useIsCompact()`）最多兩列：沒有摘要時幾項修改與「加上摘要」一列，「捨棄修改」「預覽變更」靠右一列；按「加上摘要」換成摘要的輸入框、焦點跟著過去（已經有內容或有問題時一律打開），這時摘要自己一列排在上面，幾項修改與兩顆按鈕一列（320px 時幾項修改的字在自己的格子裡換行，送出列一樣是兩列、113px）。黏住時整頁加上 `scroll-padding-bottom`（`:root:has(...)`，送出列一列或兩列控制項的高度加安全區域），Tab 走到的元素不會停在送出列底下；送出列上方的說明出現時多出來的高度不算。「還沒有修改」「還沒送出的修改：N 項」照舊在 `aria-live="polite"` 裡。問題的說明（`role="alert"`）、別的區塊的問題、「其他問題」排在這一列的上面。
- **每一列**：一列一行（`--row-height`，直接放在紙上、列與列之間一條細線，沒有卡片與陰影）：順序、名稱、其餘的資訊（類別或流程、key、標籤，`.details`）、右邊的圖示按鈕。「上移」「下移」「刪除」「復原」「移除」（剛加的選項）是 `IconButton`，名稱照舊是完整的句子（「把「待辦」往上移」「刪除「待辦」」「復原「待辦」」）；停用但停得到的（既有選項的「刪除」、最後一個類型的「刪除」）照舊用 `aria-disabled`。窄螢幕一列最多兩行：名稱與動作一行，`.details` 一行（`.cells` 用 `display: contents` 讓名稱與 details 直接排進那一列的格線）。欄位、類型、角色的勾選（`Checklist`）與選項、提醒接在下面。列上的輸入框和共用的 `Field` 同一種外框（`--color-control-border`），下拉是共用的 `Select`（`size="sm"` 加 `width="content"`：照目前的值的寬度、8～16rem）；狀態類別與搬移目標的選項前面是類別的形狀（`work-items/selectOptionMarks.tsx`）；搬移目標還沒選時按鈕上是灰字的「選擇狀態」（placeholder；刪除狀態與類型換流程的搬移同一種做法，選了之後要改就重選）；勾選都是共用的 `CheckboxField`（整個標籤是點擊範圍）。問題前面是錯誤的圖示（`RowParts.tsx` 的 `IssueText`，「別人先改了」的說明裡讀不到最新設定的錯誤也是），不是「!」。列裡的警告（自動化用到要刪除的東西、還有成員是要刪除的角色、拿掉之後清單變空）是共用的 `Notice`（`tone="warning"`、`role="none"`，`id` 給 `aria-describedby`）。key 是等寬字、`--text-sm`。列上輸入框與下拉的樣式在 `SettingsControls.module.css`（`Settings.module.css` 放版面）。
- **焦點**：按的按鈕會跟著不見或停用時，焦點都有去處（`lib/updateThenFocus.ts`：先 `flushSync` 更新畫面，再放到第一個還在、沒有停用的候選上）。下面每一種操作各自寫了去哪裡；對話框關上時焦點回到打開它的按鈕；「捨棄修改」與「以最新版本重新開始」之後到頁面的標題（h1 是 `tabIndex={-1}`）。
- **狀態**：每個流程一區（有限制轉換的流程說明限制）。名稱與類別直接在列上改；上移、下移（焦點留在按的那顆，到頭停用時換到另一顆）；刪除後那一列換到「要刪除」、焦點到「項目搬到」的選單（同一個流程裡還在的狀態，沒選不能送出），可以「復原」（回到原本的位置）。被當成搬移目標的狀態也被刪除時，目標清掉重選。剛新增的狀態刪掉就直接不見。「新增狀態」是對話框：名稱、key、類別、位置（預設在第一個完成類或已取消的狀態之前）；有限制轉換的流程多兩組勾選「從哪些狀態可以轉進來」「可以轉去哪些狀態」，預設從插入位置的前一個狀態轉進來、轉去後一個狀態（新狀態是完成或已取消類就預設不轉出去；沒自己勾過時跟著位置與類別變）。
- **轉換**（`TransitionsPanel`、`TransitionMatrix`、`TransitionDialog`）：每個流程那一區、狀態清單的下面。「限制轉換」的勾選框加說明（不限制＝任何兩個狀態都可以互轉；限制＝只有勾起來的可以走；唯讀時說「只有下面列出的轉換可以走」）。從不限制切成限制時，目前藍圖本來就有列轉換的回到那些，本來沒有的從「每兩個不同狀態都可以互轉」（n×(n−1) 條，照狀態順序）開始，切換的當下行為不變、不算個別的修改，使用者再取消不要的（算「要刪除」）；切回不限制時 `transitions` 整個不送。有限制時是「從 → 到」的表格（視覺隱藏的 `<caption>`「「交付流程」的轉換：列是起點，欄是終點」）：列是起點、欄是終點（照草稿的狀態順序），對角線不能勾。表頭與表格下方的問題用草稿的名稱，名稱空著時用 key；每格的勾選框（「從「A」到「B」」）與「設定」按鈕的無障礙名稱和狀態那一列一樣用目前藍圖裡的原名（新狀態用 key），打字時不跟著變；專案有兩個以上的流程時後面帶「（流程名）」（和「限制轉換（交付流程）」一致）。新增狀態的對話框與刪除角色的說明裡的狀態名稱也是空著時用 key。勾起目前藍圖就允許的那一條時放回原本的位置、帶回原本的限制（送出的是原本的物件），新的接在最後，帶 `allowedRoles: []` 與 `requireFields: []`。勾起來的格子有「設定」（對話框：允許的角色是內建四個加草稿的自訂角色，都不勾是不限，沒有「改變狀態」權限的角色名稱後面標「（不能改變狀態）」；要先填的欄位是說明、上層項目、這條轉換現在或原本就要求的其他核心欄位（例如用變更集文件寫的「到期日」，看得到才拿得掉），再接草稿裡還在的自訂欄位；按「套用」才寫進草稿，被刪除的角色與欄位留在草稿裡不顯示；打開不改就按「套用」仍然沒有修改）。對話框開著時草稿被背景重抓換成新的一版、那條轉換不在了：對話框關上，焦點到那個流程的「限制轉換」。格子上的「角色」「必填」看得出有限制，完整的說法與還沒送出的修改（新增、已修改、要刪除）用 `aria-describedby` 連到勾選框。自己到自己的格子只有淡底（不畫符號），「不能轉到自己」是隱藏文字。還沒送出的修改在格子上是文字（「新增」強調色；「已修改」「要刪除」是警告色、危險色加同語意的淡底），不畫色條；行列的標頭與左上角是凹下去的底（矩陣的兩個軸，規範 7.1 的例外）。每格的勾選框包在一個 `<label>` 裡當點擊範圍（至少 `--target-min` 見方：滑鼠 24px、觸控 44px），名稱照舊是勾選框的 `aria-label`。表格包在可以水平捲動的容器裡（`role="region"`、`tabIndex={0}`、`position: relative`，第一欄固定；外面一圈細線，沒有圓角與陰影），手機寬度時整頁不會被撐寬。問題標在格子上（紅框加文字「有問題」、`aria-invalid`）並寫在表格下方（「「A」→「B」：…」）；表格下方走過每一對有問題的「從 → 到」、不只勾著的，取消勾選那一格之後伺服器的問題照樣列著，勾選框的 `aria-describedby` 一定連得到。
- **類型**（`ItemTypesSection`、`ItemTypeRow`、`AddItemTypeDialog`）：名稱、流程（下拉）、可以掛在哪些類型底下（其他類型的勾選，照草稿的順序存）直接在列上改。換了流程的類型在那一列下面列出要搬的狀態：目前藍圖裡就有、換了流程的類型，它原本流程的狀態裡不在新流程（草稿）的那些；同 key 的不用搬，新流程原本就有、在草稿裡刪掉的由「刪除狀態」的搬移處理。「類型「需求」停在「開發」的項目搬到」預先選好新流程裡第一個同類別的狀態，沒有就第一個狀態。換流程之後，類型那一列一直掛著的 `aria-live="polite"` 區域（先掛空的；不用 `role="status"`，頁面上「已套用」的提示才是唯一的 status）說「換到「任務流程」之後，有 8 個狀態要選項目搬到哪裡（已經預選好，請確認）」。伺服器每個（新流程, 舊狀態）只認一條指示，所以兩個類型換到同一個流程時共用一條（改一個另一個跟著變，列上寫「和「需求變更單」共用」，說明照第一個類型的舊狀態名稱）；共用的舊狀態在兩個類型原本的流程裡類別不同時不預選（照哪一個類型的類別都可能搬錯），送出前要選；這條搬移的問題標在（新流程, 舊狀態），每個共用它的類型列上的選單都拿到 `aria-invalid` 與說明（各自的 id）；舊狀態在新流程裡被刪除了的，類型那一列另外說「停在「待辦」的項目照「另一流程」刪除「待辦」的搬移，搬到「審查」」（還沒選時說還沒選），使用者才知道不是漏了；換回原本的流程就不用搬，留下的選擇不送；選過的目標後來被刪掉就回到預設。「新增類型」是對話框：名稱、key、流程、上層、要套用的自訂欄位（預設勾選選定流程的轉換要求先填的，寫進那些欄位的 `appliesTo`）。新類型出現在欄位的「套用到」與其他類型的上層勾選裡。
- **刪除類型**（`domain/settingsTypeRemoval.ts`、`ItemTypeRow` 的「刪除」、`RemovedItemTypeRow`）：原本就有的類型換到「要刪除的類型」，焦點到它的「復原」（回到原本的位置，焦點回到「刪除」）；剛新增的直接不見，連其他類型的上層與欄位的套用一起拿掉，焦點到「新增類型」。只剩一個類型時「刪除」停用但仍然停得到，那一列寫出看得到的說明「最後一個類型：要先新增另一個類型，才能刪除它。」（和成員對話框的最後一位管理員一樣，用 `aria-describedby` 連到「刪除」；伺服器沒有這條規則，前端先擋；送出前的檢查也有，說「至少要留一個類型。」）。刪除的類型 key 也算用過。引用在**組變更集時**才拿掉：其他類型的 `parents`、檢視的 `filter.itemTypes`（變空送空陣列，就是不篩選類型）；類型的 `fields` 跟著類型消失；換了流程又刪掉的類型不再要搬移（共用那條搬移的其他類型照舊）。自動化不改。要刪除的那一列說明「還有這種項目時，預覽頁會擋下：要先刪除這些項目或改成別的類型。」（設定頁不知道數量，預覽頁的 `item_type_removal` 有）、會一起拿掉哪些引用（「也會從類型「任務」可以掛的上層、檢視「給客戶看」的類型篩選拿掉這個類型。」）、拿掉之後清單變空的（「注意：拿掉之後，「任務」不能再掛在任何類型底下；檢視「給客戶看」不再篩選類型（所有類型都會列出）。」）與自動化的提醒；這些（與伺服器的問題）都用 `aria-describedby` 連到「復原」。勾選清單（`Checklist`）裡看不到的值（要刪除的類型）照樣留著：改了別的勾選再復原，引用跟著回來。送出前的檢查只把草稿裡還在的類型當上層（轉換要求先填上層、而上層只剩要刪除的類型時擋下）。
- **角色**（`RolesSection`、`RoleRow`、`RoleNotes`、`AddRoleDialog`）：內建的四個列在「內建角色」（名稱與權限，照後端 `ProjectRoles.cs` 寫在 `domain/labels.ts`，唯讀）。自訂角色可以改名、勾權限（照 `PERMISSION_ORDER` 存與比較，和原本同一組就送原本的物件）、刪除與復原（焦點在「復原」與「刪除」之間來回；剛新增的刪掉回到「新增角色」）。要刪除的那一列說明還有幾位成員是這個角色（「套用前要先在「成員」把他們換成別的角色，否則預覽頁會擋下」）、會一起拿掉哪些轉換與檢視的引用，拿掉之後清單變空的另外提醒（轉換變成所有角色都能走、檢視變成所有成員都看得到）；只提醒、不擋送出。這些說明用 `aria-describedby` 連到「復原」（刪除後焦點去的地方），要刪除的欄位的封存說明與自動化提醒也連到它的「復原」，要刪除的狀態的自動化提醒連到「項目搬到」的選單。「新增角色」是對話框：名稱、key、權限（預設和檢視者一樣：查看項目、查看設定）。權限的中文在 `PERMISSION_LABELS`。
- **手機寬度**：每一列最多兩行（見上面「每一列」）；欄的位置從右邊數（`grid-column: -3 / -2`），有順序欄的狀態列與沒有的類型、欄位、角色列共用同一條規則。整頁不會水平捲動（320px 也是）。
- **欄位**：名稱直接改；「套用到」是一排勾選框（草稿裡的類型，包含剛新增的），取消勾選的類型用的流程有轉換要求先填這個欄位時，在那一列先提醒「「需求變更單」用的「交付流程」有轉換要求先填這個欄位：取消套用之後，送出會被伺服器擋下。」（`settingsChangeSet.ts` 的 `detachConflicts`，看草稿的轉換與類型；一直掛著的 `aria-live` 區域，並用 `aria-describedby` 連到那一組勾選框；送出前的檢查也會標在那條轉換上）。選項型欄位下面是選項：可以改名、可以加（名稱加 key），既有的選項不能刪（按鈕 `aria-disabled` 並用 `aria-describedby` 說明原因），剛加的可以拿掉（焦點到下一列、沒有就上一列的按鈕，都沒有了到新選項的名稱）。刪除欄位說明值會封存、還有哪些地方會一起拿掉它（`fieldReferences`），可以復原。「新增欄位」是對話框：名稱、key、型別、選項（至少一個；拿掉一個之後焦點到相鄰那一列的「拿掉」，都拿掉了到「再加一個選項」，不會掉到對話框外面）或幣別（常用的十種）、套用的類型（預設全部）。這一片不做改型別。
- **自動化的提醒**（`domain/settingsAutomations.ts`）：要刪除的狀態被自動化用到（`transition` 動作的 `to`、條件 `state` 的 `in`）、而且草稿裡沒有任何流程還有這個 key 時，那一列提醒「自動化「…」用到這個狀態：刪除之後，送出會被伺服器擋下。自動化目前只能用變更集文件修改。」；欄位同理（`set_field` 的 `field`、條件的 `field`），類型同理（條件 `item_type` 的 `in`，伺服器會擋 `automation.unknown_item_type`）。不擋送出。
- **key**：可以自己填，給建議值（英文名稱轉小寫加底線，其他用 `state_1`、`field_1`、`option_1`、`type_1`、`role_1`，避開用過的）。前端先擋：格式 `^[a-z][a-z0-9_]{1,39}$`、同一個流程（包含要刪除的狀態）、欄位、類型、角色（包含要刪除的）裡不重複、自訂欄位不能用核心欄位的名字、自訂角色不能用內建角色的 key。名稱必填、最多 100 個字、不能有控制字元；摘要最多 500 個字（和伺服器的上限一樣，輸入框也設了 `maxLength`）。每個流程至少一個狀態、至少一個完成類；選項型至少一個選項。
- **送出前先擋的語意檢查**（`domain/settingsChecks.ts`，對照後端的 `WorkflowRules`、`TransitionRules`、`ItemTypeRules`、`ParentCycles`、`RoleRules`）：有限制的流程每個狀態都要從起始狀態走得到、完成與已取消以外的要有出路（標在那個狀態）；轉換要先填的自訂欄位要套用在每個用這個流程的類型、要先填上層項目時這些類型都要能有上層（標在那條轉換，說出缺的類型；類型換流程造成的也算）；轉換限了角色、而每個允許的角色（內建的照 `labels.ts`、自訂的照草稿的權限，被刪除的不算）都沒有「改變狀態」（伺服器改狀態先看 `item.transition` 再看 `allowedRoles`，這條轉換沒有人走得了；自訂角色取消「改變狀態」也會觸發，標在那條轉換）；類型的名稱、上層繞成一圈（標在把圈閉合的那個類型，和伺服器一樣照類型的順序深度優先找）、換流程的搬移沒有目標（標在那條搬移的選單）；角色的名稱。
- **名稱的前後空白**：狀態、欄位、選項、類型、角色的名稱送出時去掉前後的空白；只差空白不算修改（沒有標記、不計數，送出的是原本的那一個物件）。
- **預覽變更**（`useProposal`）：先做前端的檢查，按過一次之後問題標在對應的那一列（`aria-describedby`），送出列上方用 `role="alert"` 說還有幾個地方要修正，後面接著分布在哪裡（「還有 2 個地方要修正，請看標示的地方。欄位 1 個、角色 1 個。」，照分頁的順序，再接「摘要」與「其他問題」；`settingsSections.ts` 的 `issueBreakdown`）：問題可能都在目前沒有畫出來的區塊，報讀軟體只聽到「請看標示的地方」會找不到。伺服器擋下時也一樣（「伺服器檢查後擋下了這份變更（3 個問題），請看標示的地方。欄位 1 個、角色 1 個、其他問題 1 個。」）。通過才 `POST …/changesets`（`baseVersion` 是開始編輯時的版本），成功後把回應寫進那份變更集的快取、換到預覽頁。`changeset.invalid` 時 `domain/settingsIssues.ts` 的 `locateIssue` 照 `details` 的路徑在送出的文件裡找到那一列：`/blueprint/workflows/N/states/M` 是狀態；`/blueprint/workflows/N/transitions/M[/…]`（包含 `requireFields`、`allowedRoles`）是那條轉換（上一片標在自訂欄位那一列，現在轉換改得了，改標在轉換上）；`/blueprint/fields/N[/options/K]` 是欄位或選項；`/blueprint/itemTypes/N/fields/K` 是那個欄位，`/blueprint/itemTypes/N[/…]` 的其他是那個類型；`/blueprint/roles/N[/…]` 是那個角色；`/migrations/moveStates/N[/…]` 是刪除狀態的搬移就標在狀態、是類型換流程的搬移就標在那條搬移（新流程, 舊狀態），每個共用它的類型列上的選單都標（要草稿與基準才分得出來）；`/migrations/dropFields/N` 是欄位；`/blueprint/automations/N/conditions/C/in/V`（條件看 `item_type`）與 `/blueprint/views/N/filter/itemTypes/K` 是那個類型（目前藍圖裡有的，包含要刪除的：問題標在「要刪除的類型」那一列）；`/summary` 標在摘要旁邊；對不到的（其他的自動化與檢視問題、根）列在送出列的「其他問題」。`locateIssue` 的對應不變，但問題可能標在目前沒有畫出來的區塊：那個區塊的分頁帶著問題的數量，送出列在說明下面寫「別的區塊也有要修正的地方：流程 2 個、欄位 1 個。」並連過去（`SettingsSectionNav.tsx` 的 `ElsewhereIssues`；不是即時區域，上面的 alert 已經唸過）。點了連結（沒按修飾鍵的左鍵），換過去之後焦點放到那個區塊的標題（h2，`tabIndex={-1}`；按的連結會跟著不見）；按著 ⌘／Ctrl 點、中鍵點交給瀏覽器開新分頁，不留下焦點的要求（要求在區塊一換就清掉）。
- **離開提醒**（`useLeaveGuard`）：有沒送出的修改時，離開設定頁用 React Router 的 `useBlocker` 問一次（「留下來」或「捨棄修改並離開」），重新整理或關分頁用 `beforeunload`。目的地還在同一個專案的設定頁底下（切換區塊、`/settings` 轉到預設的區塊，`itemLinks.ts` 的 `isSameSettingsPage`）不問：草稿在外層的版面路由，不會不見。例外是有對話框開著時（新增狀態、欄位、類型、角色，轉換的限制；每個對話框掛著時用 `SettingsContext.tsx` 的 `useSettingsDialog` 登記）：區塊一換對話框就跟著卸下、打到一半的內容不見，所以連切換區塊（例如瀏覽器的上一頁）也先問「對話框裡的內容還沒加入」（「留下來」或「捨棄並換過去」；換過去之後焦點到新區塊的標題），`beforeunload` 也照樣提醒。送出成功後不擋。
- **預覽之後回去修改**（`settingsDraftMemory.ts`、`useDraftMemory.ts`）：「預覽變更」送出成功時，把整份編輯（`useEditSession` 的基準藍圖、版本與草稿，包含刪除狀態與類型換流程選的搬移目標）、摘要、當時的區塊與變成的變更集編號記在記憶體。鍵是專案代號加基準版本，每個專案只留最新的一份（再預覽一次就換成新的變更集）；只放記憶體（重新整理就沒了），不放查詢的快取（會被失效、回收），每個 `QueryClient` 一份（測試每次 `renderApp` 一個，不會跨測試）；記下送出的人，換人登入看不到；登出與工作階段失效時整份清掉（`auth/session.ts` 的 `markSignedOut` 呼叫 `forgetAllDrafts`，和留言、說明的草稿一起）。預覽頁按「回去修改」放棄成功之後，這一份改成「等設定頁接回去」；設定頁掛上時（有 `blueprint.propose` 才接）用它當 `useEditSession` 的起點、摘要也帶回來，接到就從記憶體拿掉——之後「捨棄修改」或離開設定頁再進來，就是目前的設定。接回來的是原本的基準藍圖與版本，不是套在手上的藍圖上：這段期間別人套用了新版本時，照「別人先改了」顯示說明與「以最新版本重新開始」。還在等待核准的那一份不會自己接回設定頁：沒按「回去修改」直接回到設定頁（例如瀏覽器的上一頁）是目前的設定（否則再預覽一次就多一份等待核准的），但「有 N 份變更等待核准」的提示（`SettingsNotices.tsx` 的 `PendingNotice`，同一份變更集清單，不多打請求）在其中有自己提出、草稿還在記憶體裡的那一份時多一句「你剛送出的變更集 #N 還在等待核准，可以到預覽頁按「回去修改」帶著修改回來。」，「變更集 #N」連到預覽頁。設定頁「捨棄修改」時清掉這個專案記下的草稿，那一份變更集也就不再有「回去修改」。
- **別人先改了**：專案的藍圖換了新的一版（重抓專案內容時看到）時，沒有修改就直接換成最新的（版本只會往前）；有修改就說明「別人已經套用了新版本：設定在你編輯時已經更新為第 N 版…」，可以「以最新版本重新開始」。送出時才知道的（422 的 `details` 有 `plan.base_version_mismatch`，路徑 `/baseVersion`）：讓專案的內容重抓、同一段說明出現在上方並拿到焦點，送出列說「別人已經套用了新版本，這份修改送不出去」，不列在「其他問題」。「以最新版本重新開始」先向伺服器讀專案最新的內容（`queryClient.query`，手上的那一份可能還沒重抓完），草稿與摘要丟掉、用新的藍圖重建；讀不到時在說明裡寫原因，草稿留著。
- 頁列是「專案名稱 / 設定」（h1；專案的連結照這個專案上次用的檢視開，`useProjectPageLink`；分頁標題帶上區塊，`PageBar` 的 `documentTitle`，一頁只有一個 `<title>`），右邊「所有變更集」；工具列是區塊的分頁；標題下面一句「藍圖第 N 版。修改會先送出成一份變更集，預覽差異與影響之後再套用。」。提示都是共用的 `Notice`（`SettingsNotices.tsx`）：「有 N 份變更等待核准」（`role="none"`，連到變更集清單）、唯讀的說明、別人先改了設定（`OutdatedNotice`：`Notice` 本身是 `role="alert"`，給 `ref` 與 `tabIndex={-1}` 當焦點的去處）。套用之後導回這裡時（`navigate` 的 `state`，直接到 `workflows`），焦點到頁面的標題，「已套用變更集 #N，藍圖是第 M 版。」填進一直掛著的 `role="status"`（`Notice` 先掛空的，下一輪才填內容；和區域一起出現的文字，螢幕報讀器常常不唸）。
- **高度**：一次只畫一個區塊，手機上整頁從 6.4 個畫面高縮到 1.3～2.8 個（流程最長）；`data-content-start` 標在目前那個區塊（`section`）上。

## 變更集

`features/changesets/`。

- **清單**（`/projects/<代號>/changesets`）：頁列是「專案名稱 / 設定 / 變更集」（h1；專案的連結照這個專案上次用的檢視開，預覽頁與 403 的「回到專案」也是），右邊「到設定頁修改」。編號（連到預覽頁）、摘要（沒有時寫「沒有摘要」）、狀態（已套用的加上第幾版）、提出的人、提出時間，新的在前。沒有時說明怎麼產生並連到設定頁。寬螢幕的表格是 `TableScroll layout="page"`（表頭黏在頁列下面）。窄螢幕（`useIsCompact()`）換成 `components/List`（`ChangeSetCompactList.tsx`）：整筆連到預覽頁，第一行編號與摘要（單行省略，`title` 是全文），第二行狀態、提出的人與時間；內容和表格一樣。
- **預覽頁**（`/projects/<代號>/changesets/<編號>`）：頁列是位置（專案 / 設定 / 變更集 / #N），右邊是套用與放棄；變更集編號是內容區的大標題（h1「變更集 #N」，`headingRef` 給放棄、「知道了」之後放焦點），摘要接在下面。狀態、誰在何時提出、決定的結果（誰在何時套用、第幾版；放棄；過期）。最上面三格摘要：設定的修改幾項、會動到的項目（搬移、封存、轉換的數量加總；有兩種以上時說「最多」，因為同一個項目可能都算到）、能不能套用（可以套用是綠、有原因擋住是紅：淡底加同色的數值，不畫色條，意思寫在格子的文字裡）。狀態標籤（`ChangeSetStatusBadge`）：等待核准與已放棄是中性、已套用是成功色、已過期是警告色——強調色不拿來表達狀態。三格直接放在紙上，上下各一條細線、格子之間一條直線（不是浮起來的卡片）；窄螢幕一格一列，名稱與數字排在同一行。差異、影響、擋住的原因也是細線分隔的清單。提示都是共用的 `Notice`：放棄的結果（一直掛著的 `role="status"`）、過期（`role="none"`，「到設定頁重新編輯」是長得像按鈕的連結）、套用或放棄被擋下（`Notice` 本身是 `role="alert"`，給 `ref` 與 `tabIndex={-1}` 當焦點的去處，「知道了」是 `Notice` 的 `onDismiss`）、套用的確認對話框裡「不能一鍵還原」。
  - **差異**（`domain/changeSetText.ts`）：每一個 `Change` 一句話，例如「新增狀態「內部驗收」」「刪除欄位「備註」」「把狀態「審查中」改名為「內部審查」」「修改狀態「審查中」：類別從「進行中」改成「完成」」「修改欄位「預算」：幣別從「TWD」改成「USD」」「修改類型「需求」：多了欄位…，少了欄位…」；專案有好幾個流程時狀態後面帶流程的名稱。「改之前」一律是變更集的 `baseBlueprint`、「改之後」是 `blueprint`（已套用的變更集，專案目前的藍圖已經是改之後的樣子，拿它來比會說成「從 X 改成 X」）。名稱：新增的看 `blueprint`、刪除與修改的看 `baseBlueprint`（`domain/changeSetNames.ts`），都找不到用 key。`changedProperties` 轉成看得懂的說法（伺服器比對的每一種資源的屬性都有，檢視的 `type` 說「顯示方式」）；清單型的屬性兩版都有是「調整了…的順序」，只有一版有是「加上了…」「拿掉了…」（流程的 `transitions` 說「開始限制轉換」「不再限制轉換」）。轉換、類型、角色、檢視裡勾選出來的清單（`domain/changeSetProperties.ts`）說成改成了哪些：「允許的角色改成「專案經理」、「客戶」」「改成不限角色」「要先填的欄位改成「說明」、「客戶驗收日」」「改成不必先填任何欄位」「流程從「交付流程」改成「任務流程」」「可以掛的上層類型改成「需求」」「不能掛在任何類型底下」「權限多了「新增項目」，少了「提出設定修改」」「看得到的角色改成「客戶」」「改成所有成員都看得到」（`visibleTo` 省略才是所有成員；空陣列說「看得到的角色改成一個都沒列」）；檢視的 `filter`（`domain/changeSetViewFilter.ts`）比對前後的 `itemTypes`、`states`、`stateCategories`、`assignee`，說出改了什麼：「類型篩選拿掉「需求」」「類型篩選多了「任務」，拿掉「需求」」「狀態篩選改成「待辦」」（原本沒有篩選）「不再篩選類型（原本是「需求」）」（清單變空就是不篩選）「調整了類型篩選的順序」「負責人篩選改成「看的人自己」」「不再篩選負責人」，好幾種一起改時用「；」分開；這四種都沒變（別的屬性改了）才說「篩選條件有調整」；這幾種資源有好幾個屬性改了時用「；」分開（名稱之間已經用「、」）。核准的人要看得到內容（`domain/changeSetTransitions.ts`）：流程從不限制切成限制（伺服器只給流程的 `transitions` 改了，不逐條列出）時從變更集的藍圖列出能走的每一條與限制，四條以內寫在同一句（「開始限制轉換，只能走「待辦」→「進行中」、「進行中」→「完成」（限「編輯者」；要先填「說明」）」），更多時句子說「只能走下面這 N 條」、底下一行一條（`blueprintChangeDetails`，`aria-label="可以走的轉換"` 的清單）；新增的轉換帶上限制（「新增轉換「程式審查」→「內部驗收」（交付流程），限「專案經理」；要先填「說明」」）；新增的角色帶上權限（照固定的順序，「新增角色「QA 主管」，權限：查看項目、修改項目、改變狀態、留言、查看設定」，一個都沒有時說「沒有任何權限」）。
  - **影響**（`domain/impactText.ts`）：每一項一句話加數量（「12 個項目會從「待驗收」搬到「內部驗收」」；舊狀態的名稱有歧義時帶流程的名稱：類型換流程（舊狀態在另一個流程，搬去的狀態也帶）「3 個項目會從「完成」（任務流程）搬到「結案」（交付流程）」，同一個 key 在好幾個流程都有時只帶真的會搬過來的那幾個流程（刪除狀態的是這個流程本身，類型換流程的是那些類型原本的流程；兩種是同一條指示時都列出：「從「待辦」（任務流程）、「待辦」（另一流程）搬到「審查」（另一流程）」）「8 個項目的「備註」會被封存」「5 個「任務」的「摘要」會被封存」「還有 4 個「任務」：要先在項目頁刪除這些項目或改成別的類型，才能刪除這個類型」…），`blocksApply` 的那一列紅底加「擋住套用」。等待核准時，數量是 0 的搬移合成一行，放在其他搬移的後面（「其他 7 個狀態沒有項目要搬：「需求確認」、「設計」…」，名稱全部列出；沒有別的搬移時不說「其他」），套用的確認對話框也是（`impactLines`）；不是等待核准時照舊一項一行。不是等待核准的變更集伺服器不再算數量，只說會做什麼（「「摘要」從「任務」拿掉，值封存起來」）。「會動到的項目」加總搬移、封存（包含 `field_detach`）與轉換。
  - **擋住的原因**：`blockers` 的訊息逐條列出。
  - **套用**（`canApply` 時才有）：確認對話框說明會是第幾版、每一項會動到多少項目、不能一鍵還原。成功後讓專案底下的所有查詢（內容、項目清單、看板的每一欄、上層選項、變更集）、每個項目與活動、我的工作、專案清單失效，等專案內容讀回新的一版之後回到設定頁的預設區塊（`/settings/workflows`，不經過 `/settings` 的轉址，提示只唸一次）。`changeset.outdated`、`changeset.apply_blocked`（列出每一個原因）、`changeset.not_pending` 時關上對話框、在頁面上用 `role="alert"` 說明（過時的附「到設定頁重新編輯」；說明拿到焦點，「知道了」之後焦點到頁面的標題），並重新讀這份變更集與專案；`changeset.busy`（等不到鎖）留在對話框裡說「專案正在被修改，請稍後再試。」，按鈕不停用，可以再按；其他失敗也留在對話框裡。
  - **放棄**：提出的人或有 `blueprint.apply` 的人才有；確認後呼叫 reject，狀態換成「已放棄」，按鈕都不見了，焦點到頁面的標題，一直掛著的 `role="status"` 說「已放棄變更集 #N，設定沒有改變。」。放棄或套用成功之後，設定頁送出這份時記在記憶體的草稿一起清掉。
  - **回去修改**（`useReviseChangeSet.ts`）：等待核准、我提出的、而且草稿還在這個分頁的記憶體裡（剛從設定頁送出的那一份，見「設定頁」的「預覽之後回去修改」）才有。是標題下面一則 `info` 的 `Notice`（`role="none"`）加「回去修改」：頁列最多兩顆按鈕（套用、放棄），而且按下去會先放棄這份變更集，旁邊先寫清楚。不另外確認（1 步）：先呼叫 reject，成功了才換到送出時的區塊（先換頁再更新這份變更集的快取，這一頁不會先畫一次「已放棄」），不在這一頁說「已放棄」；設定頁的焦點到標題，換頁後的提示說「已放棄變更集 #N，修改還在，可以繼續改。」。換頁之前先向伺服器讀一次專案最新的內容（`staleTime: 0`，也寫進快取，設定頁掛上時就是最新的；讀不到就用手上的）：草稿的基準版本已經不是最新的，提示改說「已放棄變更集 #N。修改還在，但別人已經套用了新版本，要先以最新版本重新開始才送得出去。」，不和設定頁上方的「送不出去」矛盾。送出中按鈕是「放棄中…」並標 `aria-disabled`（不用 `disabled`：停得到，焦點留在按鈕上），再按不重送。放棄失敗就留在這一頁，用和套用被擋下同一個 `role="alert"` 的說明（拿到焦點）：過時、已經不是等待核准的照套用的做法說明並重讀，其他的說「放棄這份變更集失敗了，還不能回去修改；你的修改都還在。」加原因（等不到鎖時說稍後再試），可以再按一次。
- 時間軸的 `migrated`（`domain/activity.ts`）：「套用設定變更（第 N 版）時，狀態從「A」搬到「B」」「…「備註」被封存（原本是 …）」「…「X」從 V1 轉成 V2」，值的文字沿用時間軸既有的轉法；好幾件事時每一件一行（「搬移的內容」）。

- **密碼**那一塊多一個預設勾選的「同時撤銷所有存取權杖」（送出帶 `revokeAccessTokens`），左欄的說明：改密碼會登出其他裝置、存取權杖預設一併撤銷，沒有勾選的話到「命令列與整合」自己管理（連到 `/account/integrations`）；成功訊息寫出登出幾個裝置、撤銷幾把權杖並提醒再執行 `kumi setup`。收到任何 401 時（`auth/session.ts` 的 `handleUnauthorized`）先重問一次 `/v1/session`，還是 401 才登出：改密碼換 Cookie 的瞬間，另一個分頁送出的請求會被 401 打回；同時多個 401 只問一次，問到還登入著就把失敗的查詢重抓。
- **存取權杖**（`AccessTokensSection.tsx`，給 CLI 與腳本用的個人權杖，`internal/HANDOFF-pat-cli.md` 第 6 節）：清單與「建立存取權杖」按鈕。
  - 清單（`AccessTokenViews.tsx`，`accessTokenText.ts` 管文字）：寬窄螢幕都是 `List`（設定中心的右欄放不下六欄的表格）：名稱，第二行明文的開頭 `pmt_Ab12…`、範圍、建立、最後使用、到期，「撤銷」在最後。範圍四種都有寫「全部」，否則列名稱（讀取項目、修改項目、讀取設定、修改設定）；最後使用是相對時間或「還沒用過」；到期是日期（舊的權杖可能是「不過期」），過期的後面加「已過期」徽章；建立它的位址（`createdFrom`）有值時多一項「從 203.0.113.5 建立」。「現在」是查詢的 `dataUpdatedAt`（畫的時候不讀時鐘）。沒有權杖時一句「還沒有存取權杖。」，按鈕照舊在清單下面。第一次讀不到是 `ErrorState`（可以重試），背景重抓失敗留著清單加一行提示。
  - 撤銷（`RevokeAccessTokenDialog.tsx`）：每一列「撤銷」（名稱「撤銷「我的筆電」」），`ConfirmDialog` 的 `danger`，送出中確認鈕只標 `aria-disabled`、焦點留著、Esc 與取消不作用；失敗時對話框留著並重抓清單；成功後那一列不在了，焦點到「建立存取權杖」（`updateThenFocus`）。
  - 建立（`CreateAccessTokenDialog.tsx`，欄位在 `CreateTokenFields.tsx`，表單狀態與錯誤對應在 `createAccessTokenForm.ts`）：名稱、範圍（`CheckboxGroup` 的 `layout="column"`，預設全勾）、期限（30 天、90 天〔預設〕、1 年；沒有不過期，勾了本機代理只到 90 天）。送出前檢查名稱（空白、超過 100 字）與範圍（至少一個），伺服器的 422 依細項路徑標在欄位上，409 等寫在表單上方；焦點到第一個有問題的欄位（欄位用 callback ref 登記，畫的時候不碰 `ref.current`）。
  - 「只會顯示這一次」（`TokenSecretView.tsx`）：建立成功後**同一個** `Dialog`（標題換成「存取權杖已建立」，關上時焦點才回得到「建立存取權杖」）換成這個畫面：明文在唯讀的 `TextField`（掛上時選取、焦點在欄位）、「複製」（`navigator.clipboard.writeText`，成功說「已複製。」，失敗說「無法自動複製，請選取上面的權杖手動複製。」並選取欄位）、CLI 的用法、「完成」。明文只在這個元件的 props 裡，關上就卸下；測試確認畫面、查詢快取、mutation 快取、`localStorage`、`sessionStorage` 都找不到它。

## 項目頁

`/projects/<代號>/items/<編號>`，在 `features/item-page/`。表格的編號格、看板卡片的標題、我的工作的標題、下層項目清單都連到這裡（網址由 `work-items/itemLinks.ts` 產生）；寬螢幕一般的點擊是在清單旁邊開項目面板，內容和這一頁一樣（見「項目面板」）。

- **外殼**（`ItemPage.tsx`，讀取與分情況在 `ItemContent.tsx` 的 `useItemContent`，和項目面板共用）：同時讀項目（`useItem`）與專案內容（`useProject`，藍圖、成員、權限）。項目 404 是「找不到這個項目」、403 是「沒有權限看這個項目」，其他錯誤可以重試；專案讀不到沿用專案頁的 `ProjectLoadError`。這些只在第一次就讀不到（還沒有資料）時；已經有資料時背景重抓失敗（例如切回分頁時伺服器暫時 503），畫面與寫到一半的說明、留言都留著，上方多一行「無法更新這個項目的最新資料，畫面上可能是舊的。」（專案讀不到是專案的版本），有「重試」。網址的專案和項目對不上、或編號的寫法不是後端回的正規寫法（`smk-7`、`SMK-07`）時，用 `replace` 換到正規的網址；`useItem` 讀到不同寫法時也寫進正規編號的快取，換過去不必再讀一次。分頁標題是「編號 標題」。
- **版面**（`ItemDetailView.tsx`、`ItemPage.module.css`，閱讀頁）：頁列是位置（專案、上層、編號，`ItemHeader.tsx` 的 `itemCrumbs`；`titleInBar={false}`，分頁標題是「編號 標題」）。專案的連結：從這個專案的表格或看板連進來的（state 的 `returnTo`）回到那裡、檢視與條件照舊，其他的（我的工作、直接打網址）照這個專案上次用的檢視開（`ItemDetailView.tsx` 的 `useProjectCrumbLink`）與右邊的「更多動作」（`ItemActions.tsx`，見下面的改類型與刪除）。內容區最上面是標題區：類型與編號一行（灰字，編號是等寬字）、可以直接改的標題（h1，表格的 `TitleCell`）、建立與更新時間，下面一條細線。內容區用容器查詢（`item-page`），夠寬（52rem 以上）時分成左邊內容、右邊欄位，不夠寬就上下排；原始碼裡欄位排在內容前面，窄螢幕先看到狀態與負責人。左欄的說明、下層項目、活動與留言都以 `--reading-max` 為限，右緣對齊同一條線。整頁放在表格同一個 `ProjectTableProvider` 裡，**欄位的編輯器就是表格的格子**（含改狀態被擋時的說明與「到『成員』調整角色」），權限一樣看 `myPermissions`。
- **欄位**（`ItemFieldsPanel.tsx`）：狀態、類型、負責人、優先度、開始日、到期日、估計、上層項目（類型可以有上層、或資料裡有上層時；旁邊有「開啟」連到上層的項目頁，點擊範圍至少 `--target-min`），再加上這個類型的自訂欄位（照類型定義的順序）。不是卡片、沒有陰影：寬的時候是右邊一欄（左邊一條細線），一組一列、名稱一欄 5.5rem，面板貼在頁列下面、太長時自己捲；窄的時候在標題下面（下面一條細線），面板自己有 21rem 寬就兩組一列、40rem 就三組一列（容器查詢 `item-fields`；名稱一欄 4rem，同一欄的名稱與值上下對齊），編輯中的欄位與上層項目佔一整列；區塊標題「欄位」只給報讀軟體（`region` 的名稱不變）。勾選欄位的勾選框靠左，和其他值對齊（表格裡是置中）。面板標 `data-content-start`：寬螢幕它和說明在同一列，窄螢幕它在最上面，兩種排法都是第一筆內容。
- **說明**（`DescriptionSection.tsx`、`CollapsibleText.tsx`）：純文字，保留換行顯示（`white-space: pre-wrap`，不解析 Markdown、不用 `dangerouslySetInnerHTML`），一行最寬 `--reading-max`。超過 12 行時先收起來（CSS 的 `line-clamp`，最後一行是省略號；全文一直在 DOM 裡，報讀軟體唸得到全部），下面一顆「顯示全部」，展開後換成「收起」：按鈕的文字就是狀態，所以不另外標 `aria-expanded`（兩個都有會唸成「收起，已展開」），`aria-controls` 連到那段文字；收回時把按鈕捲回看得到的地方。超過沒有是量出來的（收起來時內容比收起來的高度高，寬度變了用 `ResizeObserver` 重量；測試環境沒有版面，量不出來就當成沒有超過）。編輯時換成文字框，一律是全文；存好之後回到收起來的樣子。有 `item.update` 時點說明的內容就進入編輯（視覺翻新；點到「顯示全部／收起」、連結，或拖曳選取文字不算；滑過時是淡底加環線、文字游標），沒有說明時整塊虛線框就是「新增說明」的按鈕；鍵盤與報讀軟體用標題列的「編輯說明」。編輯中下面一列「儲存」「取消」，結束編輯後焦點回到入口（有說明是「編輯說明」，沒有是「新增說明」那一塊；細節見規範 8.3「說明」）。沒有權限的人點了沒有反應。編輯用 `PlainTextArea`：Ctrl+Enter 或 ⌘+Enter（或「儲存」）送出、Esc（或「取消」）放棄；整段空白是清掉（送 `null`）；沒改不送；失敗時留著輸入，訊息用 `aria-describedby` 連到文字框。剩下不到一成的字數時顯示「還可以輸入 N 個字」（上限 `MAX_DESCRIPTION_LENGTH`，在 `cells/drafts.ts`）。草稿（`lib/useDraft.ts`，規範 8.3「草稿」）：編輯中、而且和伺服器的內容不同時才存進 `sessionStorage` 的 `draft.description.<編號>`；回到這個項目（換頁、重新整理）時進入編輯、還原內容，不搶焦點，上面一則 `RestoredDraftNotice`（`info`、`role="status"`，先掛空的再填字）「已還原上次沒送出的內容。」與「捨棄」（名稱「捨棄還沒儲存的說明」：回到伺服器的內容、留在編輯中、焦點到文字框）。存著的草稿和伺服器現在的內容一樣時不還原。草稿連同打草稿時伺服器上的說明一起存（`useDraft` 的 `withBase`，JSON `{ text, base }`；讀到舊的純文字草稿照樣還原）：還原時伺服器上的說明已經和它不同（別人在你離開之後改過；先用手上的資料畫、重抓到新的說明時也會換），提示換成警告「說明在你離開之後被別人改過；這是你上次沒送出的內容，儲存會蓋掉新的說明。」，按鈕是「看伺服器上的內容」（名稱「看伺服器上的內容（捨棄還沒儲存的說明）」：就是捨棄，文字框換成新的說明）。儲存成功、取消（Esc 或「取消」）、沒改就儲存時清掉。以項目編號為 key 重新掛上，換了項目不會帶過去。
- **下層項目**（`ChildItems.tsx`）：有類型的 `parents` 包含這個類型時才有。用 `useProjectItems` 帶 `parent` 讀（一頁 50 個，照編號），寬窄都是 `components/List` 的清單列（`<ul aria-label="下層項目">`）：第一行編號與標題（一行、省略號），第二行和專案的項目清單同一組：狀態（`StateBadge`）、負責人（頭像加名字，頭像是裝飾）、到期日（有設才有），欄位與只給報讀軟體的說法在 `work-items/itemListMeta.tsx`；整筆是一個連結，名稱是這一筆所有的文字（「AGY-5 首頁切版 狀態：進行中 負責人：範例成員 到期：2026/11/30」，沒有負責人時唸「沒有負責人」、畫面上不佔位置）。寬螢幕一般的點擊在這一頁旁邊開那個下層的面板（`page` 版面），面板裡的下層清單點了是把面板換成那一個；清單列是共用的 `ListRow`（連結沒有 `onClick`、`aria-current` 可以給），所以在外層用捕獲階段的 `onClickCapture` 攔點擊、畫好之後在開著的那一筆標 `aria-current`（`useChildPanelLinks`）。第一次載入是骨架（「正在載入下層項目…」只給報讀軟體），「載入更多」接在清單下面：載入中是「載入中…」並標 `aria-disabled`（不用 `disabled`：有焦點的按鈕一停用，焦點就掉回頁面本體），載完最後一頁按鈕不見時，焦點放到新載入的第一筆（載入時焦點被移到別處就不搶）。全部載入時標題旁顯示「N / M 完成」。有 `item.create` 時清單下面一列快速新增（`ChildQuickAdd.tsx`：直接用表格上方快速新增的 class（`item-table/QuickAddItem.module.css`），只多了排不下時折行——欄位 `size="sm"`、標籤視覺上隱藏、提示文字「輸入標題後按 Enter 新增」，類型多於一種才要選；「已新增 AGY-9。」接在按鈕後面），新的接在清單最後。快速新增與表格上方的共用 `item-table/useCreateItem.ts`。
- **改類型與刪除**在頁列右邊的「更多動作」（`ItemActions.tsx`，共用的 `Menu`，按鈕與選單的名稱是「AGY-3 的更多動作」）：「改類型」（有 `item.update`、而且專案有兩種以上的類型）、「刪除」（有 `item.delete`，危險色、排最後、前面一條分隔線）；一件都不能做時沒有這顆按鈕。選了之後選單先關上、焦點回到「更多動作」，才開對話框，對話框關上後焦點回到「更多動作」。對話框放在選單外面（選單關上時卸下的是浮層）。
- **刪除**（`DeleteItemDialog.tsx`、`useDeleteItem.ts`）：確認對話框說「「…」刪除之後不會出現在任何清單、看板與我的工作；活動紀錄留著。這一版還沒有復原的畫面。」。下層清單還在讀的時候，確認鈕先停用但停得到（`aria-disabled`），上方說「正在確認有沒有下層…」（`ConfirmDialog` 的 `blockedReason`，用 `aria-describedby` 連過去），不先出現能按的刪除鈕、讀到有下層才突然換掉。已經知道有下層（`knownChildren.ts`：類型可以有下層時，讀下層清單同一個查詢鍵，不會多發請求）就不給刪除的按鈕，說明「要先刪除它們，或把它們的上層項目換掉」並列出下層（連到各自的項目頁，`ChildLinks.tsx`）；下層只載入了第一頁時數量說「還有至少 50 個下層項目」；伺服器回 409 `item.has_children`（別人剛加了下層）時換成同樣的說明（`role="alert"`），列出 `details` 的那些下層，並重新讀下層清單。成功後先把它從這個專案每一份已經載入的清單（表格、看板的欄、下層清單）與我的工作的快取拿掉、全部標成過期（`itemCache.ts` 的 `removeItemFromCache`），再 `replace` 回到專案頁；離開項目頁之後才丟掉它與活動的快取（正在看的那一頁才不會先重抓出一個 404）。伺服器回 404 `item.not_found`（別人剛刪掉）當成已經刪除，照成功的路徑走。其他失敗留在對話框裡顯示伺服器的訊息。
- **改類型**（`ChangeTypeDialog.tsx`、`ChangeTypePreview.tsx`、`domain/itemTypeChange.ts`）：對話框選新的類型（其他的類型，預設不選、不能送出），選了之後一直掛著的 `aria-live` 區域（「改了之後」，選單用 `aria-describedby` 連過去）先說明：
  - 狀態怎麼搬：照伺服器的三條規則（`internal/HANDOFF-week4-admin-ops.md` 3A.1）在前端算，並說出用了哪一條。新流程有同 key、而且同類別的狀態就留著（「狀態維持「開發」。」）；否則新流程不限制轉換（`transitions` 省略）、而且自己有 `item.transition`（`myPermissions`）時，搬到新流程第一個同類別的狀態，沒有就第一個（「狀態會從「內部驗收」搬到「進行中」：「任務流程」沒有「內部驗收」。」；同 key 但類別不同時說「「任務流程」的「關閉」是另一個類別」）；其他情況回到新流程的第一個狀態，說清楚為什麼（「狀態會從「進行中」回到起始狀態：「交付流程」有限制轉換，改類型之後從起始狀態「需求確認」開始，再照一般的方式改狀態。」「…：你沒有「改變狀態」的權限，改類型之後從起始狀態「待辦」開始。」）。改類型才不會變成繞過轉換限制的捷徑。
  - 哪些有值的自訂欄位會封存：新類型沒有的，舊類型的欄位照舊類型的順序，其他有值的照 key 排序（和伺服器 `TypeChange.cs` 記進活動的順序一樣），值照表格的寫法，長文字不顯示內容。
  - 上層不允許（新類型不能有上層；或上層的類型不在新類型的 `parents` 裡——對話框打開時才讀上層那一個項目）與已經載入的下層不能掛在新類型底下（列出它們）。下層只載入了第一頁時加一句「只檢查了前 50 個下層，送出後以伺服器為準。」。

  前端看得出來會被擋下時，「改類型」停用但仍然停得到（`aria-disabled`，`DialogFormActions` 的 `blockedReasonIds`），用 `aria-describedby` 連到上層或下層的那段說明，按了不送出。伺服器回 422（`item.parent_not_allowed`、`item.children_not_allowed`、`item.unknown_type`；不管代碼是什麼，`details` 裡有 `children/` 開頭的路徑就列出那些下層）、403、404 時留在對話框裡說明。成功後和其他修改一樣用回傳的項目換掉每一份快取（`replaceItemInCache`：表格在原位換掉、看板的欄從舊流程搬走、項目頁、活動重抓），對話框關上、焦點回到「更多動作」。
- **活動與留言**（`ActivitySection.tsx`、`ActivityEntry.tsx`）：由舊到新，「載入更多」接後面的頁；第一次載入是骨架。「載入更多」和下層項目的一樣：載入中是「載入中…」並標 `aria-disabled`（不是 `disabled`，焦點留在按鈕上，再按不重送）；載完最後一頁、按鈕跟著不見時，焦點到新載入的第一筆（以按下時已經有的編號判斷，那一筆給 `tabIndex=-1`；載入時使用者把焦點移到別處就不搶）。左邊一條細線串起每一筆，線上是作者的頭像（`Avatar` 的 `sm`，旁邊有名字，是裝飾）。每一筆是人、做了什麼、相對時間（`title` 是完整時間；「現在」用這份資料讀回來的時間，整條一致；不到一天說幾小時前，一天以上照使用者所在地的日曆日算，例如週一深夜的事週三一早看是「前天」）。重抓只會重抓已經載入的頁數，所以 `api/activityPages.ts` 在重抓最後一頁時往後接著讀：原本已經讀到最新的就讀到最新（剛做的修改跨過頁界也看得到，不會藏在「載入更多」後面）；最後一頁有伺服器那一頁沒有的（剛送出的留言）就讀到它出現。文字在 `domain/activity.ts`：欄位名稱用藍圖的（核心欄位用中文），值照表格的顯示方式轉（人員編號換成成員名稱，查不到是「查不到的人」；選項 key 換成名稱；優先度、日期、數字、金額），說明與長文字只說「修改了」，勾選說「勾選了／取消勾選」，從沒有到有說「設為」，清掉說「清除了（原本是…）」，一次改好幾個欄位時每個欄位一行。改狀態與搬移的狀態名稱看**當時**的類型的流程：`domain/activity.ts` 的 `typesAtEntries` 從已載入的 `type_changed` 往回推每一筆當時的類型（在某筆改類型之前用它的 `from`，之後用它的 `to`；一筆都沒載入時用項目現在的類型），改過類型的項目，更早的改狀態才不會只剩 key。改類型是一句話：「把類型從「需求」改成「任務」，狀態從「開發」搬到「進行中」；「報價金額」（原本是 $1,200）的值封存起來」（`typeChangeDescription`：舊狀態看舊類型的流程、新狀態看新類型的流程；被刪除的類型與它的狀態只剩 key）。留言是一塊有細線外框的內文（不加陰影），系統事件是一行小字，看得出差別。新的一筆出現時，`role="status"` 的隱藏文字報讀（第一次載入不唸）：自己送出的留言唸「已送出留言」；其他的唸簡短的摘要（`activityAnnouncement`：留言只唸開頭 40 個字，好幾個欄位只說「修改了 N 個欄位」，太長的句子截短）；一次多好幾筆時說「多了 N 筆活動」。
- **留言**（`CommentForm.tsx`）：有 `comment.create` 才有。平常是一行（文字框一列高、至少 `--control-height`，說明與「送出留言」收起來），焦點進到留言框（文字框或按鈕）才展開成三行加「送出留言」；是同一個文字框變高，焦點不會掉。打了字、送出中、失敗時一直展開（用滑鼠點「送出留言」時文字框先失去焦點，也不會先收起來、按鈕跟著不見）；空白時焦點離開就收回。收起來的說明是 `display: none`，照樣用 `aria-describedby` 連著。空白不能送；Ctrl+Enter 或 ⌘+Enter 送出；送出中按鈕是「送出中…」、文字框唯讀（仍然停得到）。從「送出留言」送出（點一下或在按鈕上按 Enter）時先把焦點放回文字框再送：送出中按鈕會停用，有焦點的按鈕一停用焦點就掉回頁面本體。成功後清空，焦點留在文字框可以接著寫（焦點在框裡，所以留言框照樣是展開的）；回傳的活動先接在時間軸最後，馬上看得到（`activityCache.ts`）：先取消正在進行的活動重抓（那是送出之前發出的，回來會把留言蓋掉），接上之後再重抓一次，排到伺服器給的位置；之後載入的頁又帶到它時以編號去重。失敗時留著內容並顯示訊息。草稿：不是空白的內容邊打邊存進 `sessionStorage` 的 `draft.comment.<編號>`，回到這個項目時還原（留言框展開、不搶焦點），框上面「已還原上次沒送出的內容。」與「捨棄」（名稱「捨棄沒送出的留言」：清空、焦點到文字框）；送出成功（送出中換了頁也算：清除寫在 `useMutation` 的回呼上）、捨棄、登出時清掉。送出中換了頁又回來時，畫面上是另一個留言框、還原了同一段字（`commentPosting.ts`）：這個項目還有留言在送（`mutationKey` 加 `useIsMutating`）就當成送出中，不能再送一次；送出成功時通知同一個項目現在掛著的留言框，框裡還是送出的那一段就清空、收起「已還原」，已經改成別的字就留著（草稿也只在還是那一段時才清）。讀寫失敗當成沒有草稿。
- **Markdown 與提及**（PM-1 協作；規範 7.4、8.3「提及」）：說明（`CollapsibleText`）與留言（`ActivityEntry`）用 `components/Markdown` 顯示：`react-markdown` 10.1.0、`remark-gfm` 4.0.1、`remark-breaks` 4.0.0（MIT，`package.json` 固定版本）。渲染器（`MarkdownContent.tsx`）用 `React.lazy` 延後下載（約 167 kB，`Markdown.tsx` 的 `Suspense` 備用畫面是原樣的純文字），主程式檔不變大。不開原始 HTML、連結只認 `http`、`https`、`mailto`、`mention`（`markdownUrls.ts` 的白名單，不認的 `urlTransform` 回 `null`，連結只剩文字）、外部連結 `target="_blank" rel="noopener noreferrer"`、圖片不載入（畫成連結）；`remarkMentions.ts` 把 `@[名稱](mention:編號)` 前面的 `@` 吃掉，`a` 的覆寫把它畫成「@名稱」（名稱查 `useMentionNames`：專案目前的成員，找不到用連結的文字）。內容裡的標題壓在 h4 以下。`CollapsibleText` 的「顯示全部」同時觀察外層與裡面那一層（`Markdown` 外面那個一直在的 `div`）的大小。`PlainTextArea` 多了 `mentionMembers`（留言框與說明的編輯器給專案成員，不含自己）與一行「支援 Markdown；輸入 @ 提及成員」；打 @ 的邏輯在 `mentions/`：`mentionText.ts`（`findMentionTrigger`、`filterMembers`、`insertMention`，純函式）、`mentionKeys.ts`（按鍵對到動作）、`useMentionInput.ts`（狀態、aria、輸入法）、`MentionList.tsx`（`Floating` 裡的 listbox）。文字框一直是 `textbox`（`<textarea>` 不能改成 combobox，`aria-expanded` 也不屬於 textbox）：清單打開時多 `aria-controls`、`aria-activedescendant`，靠 `aria-live` 說話；清單不列自己（`useMentionCandidates`）；焦點狀態不只靠 `onFocus`（`onChange`、`onSelect` 補看 `document.activeElement`）。渲染器的元件函式固定（名稱走 Context）、`memo`、`useMentionNames` 內容沒變回傳同一個 `Map`，重新渲染不拆 DOM；延後載入失敗時 `MarkdownLoadBoundary` 讓它顯示純文字。
- **關注**（`FollowButton.tsx`）：項目頁頁列（「更多動作」前面）與項目面板標題列（以編號為 key）各一顆，`aria-pressed`、名稱與字固定是「關注」（面板的標題列只有圖示，`isCompact`；按下是選取的底加實心鈴鐺），原因與效果寫在 `aria-describedby` 與 `title`（`subscriptionDescription`）；讀不到狀態時不放；`canFollow: false`（不是專案成員）時 `aria-disabled`、說明「加入專案成員才能關注。」；自己留言、指派、改說明之後延遲 2.5 秒重抓關注的狀態（`notificationCache.ts` 的 `refreshSubscriptionLater`）。
- 在項目頁的修改與改狀態都走 `useItemCommand`，所以表格的快取、項目、活動一起更新（見上面「格內編輯」）。

## 項目面板

`features/item-page/` 的 `ItemPanelHost.tsx`、`ItemPanel.tsx`、`ItemPanelContext.tsx`、`useItemPanelController.ts`、`itemSequences.ts`，照規範 8.3「項目面板」。

- **在哪裡**：專案頁（表格與看板共用一個，`layout="fill"`，切換檢視時面板不重新掛上）、我的工作（`page`）、項目頁的下層項目（`page`）。放面板的那一頁用 `ItemPanelHost` 包住清單（`components/SidePanel` 的 `SidePanelLayout`）。
- **網址就是狀態**：開著的項目記在 `item` 參數（`/projects/AGY?view=board&item=AGY-3`），和 `view`、篩選參數並存：切換表格與看板（`ProjectWorkspace` 的 `ViewTabs`）、換篩選或排序（`useItemTableState`、`useBoardFilters` 的 `keepPanelItem`）都帶著它，換檢視、換條件不會把正在看的項目關掉。查詢字串用 `itemLinks.ts` 的 `searchWithPanelItem` 換掉或拿掉 `item`，其他參數原封不動（不重新編碼）。從清單打開是新的一筆瀏覽紀錄（帶 `state: { itemPanel: true }`），上一頁關上面板；上一個、下一個、面板裡的上層與下層、清單上點另一筆都是換掉目前這一筆。關閉（按鈕或 Esc）時看到那個 state 就用上一頁回去，沒有（網址直接帶著 `item` 打開、切換過檢視、換過條件）就換掉目前的紀錄、拿掉 `item`。
- **清單上的連結**（`useItemPanelLink`）：`href` 照樣是整頁的項目頁；只攔左鍵、沒按修飾鍵、寬螢幕的點擊（`isPlainLeftClick`），⌘／Ctrl、Shift、中鍵照瀏覽器原本的行為。開著的那一筆標 `aria-current`，選取的底色照它選（表格那一列、看板的卡片、我的工作那一列、下層清單那一筆，`--color-selected`，連結或標題是強調色，滑過時也維持；沒有色條，也不另外畫強調色的外框）。新增之後的「開啟」（`item-table/OpenItemContext`）也開面板。窄螢幕（48rem 以下）不用面板：連結照常換頁；網址帶著 `item` 時（分享來的、開著面板時視窗變窄）換到整頁的項目頁（`ItemPanelHost` 的 `useCompactRedirect`）：清單那一筆先變成不帶 `item` 的（這一筆是從清單打開面板時新開的就用上一頁退回去，不是才 `replace`），整頁再 push 一筆、帶著拿掉 `item` 的 `returnTo`：上一頁回到清單，瀏覽紀錄裡不多一筆一樣的清單。
- **內容**就是項目頁的內容：`ItemContent.tsx` 的 `useItemContent`（讀項目與專案、找不到、沒有權限、讀不到）、`useItemScope`（專案的 Context 與成員對話框）、`ItemArticle`（標題區、欄位、說明、下層、活動），整頁與面板共用。面板以項目自己的專案為準（`followItem`：我的工作跨專案，網址上只有編號；先用清單的專案或編號的前綴讀，讀到項目之後換成它的），找不到、沒有權限在面板裡說明。面板窄，版面照容器查詢排成一欄。面板的標題列是 h2（「任務 AGY-3」，編號是等寬字），內容的標題跟著降成 h2（`ItemHeader` 的 `headingLevel`），一頁只有一個 h1；各區塊的標題（欄位、說明、下層項目、活動與留言）在面板裡是 h3、整頁是 h2（`ItemPanelContext.tsx` 的 `SectionHeading`）。
- **標題列**：上一個、下一個（`IconButton`，沒有時 `aria-disabled`；Alt+↑／↓ 是 `SHORTCUTS.itemPrev`／`itemNext`，沒有時不聽、按鍵交還給瀏覽器）、「更多動作」（改類型、刪除）、「展開成整頁」（連結，帶 `returnTo`）、關閉。上一個、下一個照清單登記的順序（`useItemSequence`：表格一份、看板每一欄一份、我的工作一份、下層清單一份，都是已經載入的、照畫面的順序；面板裡的清單不登記）。換項目時面板不重新掛上，只有內容以編號為 key 換掉（編輯中的格子、草稿重新開始）、面板捲回最上面；焦點在標題列的按鈕上就留著，原本在換掉的內容裡（按了面板裡的連結、焦點在欄位上按 Alt+↓）就到面板的標題。清單上那一筆捲到看得到的地方（`lib/revealCell.ts`：一般是 `scrollIntoView` 的 `nearest`，表格的編號是固定欄，只修正直向，橫向捲過去的表格不會被捲回來）。
- **關上之後焦點**回到清單上那一筆（`useItemPanelController` 的 `useListFocus`：面板不見時焦點跟著不見才放，關閉、Esc、上一頁都一樣）；那一筆不在了（刪除）就交給換頁後的提示（焦點到頁面的標題）；清單上本來就沒有那一筆（網址直接帶著 `item`、重抓之後被拿掉）時回到清單上最後開的那一筆，都沒有就到頁面的標題，不掉回頁面本體。
- **在面板裡刪除**：`useDeleteItem` 在面板裡（`useIsInItemPanel`）時回到拿掉 `item` 的目前網址（`ItemPanelValue` 的 `closeWith`：打開面板的那一筆先用上一頁退掉，再 `replace` 帶上 `notice`，瀏覽紀錄裡不多一筆一樣的清單），清單上方出現「已刪除 …」（專案頁、我的工作、項目頁都有 `ArrivalNotice`），焦點到頁面的標題。
- **最近看過的項目**：項目頁與面板顯示一個項目時記下（`useRecordRecentItem` → `features/jump/recentItems.ts`）。
- **從整頁回到清單**（`returnFocus.ts`）：清單上的連結帶著那一筆瀏覽紀錄的 `location.key`（`useItemPageEntry` 的 `fromEntry`）；整頁的項目頁顯示時以它為鍵、把編號記在 `sessionStorage`（最近 20 筆，重新整理之後再上一頁也找得到），用上一頁回到那一筆紀錄時，等清單畫出那一筆就把焦點放上去（面板開著、焦點已經在別處時不搶）。

## 我的工作

`features/my-work/`：指派給我、還沒結束的項目，分組顯示（見下面的「分組」）。項目的標題連到它的項目頁；寬螢幕一般的點擊在旁邊開項目面板（`ItemPanelHost layout="page"`），面板用那個項目自己的專案內容，上一個／下一個照畫面上分好組的順序（一組接著一組）；在面板裡刪除之後留在這裡，「已刪除 …」出現在清單上方（`ArrivalNotice`）。清單頁：寬螢幕是每一組一張表格（所有的組在同一個 `TableScroll layout="page"` 裡，見下面的「分組」），整頁捲動、表頭黏在頁列下面；比內容區窄時（項目面板開著、48～64rem 而且側欄展開；1024 寬加上展開的側欄放得下）所有的組一起退回橫向捲動，那時表頭不黏（`components/Table` 的 `data-overflowing`）、編號與標題固定在左邊。窄螢幕是和專案同一套的清單（`components/List`，跟著整頁捲）：第二行是狀態、專案、優先度、到期日（後兩個有設才有，見「外框與每一頁的骨架」的窄螢幕清單）。第一次載入是骨架。已經有清單時背景重抓失敗，留著清單、多一行提示（專案清單、人員頁、側欄的專案連結也一樣）。沒有項目時（`MyWorkEmpty.tsx`）說這裡會出現什麼，下一步是「到專案看看」（連到專案清單）；能開專案的人（組織的擁有者與管理員）多一顆「新增專案」，當場打開和專案清單同一個對話框，關上後焦點回到這顆按鈕。專案清單沒有專案時不另外加按鈕：頁列上已經有「新增專案」，空白狀態的說明指向它（同一頁兩顆同名的按鈕，報讀軟體分不出來）。

- **分組**（`myWorkGroups.ts`，`domain/dates.ts` 的 `groupByDue`）：預設照急迫程度——已過期、今天、這一週、之後、沒有到期日（只看到期日、不看狀態；一週從週一開始，照使用者所在地的日期，「今天」在畫面打開時決定一次）。這一頁看過（面板讀過）或改過的列，分組與排序看的是第一次記下時清單裡的樣子（`useMyWorkRows.ts` 的 `MyWorkRow`：顯示最新的一份、停在原組原位），補填了到期日也不會換到別組的表格（換組會連同格子與補填的對話框一起卸下），直到重新整理或離開再回來；工具列的 `NavTabs`「分組」可以切成「依專案」（網址的 `group=project`，照專案代號排、組名是專案名稱，不再有「專案」那一欄；預設的分組不寫進網址；換分組時其他參數照留，開著的面板不關）。空的組不出現，組內照到期日再照編號（專案代號，再照號碼的數字大小）。每一組一個 h2（組名與數量，報讀軟體唸「已過期 2 項」，`MyWorkGroupSection.tsx`），下面是以組名為名稱的表格（寬螢幕，`MyWorkGrid.tsx`）或清單（窄螢幕）。寬螢幕所有的組放在同一個 `TableScroll`（區域「我的工作」）裡、欄寬固定（`table-layout: fixed`；寬度是 `MyWork.module.css` 裡 `.groupsScroll` 的區域變數 `--my-work-*`，編號欄和專案的表格一樣 6.5rem，最小寬度用 `calc` 加總）：各組的欄對齊。欄的順序是編號、標題、狀態、優先度、到期日、專案；最小寬度 46rem（依專案分組沒有專案欄，39rem，`data-show-project`），1024 寬加上展開的側欄放得下。比內容區窄（項目面板開著、48～64rem 而且側欄展開）時一起退回橫向捲動、只有一條捲軸：最先捲走的是最後面的專案，編號與標題固定在左邊（`.pinKey`、`.pinTitle`，捲動時標題欄右邊一條細線、`scroll-padding-left` 讓出那兩欄），組的標題也黏在左邊。格子左右的內距是 `--space-3`（和狀態格裡的按鈕對齊）。編號、標題、專案名稱放不下用省略號，完整的文字在 `title`。第一筆內容（`data-content-start`）是第一組的第一列，寬螢幕實測 173～174px（1024、1280、1440），手機 147px。工具列在讀不到、沒有工作時不出現。
- **狀態可以直接改**（寬螢幕）：狀態那一格是表格的 `StateCell`，每一列包在那一列自己專案的 `ProjectTableProvider` 裡（`useItemScope`：藍圖、權限、「今天」與成員對話框；我的工作跨專案，不能拿第一個專案的）。沒有 `item.transition` 的專案是唯讀的文字；專案內容還沒讀到時先顯示狀態類別。被擋下時的說明與補填都是 `StateCell` 自己的（和表格一樣），只有補填完成的那一句交給這一頁（見下一點）。點那一格、選新的狀態，2 步、不換頁。窄螢幕照規範 7.1 點進項目頁改。
- **改成完成或取消的留在原位**（`useMyWorkRows.ts`）：改好的項目只寫進單一項目與專案的清單（`itemCache.ts`），我的工作的快取只標成過期、內容不變；這一頁訂閱快取，把單一項目快取裡不比清單舊的那一份換上去（不重抓也看得到新的狀態，項目面板裡改的也一樣），並記住這次看的期間寫進的每一份。改成完成或取消的那一列留在原位（`data-settled`：字換成次要的字色、優先度也變淡、標題劃掉，狀態的標籤維持原樣；不用透明度，那一列還可以改回去、開面板；劃掉的標題滑過時照樣是強調色加底線），工具列右邊一直掛著的 `role="status"` 說「AGY-3 已經完成，重新整理後會離開清單。」（取消類是「已經取消」，只說最近的一個；放在工具列上，訊息出現時清單不會被推動；`myWorkStatus.ts`）。補填完成的那一句只唸一次：這一頁提供 `features/item-table/cells/stateAnnouncement.ts` 的 `StateAnnouncementContext`，狀態格（表格與項目面板裡的）把「已填好…，AGY-4 已移到…」連同移好的項目交過來、自己不掛 status；它是最新的事就由工具列的 status 說，移到完成或取消的合成一句「已填好「到期日」，AGY-4 已移到「結案」，重新整理後會離開清單。」（那一列之後又改過、或更晚有別的項目改成完成時說最新的那一句）。背景重抓之後伺服器不再給它也照樣留著，重新整理或離開再回來才不見；改回還沒結束的狀態就恢復原樣、說明拿掉。
- **鍵盤**（規範 8.3「清單的鍵盤操作」；`MyWorkGrid.tsx`）：寬螢幕所有組的表格合起來只有一個 Tab 停駐點：`lib/useRovingGrid.ts` 掛在包住所有組的那一層，每一列帶 `data-row-key`，`TableScroll` 給 `isFocusable={false}`（還有 `frame={false}`：上下的細線畫在每一張表格上）。從分組的切換 Tab 一次進到第一組的第一格、再一次就離開；上下鍵跨過組時走過下一組的表頭；狀態格的 Enter／F2 進入編輯、Esc 回到格子，和專案的表格一樣。每一張表格的 `aria-describedby` 是同一段操作說明（`features/item-table/tableHint.ts`；沒有任何專案能改狀態時不提編輯；都有調欄寬的那一句）。測試在 `MyWorkKeyboard.test.tsx`。
- **欄寬**（規範 7.1「欄寬」、8.3「我的工作」；`MyWorkGrid.tsx`、`myWorkColumns.ts`）：所有組共用一組欄寬，每一組的每一欄表頭都有把手（`ResizableHeader`），拉哪一組都是同一欄、一起變（拉過的寬度換掉 `MyWork.module.css` 的區域變數，設在包住所有組的捲動區塊上，`myWorkVariables`；照內容調整量所有組的格子）。沒拉過的欄是原本的區域變數（我的工作原本就是固定的寬度，不照內容量）。標題欄沒拉過時照舊吃掉剩下的寬度，拉過之後是那個寬度（換掉的是 `--my-work-title-min`：固定欄的位置、最小寬度、捲動讓出的寬度都跟著），畫的時候只夾最小（沒拉過時它吃掉剩下的寬度、可能比 32rem 寬，從那裡往窄拉一點的寬度要留著），上限是表格寬度（包住捲動區塊的容器 `.gridFrame`，`container: my-work-table / inline-size`，`100cqi`）減掉編號欄與 `--my-work-scroll-reserve`（8rem）——開著面板、側欄展開時固定欄不會蓋滿畫面（實測 1440、面板開著、側欄展開：容器 705、標題 480 被夾到 473；側欄收起：容器 929、標題 480），最後多一個空的欄吃掉剩下的寬度。記在 `localStorage` 的 `my-work.widths`（`MyWorkPage` 建 store，工具列與表格共用）。已經記住、而且是這一頁有的欄才算拉過（`myWorkColumns.ts` 的 `hasSavedWidths`，看 store 的 `saved`：拖曳中的暫時值與別的版本留下的鍵不算），拉過才有工具列右邊的「重設欄寬」（寬螢幕；`ghost`、`sm`），按了回到預設、按鈕跟著不見，焦點到頁面的標題（`updateThenFocus`）。值放不下時一行、用省略號（到期日的日期先縮、「已過期」留著；狀態那一格不裁：浮起來的編輯器要長出格子）。測試在 `MyWorkColumnWidths.test.tsx`。

## 共用元件

在 `src/components/`，一個元件一個資料夾（`.tsx`、`.module.css`、`.test.tsx`）：`Avatar`、`Badge`、`Button`、`CheckboxField`、`CountBadge`、`DatePicker`、`Dialog`、`Field`、`Floating`、`FormAlert`、`Icon`、`IconButton`、`List`、`Menu`、`NavTabs`、`Notice`、`PageBar`、`PageLayout`、`Popover`、`Select`、`SidePanel`、`Skeleton`、`StatusPage`、`StatusViews`、`Table`、`Toolbar`，加上 `DocumentTitle.tsx`。長相與用法的規則在 `docs/DESIGN.md` 第 7 節；新畫面先找這裡，沒有才做新的。每一個都在 `/design` 展示頁看得到。

- **`Icon`**：語意名稱（`add`、`more`、`stateDone`…，`IconName`）對到 lucide 的圖示，名稱打錯型別檢查會擋。一律 `aria-hidden`，16 或 20px，顏色跟著文字；`data-icon` 是語意名稱。要新的圖示就加進 `Icon.tsx` 的對照表。
- **`IconButton`**、**`IconLink`**：只有圖示的按鈕；`label` 同時是 `aria-label` 與 `title`。外觀沿用 `Button` 的 `ghost`／`secondary`，`md`／`sm` 是正方形。`IconLink` 是長得一樣的連結（`to`、`state`），要的是換頁時用（項目面板的「展開成整頁」：⌘／Ctrl 點開新分頁、複製連結都靠它）。
- **`Button`**、**`Field`**（`TextField`／`SelectField`／`FieldShell`）：次要按鈕與輸入框的外框是 `--color-control-border`（對比 3:1）；欄位的錯誤前面是錯誤圖示。`SelectField` 就是包了標籤的 `Select`（見下一點，`options` 必給）。`size="sm"` 是工具列與表格列上的高度（`--control-height-sm`，標在控制項的 `data-size`；原生的 `size` 屬性不開放），`isLabelHidden` 讓標籤只給報讀軟體（`global.css` 的 `visually-hidden`），只用在意思由選項文字、提示文字或圖示帶出來的地方。`TextField` 的 `leadingIcon`（`IconName`）是輸入框開頭的裝飾圖示（`aria-hidden`），疊在輸入框裡垂直置中、高度跟著 `size`，輸入框的左內距讓出位置：工具列的搜尋框（`SearchField`）與快速跳轉的放大鏡都用它，功能的 CSS 不再自己定位。控制項不是這兩種的欄位（補填對話框裡表格的編輯器）用 `FieldShell`（看得到的標籤、說明、錯誤與 `describedBy`；控制項自己帶標籤時 `hasOwnLabel`），輸入框與多行文字框的長相用 `fieldControlClassName`（`'input'`／`'textarea'`，和 `TextField` 同一套；下拉直接用 `Select`，它自己有兩種大小）。`Button` 的長相給連結用時是 `buttonClassName`。日期用 `DatePicker`／`DateField`（視覺翻新：自己畫的日曆，取代原生的 `<input type="date">`；`DateField` 是包了標籤的 `DatePicker`，像 `SelectField` 之於 `Select`；鍵盤、打字的格式與長相見規範 7.3「日期」）。
- **`PasswordField`**（`components/Field/PasswordField.tsx`，帳號安全那一輪，規範第 7 節）：密碼欄位，長相、標籤、提示與錯誤和 `TextField` 同一套（`FieldShell`），右端一顆和輸入框一樣高的切換按鈕：名稱「顯示＋標籤」（「顯示新密碼」）、`aria-pressed`、圖示 `showPassword`／`hidePassword`。一律關掉拼字檢查、自動大寫與自動修正。我的帳號與重設密碼用它；`/design` 有一般、有錯、停用三種。
- **`Select`**（自訂控制項 P0～P3，規範 7.3）：從幾個選項裡選一個值，取代原生的 `<select>`。按鈕是 `role="combobox"`，名稱一定要另外給：`aria-label` 或 `aria-labelledby` 至少一個（`SelectProps` 是聯集型別，沒有名稱過不了型別檢查），或用 `SelectField`；打開是 `Floating` 裡的 `listbox`（名稱和按鈕一樣）。沒有篩選框時焦點一直在按鈕上，反白用 `aria-activedescendant`；在清單上（包括外框與內距，`Floating` 的 `keepsAnchorFocus`）按下滑鼠不會帶走焦點；滑鼠左鍵按下按鈕就把焦點放到按鈕上（Safari 點 `<button>` 不給焦點）。選項 `SelectOption`：`value`、`label`、`leading`（前面的小圖，裝飾；選到時按鈕上也畫）、`disabledReason`（`aria-disabled`、停得到、原因寫在第二行並用 `aria-describedby` 連過去；寫短語，完整的說明放在清單外面）、`startsGroup`（前面一條細線，用外框畫）、`keywords`（篩選時也比對，人員的 Email）。值只有明確選了才變：`onChange`（值變了才叫）、`onPick`（每次選都叫，在後面）；沒選就關上是 `onDismiss`（`escape`、`tab`、`outside`、`scrolled`（按鈕被捲出畫面）、`toggle`）。`onBlur` 只在焦點離開整個下拉時叫（按鈕與篩選框之間移動不算）。鍵盤照規範 7.3 的表（`useSelect.ts`、`selectKeys.ts`）：關著時 Enter、空白鍵、↑／↓、Home／End、打字是打開；開著時方向鍵、Home／End、PageUp／PageDown、打字只移動反白，Enter、空白鍵選，Esc 關上（不往外傳），Tab 關上照常往下走；關著時沒處理的按鍵交給 `onKeyDown`；輸入法選字中的不算。`disabled` 打不開；`aria-disabled` 停得到、打不開；`aria-busy` 打得開、選了不收；`isOpenInitially` 掛上就打開（格子）。`placeholder` 是 `value` 對不到任何選項時按鈕上的灰字（「選擇人員」「選擇狀態」，讀取中是停用加「載入中…」）；「所有類型」這種本身就是一個選擇的，是真的選項；「還沒選」不做成清單裡的選項。`size` 是 `md`／`sm`；`width` 是 `fill`（預設，撐滿欄位）／`content`（照目前的值、8～16rem，標在 `data-width`：工具列、設定頁的列上；`SelectField` 的 `size="sm"` 加 `isLabelHidden` 自動是它）。清單經過 `Floating` 的 `matchAnchorWidth`：至少和按鈕一樣寬（寬度要執行時才量得到，`style` 只准在 `Floating.tsx`），貼近右緣時照這個寬度往左推；最高 18rem，捲到頭不連帶捲動後面（`overscroll-behavior: contain`）；反白的捲到看得到（定位完成、`maxHeight` 套上之後再捲一次：`Floating` 的 `onPositioned`）。沒有選項時清單裡一列不能選的「沒有可以選的」（`role="option"`、`aria-disabled`，反白指著它）。點欄位的標籤和點按鈕一樣（`lib/useCloseOnOutsidePointer.ts` 把指到裡面的控制項的 `<label>` 算成裡面）。同一個清單每個選項給同樣大小的小圖（人員 20px、狀態 16px），狀態、類別、人員的選項與佔位的小圖（「所有人」「沒有負責人」「所有狀態」）在 `features/work-items/selectOptionMarks.tsx`（看板卡片的「沒有負責人」也用它的 `NobodyMark`）。放在表格裡一直掛著（成員的角色）時，開著清單的方向鍵是清單的（`useRovingGrid` 不接手 `aria-expanded="true"` 的元素）。`SelectField` 就是包了標籤的它。`src/` 的元件裡不准寫 `<select>`、`<option>`（樣式檢查擋，見「樣式檢查」）。
- **`Select` 的篩選框**（自訂控制項 P3，規範 7.3「選項很多的時候」；`selectFilter.ts`、`SelectList.tsx`）：選項 10 個以上自動出現（`FILTER_THRESHOLD`），不用逐處開關：負責人（篩選與格子）、人員欄位、上層項目（最多 200 個）、加入成員的人員（`keywords` 是 Email）都是。打開時焦點在篩選框（`useEffect`：格子的編輯器在 layout effect 裡先把焦點放到按鈕，這裡要在它之後）；關著時打字是打開並把字放進篩選框；每次打開從空的開始。比對 `label` 與 `keywords`，用「包含」、英文不分大小寫（`matchesQuery`）；輸入法選字中不篩（`compositionstart`／`compositionend`，`useFilterQuery` 分開記「框裡的字」與「篩選字」），選字中的按鍵都是輸入法的。篩選框是 `TextField`（`size="sm"`、放大鏡、`role="combobox"`、`aria-controls`、`aria-autocomplete="list"`、`aria-activedescendant`），名稱是 hidden 的「篩選」加清單的名稱（`aria-labelledby`，「篩選 負責人」）。按鍵：↑／↓、PageUp／PageDown 移動反白，Home／End 留給游標，Enter 選，Esc 關上並把焦點放回按鈕（不往外傳），Tab 先把焦點放回按鈕再讓瀏覽器往下走。沒有符合的是清單裡一列「沒有符合的選項」；結果數是 visually-hidden 的 `aria-live="polite"` 區域（不是 `role="status"`：全域的 status 只有一個），停下來 300ms 才換（`useSettledQuery`，打開時是空的：關著時打字打開的那一次也唸得到）。選項的 id 照它在完整清單裡的位置編（`positions`），篩選時同一個選項 id 不變、反白換了 `aria-activedescendant` 就換；篩選字換了也把反白捲到看得到。比對前兩邊做 NFKC（全形「ＡＧＹ－１２」找得到 AGY-12）。按鈕的 `aria-describedby`、`aria-invalid` 帶到篩選框。清單開著、焦點卻在按鈕上時，按鍵轉給篩選框。篩選框標 `TRANSIENT_FOCUS_ATTRIBUTE`（`lib/focusable.ts`）：對話框的焦點陷阱算頭尾時不算它（`trapStopsIn`），下拉是對話框最後一個時 Tab 照樣繞回第一個。不做虛擬化：選項的 `key` 是 value，篩選時還符合的是同一個元素（`SelectFilter.test.tsx` 有 200 個的測試）。
- **`CheckboxField`／`CheckboxGroup`**（`CheckboxGroup` 的 `layout`：`row` 預設、`column` 一個一行，每個勾選框都帶說明時用）：原生的勾選框（方框與勾是 `global.css` 用 `:where(input[type='checkbox'])` 畫的，全站的勾選框都是，權重是零、功能自己的 class 蓋得過去；大小、外距 0 與勾的線寬都在那裡，功能的 CSS 不再各寫一份 16px；強制色彩時退回系統的樣子），整個標籤是點擊範圍（至少 `--target-min`）；`hint` 用 `aria-describedby` 連過去。一組勾選是 `fieldset` 加 `legend`（`isLegendHidden` 只給報讀軟體），說明與錯誤連到這一組。
- **`Menu`**：一串動作（從看板的「移到…」抽出來）。`renderTrigger` 拿到 `MenuTriggerProps`（`ref`、`aria-haspopup`、`aria-expanded`、`aria-controls`、`aria-disabled`、`onClick`、`onKeyDown`），展開到自己的按鈕上。項目可以有圖示、`tone: 'danger'`、`disabledReason`（`aria-disabled`、停得到、原因用 `aria-describedby` 連過去）、`startsGroup`（前面一條分隔線）。打開時焦點到第一項（在按鈕上按 ↑ 是最後一項）；方向鍵、Home、End 移動；Esc 關上回到按鈕（不往外傳，對話框不會一起關）；Tab 關上、焦點照常往下走（先回到按鈕再走，對話框鎖焦點時也不會跑出去）；點外面、焦點移到外面的元素、按鈕被捲出看得到的範圍都關上；選了之後先關上、焦點回到按鈕，再執行動作。`triggerRef` 讓呼叫端也拿得到按鈕，`isDisabled` 是暫時打不開（送出中）。
- **`Popover`**：不是動作清單的浮層（「顯示的欄位」，從那裡抽出來）。`renderTrigger` 拿到 `PopoverTriggerProps`（`ref`、`aria-expanded`、`aria-controls`、`onClick`）。浮層是有名稱的非強制對話框（`role="dialog"`、`aria-label`），打開時焦點到第一個可以操作的元素；Esc 關上回到按鈕；點外面、Tab 或焦點移到外面、按鈕被捲出看得到的範圍都關上（焦點留在使用者去的地方）。
- **浮層怎麼放**（`components/Floating`，`Menu`、`Popover`、`Select` 共用）：元素留在觸發它的元件旁邊的 DOM 裡（Tab 的順序、「點在裡面」、事件往上傳都照常），用 `popover="manual"` 放進瀏覽器的 top layer，`position: fixed` 加 `lib/useAnchoredPosition.ts` 算的座標：不被表格、看板的欄裁掉，也不受祖先的 `transform`、`container-type` 影響。預設在按鈕下方，放不下就翻到上方（`data-side`，出現的動畫從那一邊長出來），左右不超出視窗；視窗捲動（包含任何捲動容器）、改大小、浮層自己變大小時重算，打開期間每一個畫面比對按鈕的位置，按鈕自己因為版面變動而移動也跟著走。按鈕被捲出看得到的範圍（`IntersectionObserver`）就關上，焦點在浮層裡時放回按鈕（不捲動畫面）。「什麼時候自己關上」在 `components/Floating/useFloatingDismiss.ts`，兩個元件共用。沒有 `showPopover` 的環境（jsdom）不加 `popover` 屬性，退回一般的 `position: fixed` 加 `--z-popover`。`matchAnchorWidth`（`Select` 的清單）讓浮層至少和按鈕一樣寬，按鈕的寬度執行時才量（jsdom 量不到就不限）。`keepsAnchorFocus`（`Select`）：在浮層上按下滑鼠不改變焦點（輸入框除外）。`onPositioned`：座標與 `maxHeight` 套上之後通知。按鈕被捲出畫面時 `useFloatingDismiss` 的第四個參數 `closeHidden` 讓呼叫端分得出這一種（`Select` 的 `scrolled`）。React 的 `style` 物件只在這裡用（座標與最小寬度），`scripts/check-styles.mjs` 有允許清單。
- **`Notice`**：頁面或區塊裡的提示（`info`、`success`、`warning`、`danger`），圖示加文字。整個提示是 live region（預設 `danger` 是 `alert`，其他 `status`；`role="none"` 是一開始就在、不必唸的說明）。內容是空的時元素照樣掛著（看不見），晚一點才填進來的內容才唸得到。純文字的內容直接放在提示本身裡（「含這段文字的元素」就是提示，旁邊就是 `actions`）。`onDismiss` 有值才有「知道了」，`dismissLabel` 可以帶上對象。要當焦點的去處（按的按鈕不見之後、送出時才知道的問題：設定頁的「別人已經套用了新版本」、變更集預覽頁被擋下的說明）時給 `ref` 與 `tabIndex={-1}`，焦點放在提示本身，不在外面另包一層。`FormAlert`、`ErrorState`、`RefetchErrorNotice`、`ArrivalNotice` 內部都是它，對外的用法與名稱不變。
- **`Badge`**：可以帶 `icon`（取代前面的小圓點）；`stateIdle`／`stateActive`／`stateDone` 三種顏色來自 `--color-state-*`。`StateBadge`（`features/work-items`）是五種狀態類別的形狀（虛線圓、空心圓、半滿的圓、打勾的圓、劃掉的圓）加藍圖的狀態名稱。
- **`Avatar`**：名稱的第一個字（`domain/initials.ts` 的 `initialsOf`：中文取第一個字，英文取前兩個單字的字首）。旁邊已經有名字時 `decorative`（`aria-hidden`），單獨出現時 `role="img"` 加 `aria-label`。
- **`Skeleton`**：第一次載入時的形狀（`rows` 是表格與清單的列，`text` 是一段文字），「載入中…」只給報讀軟體（`role="status"`）；明暗變化一次是 `--duration-pulse`。
- **`NavTabs`**：用網址切換的分頁，`<nav aria-label>` 裡的連結，目前的那個 `aria-current="page"`。計數是 `CountBadge`（「要修正」的危險計數除了顏色還有錯誤的圖示），完整的說法放在 `CountDescription` 裡、用 `aria-describedby` 連到分頁（分頁的名稱維持只有名字，報讀軟體逐字瀏覽時也不會多唸一次）。
- **`CountBadge`**、**`CountDescription`**（E 輪）：名稱旁邊的小計數，分頁的計數與側欄「我的工作」的數量、過期數共用。`CountBadge` 收 `value` 與 `tone`（`neutral` 中性的淡底；`danger` 危險色的淡底加錯誤的圖示），整個 `aria-hidden`；`CountDescription` 收 `id` 與每一個計數的完整說法 `labels`，用「、」接起來放在 `hidden` 的元素裡（內容是空的也掛著），給連結或按鈕的 `aria-describedby` 引用，名稱不變。
- **`PageBar`／`Breadcrumb`**：頁列，左邊位置（`<nav aria-label="位置">`）與標題，右邊動作；`title` 也是瀏覽器分頁的標題（分頁標題和 h1 不同時給 `documentTitle`，例如設定頁「設定 · 流程」：一頁只有一個 `<title>`，不靠 React 掛上的先後）。頁列上有標題時，目前的頁面是標題，位置裡不標 `aria-current`（專案頁的代號就是一般的文字）；`titleInBar={false}`（項目頁、變更集預覽、`StatusPage`）時頁列沒有 h1、位置的最後一個是目前的頁面（`aria-current="page"`）。窄螢幕（48rem 以下，CSS）只留最近的上一層與目前那一層：有標題時只留位置的最後一段，沒有時留最後兩段，其餘 `display: none`。`headingRef` 給了，標題就是 `tabIndex={-1}`，換頁、套用、捨棄、刪除之後程式把焦點放到這裡。左內距多了 `--page-bar-inset`（外框疊在左上角的按鈕的寬度）。每一頁都用它（原本的 `PageHeader` 與 `ProjectCrumbs` 已經拿掉）。
- **`Toolbar`**、**`PageLayout`**：工具列（不用 `role="toolbar"`，那要方向鍵操作）與三種頁面的骨架（`workspace` 剛好一個畫面高、內容緊接工具列，用滿寬度；`list` 整頁捲動、用滿寬度（2026-11-17 拿掉了 `--content-max` 的上限：側欄收起或寬螢幕時右邊不再留一大塊空白）；`reading` 以 `--content-max` 為限、靠左，旁邊的項目面板排成右邊一欄時內容區不設上限、面板貼著右緣，閱讀的內容用掉面板以外的寬度）。工具列那一列寬螢幕是 44px（含細線）、觸控時 53px，頁列 48px，在規範第 14 節的預算內（`/design` 的工作區範例量過）。每一頁都包在裡面（見「外框與每一頁的骨架」）；`workspace` 是專案的表格與看板。
- **`Dialog`**、**`ConfirmDialog`**、**`DialogFormActions`**：打開時焦點進去、Tab 不跑出去、Esc 關閉、關閉後焦點回到打開它的元素；`size="lg"` 是裡面有表格的對話框（`--dialog-width-lg`）。`ConfirmDialog` 是確認（`tone="danger"` 寫出後果；還不能確認時給 `blockedReason`，主要動作改成 `aria-disabled` 並連到原因）；`DialogFormActions` 是表單的「取消」與主要動作（`blockedReasonIds` 同上；送出要等、送完還留在對話框的給 `keepsFocusWhilePending`）。

## 已知的限制

- PM-1 協作：提及的清單浮在文字框的下緣（放不下就翻到上緣），不跟著游標；說明很長、游標在上面時離游標比較遠。收起來的說明用 `max-height` 加 `line-clamp`，最後一行可能被切在半行。收件匣的「提及你」不分說明或留言（合約的 `kind` 只有 `mentioned`）。收件匣沒有放進快速跳轉的頁面清單。
- 項目頁欄位面板的自訂長文字欄位和表格一樣只顯示一行（點開編輯才看得到全部）；說明超過 12 行先收起來，「顯示全部」看全文。
- 活動由舊到新分頁：超過一頁時，打開項目頁先看到最舊的那些，最新的要按「載入更多」。還沒載到底時修改欄位，新的那一筆一樣在「載入更多」後面（留言會一路讀到它，見上面）。
- 相對時間不會自己跳（「剛剛」不會隔一分鐘變「1 分鐘前」），重新讀活動時才更新。
- 快速跳轉只搜尋得到目前專案的項目標題：別的專案的項目要打編號，或之前看過（最近看過的項目）。跨專案的搜尋要後端。
- 上層項目的選項一次最多讀 200 個（`PARENT_CANDIDATE_LIMIT`），超過的要等之後加搜尋。
- 新增的項目放在目前清單的最上面，即使它不符合目前的篩選條件（訊息會說「它不符合目前的條件…」）；重新整理或換條件後才會照條件與排序排好。搜尋字與狀態篩選沒辦法帶進新的項目（新的項目一律從流程的第一個狀態開始）。
- 表格沒有虛擬捲動；一次載入很多頁時（幾百列 × 十幾欄）可能變慢。
- 下拉的篩選框沒有在實機上驗過（自訂控制項 P3）：Android 的 Gboard 打英文也走輸入法選字（`compositionstart`），選字中不篩，可能要選好字才看到結果；手機上一打開焦點就到篩選框，虛擬鍵盤可能蓋住清單；用滑鼠在長清單選完之後，按鈕可能出現鍵盤焦點的外框（瀏覽器的 `:focus-visible` 推斷）；清單的 `overscroll-behavior: contain` 只在清單長到自己會捲時才有效，短的清單捲到頭照樣會帶著後面的頁面捲。
- 一個 Tab 停駐點（方向鍵在格子之間走）的只有專案的表格、我的工作的分組表格與成員對話框的表格；看板與窄螢幕的清單還是每一筆（每一個按鈕）一個停駐點。成員表格的角色那一格一直是下拉，停在它上面時 ↑／↓ 是打開清單，要上下移動得先用 ← 回到名稱那一格。報讀軟體的瀏覽模式下方向鍵是報讀軟體自己的（語意照規範維持表格，不是 `grid`），用 Tab 進到停駐點或表格的瀏覽指令。
- 清單頁的表格（我的工作）比內容區寬時退回橫向捲動，那時表頭不黏在頁列下面（要黏住，容器就不能是捲動容器）。
- 草稿只在同一個分頁裡（`sessionStorage`）：另開分頁、關掉分頁再開都看不到。說明的草稿還原後，別人改過說明時會警告「儲存會蓋掉新的說明」，但不合併：儲存就是用自己的版本蓋過去（和沒有草稿時一樣，以最後存的為準）。編輯中（沒有離開）別人改了說明不會提示，要等之後有版本比對的 API。
- 看板只依狀態分欄；藍圖 `views` 的看板設定（`groupBy` 的負責人、類型、單選欄位，自訂的篩選、`visibleTo`）還沒套用。欄內照編號排，不能手動排序；拖曳只換欄，不換順序。
- 看板的快速新增和表格一樣放在第一欄最上面，重新整理或重抓後才照編號排到最後。
- 看板的自動捲動是 dnd-kit 的，只捲看板（橫向）：欄裡很長時拖到欄的下緣不會自己捲（放在欄的哪個高度結果都一樣，放在看得到的地方就好）；指標在看板外面（例如側欄上）但靠近左緣時看板照樣往左捲（放下時不在任何一欄上，不送請求）。
- 「這一欄沒有項目」「沒有符合條件的項目」沒有句號：既有的測試用完整的字串找它，要加句號得一起改那些測試。
- 卡片移進一個還有下一頁的欄、而且編號超過那一欄已載入的範圍時，成功後先不顯示在那一欄（照編號它排在還沒載入的那些後面），按「載入更多」才看得到。
- 「走不到」的預先判斷只看轉換與角色；要先填的欄位只有後端知道，拖過去被擋下才開補填的對話框（不預先猜：清單裡的項目沒有說明，猜不準）。
- 看板每一欄各自讀，欄多的流程（接案模板 7 欄）打開時一次發 7 個請求。
- 設定頁還不能改檢視、自動化與整合。自動化用到要刪除的狀態、欄位或類型時只在那一列提醒（伺服器的說明：類型的標在那一列，狀態與欄位的列在「其他問題」），要改只能寫變更集文件。
- 刪除項目沒有復原的畫面（資料與活動都留著，之後再做）。刪除之後的提示和套用變更集一樣放在瀏覽器歷史的 state：按上一頁回來不會再出現，但重新整理那一頁還會再出現一次（記得「說過了」的是頁面裡的記憶，重新整理就沒了）。只有從表格的編號、看板的卡片連進項目頁時記得要回到哪個檢視；從我的工作、下層清單、別的項目頁或直接打網址進來的，刪除後回到專案的表格。
- 改類型與刪除的事先說明只看前端已經知道的：下層只看已經載入的（第一頁 50 個；還有更多時對話框會說「至少」「只檢查了前 50 個」），上層的類型要對話框打開時讀了才知道（還沒讀到時不先擋）；最後以伺服器為準。
- 被移出專案的人：負責人照樣顯示名字，但成員欄位（自訂的 person 欄位）的值只有人員編號，網頁從成員清單找名字，找不到時（格子與編輯器的選單）都寫「不是成員的人」，看不出是誰；同一個欄位有好幾個項目填了不同的前成員也分不出來。要顯示名字得等 API 的成員欄位帶上名字（或提供讀得到前成員的人員端點）。時間軸裡的他是「查不到的人」（和之前一樣）。
- 時間軸的 `migrated` 與 `type_changed`，名稱只能從目前的藍圖找：被刪除的狀態、欄位與類型只剩 key（活動沒有帶那一版的藍圖）。變更集的預覽頁用 `baseBlueprint`，沒有這個限制。每一筆當時的類型只從已載入的改類型推：還沒載入的頁裡又有改類型時，最後一筆已載入的改類型之後的那幾筆照它的 `to` 算（一筆改類型都沒載入時照項目現在的類型），可能對不上；載入更多之後就對了。
- 套用後導回設定頁的提示放在瀏覽器歷史的 state，重新整理那一頁還會再出現一次。
- 帳號的管理（帳號安全那一輪）：已經是專案成員的停用者照樣在成員清單、負責人的選單裡（這一輪不另外處理，`internal/HANDOFF-security-local-ops.md` 第 2 節第 3 點）；「加入成員」的候選才不列他。人員表格不是單一停駐點：每一列的「更多」各是一個 Tab 停駐點（規範 7.1「列上的動作」）。沒有登入帳號的人（`email` 是 `null`：後端的 Email 是從帳號表左聯結來的）那一列沒有「更多」；萬一伺服器還是回 409 `person.no_account`，說明寫在對話框或頁面上方。
